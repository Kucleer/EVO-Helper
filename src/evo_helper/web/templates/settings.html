军力选靶窗口（有效期与门限）

⚠️ 这两格 2026-08-23 从任务行搬到了这里，现在是全局的——所有军力任务共用同一份，任务行上那两个框已经撤掉。 从前每个任务各配一份，而任务是按出发点银河系分的，于是同一个数存了好几份； 但它们约束的不是星系，是军力榜扫描的节奏：榜是一趟扫完全宇宙的，一轮扫多久、读数能有多新，与舰队从哪个银河系出发无关。

选靶顺序：① 剔除近期打过的与撞上过保护期的 → ② 只留有本周期军力读数的（从未上榜的不打，上周一之前读到的也不算） → ③ 只留读数落在有效期之内的，窗口内不足门限那么多个时放弃窗口并告警 → ④ 过「军力上限」这道安全线，按 军力 ÷ 往返小时 从高到低出击。 这两格都不决定打谁——打谁只由第 ④ 步那一条判据定。

只有读数落在这段时间之内的目标，才算「军力值还可信」。可以填小数（1.5 小时是合法取值）。
默认 {{ score_max_age_default }} 小时的来历是一轮军力榜扫描时长的约 2 倍（实测一轮约 60 分钟）。
⚠️ 卡在「刚好一轮时长」附近是有害的：军力榜按军力降序扫，所以一轮扫完之后， 军力最高的那批读数最旧、最低的最新。窗口若只有一轮那么宽，能通过筛选的恰好是这一批里军力最低的那些—— 而「军力优先」正是为了打高军力的，那会系统性地把攻击推向弱目标，把这个模式的意义抵消掉。

调小：只用最新读数，选靶最准；代价是窗口内的目标数会掉到门限之下，于是窗口反而被放弃，改用全部有读数的目标（会告警）。
调大：几乎不会放弃窗口；代价是拿更旧的读数排序，而实测读数每陈旧 1 小时，稀有材料产出掉约 10%（n=45，2026-08-19）—— 快照到开打这段时间里，目标可能已被别人打过。
上限 {{ score_max_age_max }} 小时（一周）——bot 军力每周一 UTC+0 刷新，上周期的读数本来就整批不参与选靶，再往上填这个数挡不掉任何目标。 要「不设窗口」请不要填 0（后端会拒）：0 等于「没有一条读数算新」，于是每轮都放弃窗口、一律拿旧读数打——和你想要的正好相反。

窗口内至少要有这么多个目标，这一轮才肯只用窗口内的那批。不足这么多个时会放弃窗口、改用全部有读数的目标， 并在任务行上标出「军力读数已放宽窗口」、往日志里写一条 WARNING。

⚠️ 它不是「打前几名」。那道军力硬截断 2026-08-18 就取消了（近而弱的和远而强的现在在同一把尺子上比）。 这个数只决定这一轮肯不肯只信新数据。
⚠️ 不足时是「放弃窗口」，不是「按时间往下补几个」。往下补捞到的正是刚出窗口那一批，而那批恰恰是军力最弱的——补下去等于把上面那个选择偏差换个地方原样复发。

调大：对「新鲜」要求更苛刻，窗口更常被放弃（照样打，但会告警，你能看见）；调小：更愿意只用窗口内那批，代价是可选目标少、得分最高的那些可能都在窗口外。
上限刻意不设：门限该多大取决于候选池此刻有多少个（库里 3000+ 个 bot，而窗口内能有多少又取决于扫描节奏），写死一个数就是拿一个凭空的上界去卡你真实的处境。 填得比池子还大只会让窗口每轮都被放弃，而那件事会告警。 要「窗口永不放弃」请不要填 0（后端会拒）：那样窗口内真的一个都没有时（周一凌晨正是如此）这一轮会在空池子上选靶、一发不派，而该响的告警一个字都不写。

军力榜盲滚行数

开榜之后先盲滚过这么多行再开始逐屏检测 bot——那一段必定还是真人，检测纯属白花。 留空 = 按实测自动标定：取最近 {{ blind_scroll_samples }} 次「翻了 N 行到达 bot 区」的最小值再减 {{ blind_scroll_margin_rows }} 行余量； 历史不足 {{ blind_scroll_samples }} 次时用默认的 {{ blind_scroll_rows_default }} 行。填了数就锁死，不再自动调。

⚠️ 这一段已经不是慢拖了，是滚轮连拨。 实测约 {{ rows_per_notch }} 行/格、每格 {{ wheel_gap_ms }} 毫秒接着拨下一格（中间不等）， 拨完之后还会惯性滑行约 {{ glide_settle_s }} 秒才停——所以填出来的行数换算成时间就是下面那一行。

填大填小由你定，这里不拦、也不标红。盲滚少走的行由检测段接手，而检测段每屏都要做一次整列 OCR， 比多拨几格贵得多——所以宁可多滚。反过来，滚过头会跳过榜单靠前的一段，那里面的 bot 就整段没采到， 而漏采是静默的：不报错、不少日志，只是采回来的数少一截。 参考：屏口径下已记录的观测下界是 {{ blind_scrolls_max }} 屏，按 {{ rows_per_scroll }} 行/屏折合约 {{ blind_scroll_rows_reference }} 行—— 那只是观测值，不是上限。

军力榜盲拖屏数（回滚用，当前不生效）

⚠️ 这个框现在完全不上命令行，填什么都不影响实机。 2026-08-22 盲滚段从慢拖改成了滚轮，口径也从「屏」换成了「行」——真正决定盲滚多远的只有上面那个盲滚行数 （包括它留空时的自动标定）。这一格连同库里那一列一起留着，是为了滚轮出问题时能退回慢拖； 但那个回滚要改代码（把调度器那两处换回屏口径），不是把上面那个框清空就行。

填法与原先一样：留空 = 按实测自动标定，取最近 {{ blind_scroll_samples }} 次「翻了 N 屏到达 bot 区」的最小值再减 {{ blind_scroll_margin }} 屏余量； 历史不足 {{ blind_scroll_samples }} 次时用默认的 {{ blind_scrolls_default }} 屏。填了数就锁死，不再自动调。

⚠️ 回滚之后这个数填大了会跳过榜单靠前的一段，那里面的 bot 就整段没采到，而漏采是静默的—— 不报错、不少日志，只是采回来的数少一截，页面上完全看不出来。填小了只是多花几屏检测（一屏约 0.3 秒），代价小得多。 参考：已记录的最小实测屏数减余量是 {{ blind_scrolls_max }} 屏——那只是观测值，不是上限； 榜会随玩家增加变长，实测值也在涨，所以这里不拦更大的值，由你判断。

调度节奏

这几项都没有唯一正确答案——取值取决于你当下的处境（活动期信箱堆积、周一 bot 军力刷新日、开不开加成道具、机器闲忙、要不要激进）。 全部留空 = 用下面括号里的默认值，行为与没有这一节时完全一致。

派出时没读到飞行时间的那一发，按派出时刻起算占多久航线。实测真实往返 10–62 分钟，默认 {{ line_hold_default }} 分钟是留了余量的兜底估算。
调小：吞吐更高，航线更快被认为空出来；代价是估短了会多跑几轮撞游戏的「舰队数量已达上限」——这一档有界且自纠，runner 会看屏复核后正常收尾。
调大：更保守，几乎不会误判航线空闲；代价是一次读不到就能把一条链路压住那么久，而期间没有任何新证据能推翻这个估算（实机曾因此停摆 4 小时）。 上限 {{ line_hold_max }} 分钟——再长会出现「战报已判缺失、航线还锁着」的死角。

每一轮开工时距上次翻信箱不足这么久就跳过，不再进信箱读战报。
调小（填 0 = 每轮都翻）：战报入库最及时，「今日 X/32」最准；代价是每轮多花约 83 秒导航+读页，而航线是逐条释放的、续跑很频繁。
调大：省掉大部分翻箱开销；代价是一份战报最多晚这么久才入库，逼近战报宽限期就会自己制造「战报缺失」。 上限 {{ reconcile_cooldown_max }} 分钟（= 战报宽限期的一半，宽限期改了这个上限跟着变）。

同一个 bot 坐标在这段时间之内不重复打。
调小：同一批高军力目标能多榨几轮；代价是打的多半是刚被自己清空的星球，ROI 低，而候选池按军力降序排——调得太小会让航线全烧在榜首那几个上。
调大：目标摊得更开、重复攻击的浪费更少；代价是已知 bot 不够多时会出现「暂无可打目标」而空转。 上限 {{ bot_revisit_max }} 小时（一周）——再长就跨过了 bot 军力的刷新周期。

目标被打过之后会进入游戏的 {{ game_protection_hours }} 小时保护期（任何人打过都会触发，不只是你）。 保护期推不出来，只能撞上了才知道——派遣时弹「没有可执行的任务」。 撞上一次之后，这个坐标在这里配的时长内不再进候选池。

⚠️ {{ game_protection_hours }} 小时是游戏规则，这一格是策略，两者同数不同义。 我们只知道「在某一刻撞上了」，不知道保护期是什么时候开始的：可能已经走了 7 小时，也可能刚开始。 所以按 {{ game_protection_hours }} 小时排除必然偏保守——这是有意的。

调小：保护期可能早就过了，早点重试能多打几个目标；代价是撞上保护期的目标会更早回到候选池， 而每撞一次就要走一遍「导航 + 开面板 + 撞弹窗 + 退出」，实测每个目标约 2.9 分钟鼠标时间，一发都派不出去。
调大：几乎不会再白跑；代价是少打几个本来已经能打的目标——而候选池有 3000+ 个，这个损失可以忽略。
两边的代价不对称，所以默认宁可过度排除。 参考实机（2026-08-18 20:29）：四个目标全在保护期，整轮 11.5 分钟一发没派，结算完一秒后的下一轮又挑中同样的四个。 上限 {{ protection_exclusion_max }} 小时——保护期最长就 {{ game_protection_hours }} 小时，再往上纯属余量， 超过一天就会和上面那个「bot 重复攻击间隔」争同一件事，排障时分不清目标是被哪一条挡住的。 要「关掉这道排除」请不要填 0（后端会拒）——那正是这一格要修的那个毛病。

站到目标星球上，行星面板上的归属名有时读不出来。判据只能说「这不是 bot」，于是这一发不派。 撞上一次之后，这个坐标在这里配的时长内不再进候选池。

⚠️ 这一格和上面那个「保护期排除时长」是两回事，刻意分开。 保护期是读得懂的事实（游戏弹窗明说了「没有可执行的任务」）； 「面板名读不出」是根因还没查清的现象——可能是画面没加载完、窗口失焦，也可能这个坐标就是读不出。 两者该排多久没有理由相同。

实机（2026-08-20，近 24 小时）：这条判据触发 40 次、只涉及 3 个坐标， 而「真读出了名字、只是不匹配」0 次——也就是它 100% 是在报识别失败。 那 3 个坐标军力 39,030 / 20,960 / 20,630，排在候选池最前，历史上成功派出 0 次。 每撞一次白花 21--44 秒鼠标时间；更贵的是整轮空手而归（65 轮里 16 轮，25%）， 之后「等一条航线空出」会把那颗球压住 1--2 小时（实测一次 117 分钟）。

调小：读不出可能只是一次抖动，早点重试能救回一个高军力目标；代价是它会更早回到候选池， 而实测那几个坐标约每小时就会被重新挑中一次——填得太小等于没排。
调大：几乎不会再为它白跑；代价是万一只是偶发，一个高军力目标要闲置这么久。
排除是有尽头的，故意的：窗口一过它就回到候选池，同时库里记着连续第几次读不出， 日志每次都会写。想知道某个坐标是偶发还是无可救药，看那个数字，不用去数日志行数。 上限 {{ unreadable_exclusion_max }} 小时——超过一天就和上面那个「bot 重复攻击间隔」争同一件事， 而且根因至今没查清，按它把一个高军力目标锁掉一整天，赌的是一个还没有证据的结论。

所有星球共享的同时在飞舰队总数。填了它，某个出发点此刻可用 = min( 该星航线数 − 该星在飞 , 这个上限 − 全账号在飞 − 保留航线 )—— 和任务行上那个「每颗星球的航线数」两道同时生效。

⚠️ 留空 ≠ 0，也不是「用某个默认值」。留空的意思是 不额外限制账号总数，只按每颗星球各自配的航线数算，也就是加这一格之前的行为。
这一格刻意没有默认值：实际留给你的航线数量会随科技升级、使用道具、你自己人为占用而变， 程序里写死任何一个数都是错的（写 9 是错的，写 6 也是错的）。留空时的安全性靠的是 「每颗星球的航线数是你自己配的、你配的时候已经确认过不会超过总量」这一条。

填小一点：更保守，绝不会撞游戏的「舰队数量已达上限」；代价是配好的星球派不满，多出来的航线空着。
填大一点：吞吐更高；代价是 runner 会白跑一趟导航才被自己的看屏闸门拦下。
要「一发都不派」请取消任务的复选框，不要在这里填 0（后端会拒）。上限 {{ account_line_limit_max }} 条（纯防手滑）。

调度器每秒都可能写的那几条日志——「自动停用」「自动恢复」「军力候选池」「军力读数放宽窗口」—— 判定变了立刻写，没变则每种在这段时间里最多落一条。 被压掉的次数与横跨的时长记在下一条的 suppressed_since_last_log / suppressed_span_seconds 里，一条信息都不会丢。
调小（填 0 = 每次都记）：排障时看得最密、抖动频率一目了然；代价是一次反复抖动能刷出上万行 （2026-08-18 01:00 实机：一小时 447 次停用 + 447 次恢复 = 1368 行；同日 16:00：军力那两条一小时 12,155 行， 占 system_log 全表的 44%）。
调大：库里干净；代价是一次真实的反复抖动被合并成看不出频率的一条。 上限 {{ auto_toggle_log_max }} 秒（一小时）。

对账翻信箱时长

每次点「开始」都会先翻一趟信箱把战报读回来。这个数是那一趟最多往回读多久—— 信箱按时间倒序，翻到第一封比它还旧的邮件就收工。 留空 = {{ report_scan_hours_default }} 小时：再往下翻到的战报， 对应的派遣早就过了助手「还在等战报」的窗口，读回来不改变任何一条调度判据。

调小＝翻得少、快，活动期间信箱里堆着几百封无关战报时就调它； 但战报比这个时间还旧就翻不到了。 调大＝能翻到更旧的，代价是活动期间会一屏屏翻过大量无关邮件。

⚠️ 要救很久以前的历史战报，用「手动补录」而不是把这个数调大—— 手动补录（--exhaustive）不受这个下限约束，翻到你选的起始日期为止。 上限 {{ report_scan_hours_max }} 小时。
