# 用 LLM 选攻击目标 —— 方案（2026-08-19）

用户口径（2026-08-19，第二版，**推翻了第一版的输入设计**）：

> **AI 不应该参考旋钮，AI 就是去调这些旋钮的。** 他只需要知道，他在哪儿，
> 军力排行榜是多少，是什么时候刷新的，要飞多久，军力和收益的关系。
>
> 第一期完成基础框架后，直接评估他的选择；第二期进行 A/B test。

---

## 一、这一版最重要的改动：分清「事实」与「旋钮」

第一版把现有的五个旋钮当成约束喂给 LLM，让它在既定筛选之后排序。**那是错的**——
那几个旋钮本身就是我们对同一件事的粗糙近似，喂给它等于让它继承我们的近似误差。

| 现有旋钮 | 它其实在近似什么 | 这一版怎么处理 |
|---|---|---|
| `score_max_age_hours`（6h 窗口） | 「读数旧了就不准」 | **删掉**，直接给收益曲线里的衰减项 `exp(−0.068×龄)` 与每个目标的读数龄 |
| `top_n`（窗口门限 500） | 「池子够不够新鲜」 | **删掉**，直接给读数龄的分布 |
| `bot_revisit_hours`（24h 不重复打） | 对游戏 8 小时保护期留的保守余量 | **删掉**，直接给游戏规则（8h）与我方每个坐标的上次攻击时刻 |
| `max_score`（军力上限 70000） | 「太强的打不动」 | **换成能力描述**：我们有哪几个预设、各自打得动什么量级 |
| 档位表（≥60000→CCC 等） | 「多强的目标配多狠的编组」 | **交给 AI 一起决定**：它返回 (目标, 出发点, **预设**) |

**留下的只有事实**：游戏规则、我方现状、实测出来的关系。

⚠️ **这条界限就是这个方案的要害。** 判据是「**这个数是游戏定的，还是我们猜的？**」
——游戏定的（保护期 8 小时、周一 UTC+0 刷新、航线上限）是事实，要给；
我们猜的（6 小时窗口、24 小时复访、门限 500）是待优化的量，**给了就等于把答案先塞给它**。

## 二、给 LLM 的五样东西（用户口径逐条落地）

### 2.1 「他在哪儿」+ **此刻有几条线空着**

⚠️ **这是决定「这一轮能做什么」的那个数，要给得毫不含糊**——不是让它自己从
「配置 5 条、在飞 3 条」去减。**直接给可派发数，同时给出减法的过程**，
这样它既不会算错，又能看懂为什么是这个数：

```
出发星球 4:277:15
  配置航线   5
  在飞       3   （其中 1 条是「时长未知」，见下）
  ⇒ 此刻空闲 2
  已占用的那几条各自最早何时空出：16:50:27 / 17:22:03 / 未知

出发星球 9:250:8
  配置航线   4
  在飞       1
  ⇒ 此刻空闲 3
  最早空出：15:43:07

全账号航线上限 10，已占用 4  ⇒ 全账号还剩 6

★ 这一轮真实可派发数 = 5（两道闸取小：2+3=5，全账号余 6，取 5）
```

⚠️ **「时长未知」这一档要单独说明**：飞行时间没 OCR 出来的那几条，是按**兜底时长
90 分钟**占着的，实际可能早就回来了。**不标出来 AI 会把一个猜测当成事实**，
在「要不要等一条线空出来」这种判断上会算错。

⚠️ **航线占用判据必须复用 `repository._still_holding_a_line`**，不许另算——
数据概览页那一版自己写过一次，把 22 小时前派出的算成还占着（需求文档 8.1）。

### 2.2 「军力排行榜是多少」

⚠️ **池子有 3784 个，塞不进 prompt；而这一版不能再按现有得分裁**——那等于把公式的
答案先给它。改成**摘要 + 分层样本**：

**摘要**（让它决定去哪儿打）：按 `银河 × 往返档 × 军力档` 的三维交叉表，每格给
个数、军力中位、读数龄中位。往返档按每个出发点各算一份。

**样本**（让它挑具体的）：每个非空的格子里取 **军力最高的 3 个 + 读数最新的 3 个**，
去重后给出坐标、军力、读数龄、从各出发点的往返分钟、我方上次攻击距今、是否撞过保护期。

⚠️ **prompt 里必须写明「你看到的是分层抽样，不是全池」**，并给出每格的真实总数，
否则它会把样本数当成可选目标数。

⚠️ **抽样键刻意用两个**（最强 / 最新），而不是用现有得分——两个键都不是我们要验证的
那条公式，这样才没有把答案泄露给它。

### 2.3 「是什么时候刷新的」

```
本周期起点（周一 UTC+0，由 domain.rules.cycle_start_utc 给）
现在是刷新后第几天、第几小时
每个候选自己的读数龄
整池读数龄的分布（中位 / p90 / 最大 / 有多少个根本没读数）
```

### 2.4 「要飞多久」

**给公式本身，不只给算好的数**——这样它能对任何目标自己估：

```
同银河：D = 1162 + 31.71 × 恒星系环距
跨银河：D = 20000 × 银河环距
单程秒 = 2 + k × √D          k 按出发星球标定（PR #216）
往返 = 单程 × 2
环距是环形距离（银河 9 环、恒星系 499 环），不是减法
```

⚠️ **同时给出这个公式的适用域**：同银河那一档 p90 误差 32–50%（`D` 常数在近距离
本身就不准），跨银河那一档最大 0.03%。**不标出来它会把两档一视同仁。**

### 2.5 「军力和收益的关系」

用户口径（2026-08-19）：「**我只关心核心三资源**，如果军力和核心三资源有线性关系，
并且这个公式你需要给到 AI，然后为后面的筛选目标做准备。」

**核心三资源 = 稀有三样**：合金碎片 / 泰坦立方 / 收割者碎片
（槽位 5 / 8 / 9，⚠️ 槽位号从 `domain.battle_resources.SLOT_LABELS` 取，不许另抄）。

★ **机制**（用户口径 2026-08-20）：**这三样就是舰艇被打爆之后产生的**，
所以 `稀有 ≈ 0.141 × 军力` **不是相关性而是恒等式**，0.141 就是「军力 → 材料」的
转换率。⇒ **军力读数的语义是「剩余可收获库存」，不是「有多难打」**，
而排序键 `军力 ÷ 往返小时` 字面上就是「库存 ÷ 取货时间」。
详见 [`军力被打败会崩-实测.md`](军力被打败会崩-实测.md) 第三节。

**给 AI 的就是这一个式子：**

```
稀有三样 ≈ 0.141 × 军力 × exp(−0.068 × 快照龄小时)

    n = 74，R² = 0.781，样本 2026-08-18~19
    衰减 = 每小时 6.6%，半衰期 10.2 小时，6 小时后剩 66%
```

同一批样本上四个模型摆平了比（**全部换算到原始尺度，R² 才可比**）：

| 模型 | R² |
|---|---|
| ① 线性×衰减 `0.141 × 军力 × exp(−0.068×龄)` | **0.781** ← 采用 |
| ② 幂律重拟 `0.659 × 军力^0.85 × exp(−0.070×龄)` | 0.791 |
| ③ 幂律既有 `1.31 × 军力^0.79 × exp(−0.115×龄)` | 0.733 |
| ④ 纯线性 `0.1217 × 军力`（无衰减） | 0.460 |

- **①比②只差 0.010**：多一个指数参数几乎不带来任何改进，**线性完全够用**，
  可读性还高得多。
- **①比④高 0.321**：⚠️ **衰减项不是可选项**，去掉它模型就废了一大半。

⚠️ **注意 −0.068 与旧文档里的 −0.115 不是矛盾，是模型不同。** 幂律把指数拟成 0.79，
曲率一部分由指数承担；线性把指数钉死为 1.0，曲率就全压到衰减项上。
**给 AI 的既然是线性式，衰减就必须用 −0.068。** 两个数混用会算错。

**推论（一并给它）：**

```
近弱 vs 远强的平衡点：线性模型下退化为  军力比 = 往返比
    （幂律 0.79 时是 往返比^1.27，线性即指数 1.0，所以指数也是 1.0）
⚠️ 打得更狠不会多拿稀有材料（我方单位系数 +0.03，R² 不变）
```

⚠️ **基础三样（金属/晶体/气体）绝不能进这个模型。** 实测它由**我方货舱容量**决定，
不由目标决定：AAA 预设那 6 条的变异系数是 **0.0001**（719,900 / 720,000 / 720,100），
军力从 10,020 跨到 11,170 纹丝不动。整体回归看着有正系数，是因为 BBB 既用在强目标
上、货舱又更大；预设内一拆效应就没了。**拿它做「军力→收益」推断必得假结论。**

### 2.6 还要给的「游戏规则」与「我方能力」

| 事实 | 值 |
|---|---|
| 保护期 | 任何人打过触发 **8 小时**，且**只有撞上才知道** |
| 我方已知撞过保护期的坐标与时刻 | `bot_targets.protection_seen_at_utc` |
| 我方每个坐标的上次攻击时刻 | 由 `attack_dispatches` 算（⚠️ **不要用 `bot_targets.last_attack_at_utc`，那一列从来没被写过**） |
| 军力刷新 | 每周一 UTC+0 随机刷新，**周内只降不升**（用户口径 2026-08-20）。⚠️ **「一周内基线不动」是错的**——被打败会当场掉 20–93%（42 条实测：27 不变 / 14 降），且本周期内不再恢复。**⇒ 读数永远是真实军力的上界**，见 [`军力被打败会崩-实测.md`](军力被打败会崩-实测.md) |
| 可用预设 | 名称 + 各自适合的军力量级（**由用户维护，助手不读不校验预设内容**） |
| 每发的鼠标开销 | 约 38–42 秒（撞保护期也是 38 秒）——这是航线之外的第二种成本 |

### 2.7 ⚠️ 要标注证据强度的那几条

有些「已知」其实是领域直觉，**不标出来 LLM 会当事实用**：

| 条目 | 强度 |
|---|---|
| 收益曲线 `0.141 × 军力 × exp(−0.068×龄)` | **实测**，n=74、R²=0.781、两天数据（2.5 有四模型对比） |
| 近弱赢 56% | **实测但样本弱**：近目标只有 3 个样本；模型独立预测 1.59 vs 实测 1.56。⚠️ 那次用的是幂律，换成线性后平衡点从 `往返比^1.27` 变成 `往返比^1.0`，**这条要重算** |
| 周内相位（D1 竞争最激烈…） | **领域直觉，零数据支撑**。一周只产出一个 D1，攒两个周期要两周 |
| 「军力高 = 被打得少」 | **推断**，分不开「天生就强」 |
| 军力读数对**打过的坐标**系统性偏高 | **实测**，42 条里 14 条在我们打过之后掉了 20–93%；样本有偏——崩得最狠的最不容易被再扫到，真实比例更高。⚠️ **但不要据此做任何「打过所以打折」的修正**：用户口径（2026-08-20）「最有价值的就是他的军力是多少，而不是他有没有被打过」——军力读数本身已经包含了这个信息，再修正就是双重计数 |
| 衰减在**个体**上是跳变的 | **实测**，27 不变 / 14 崩，双峰。⚠️ **但不要据此说「指数形式错了」**——机制是「别人先到一步把库存取走了」，那是**生存过程**，而 `exp(−λt)` 正是它的生存函数，**拟的是期望值不是个体轨迹**。暂不进排序的真正理由是**样本量与外推**（定出系数的 5 个样本落在窗口之外），见 [`选靶数据跟踪-待办.md`](选靶数据跟踪-待办.md) 第八节 |

## 三、⚠️ 值得先想清楚的一件事：AI 的上限在哪

实测：把拟合出来的系数接进现有排序，模拟提升 **+7.0%**。也就是说
**现有排序已经在拟合最优的 93% 上**。

**如果 AI 只是「在同一批候选里换个顺序」，它的天花板就是那 7%。** 而检出 7% 需要
每组约 710 发（见第五节），按现在的节奏要跑一个多月。

### ⚠️ 有一条「结构性差异」被否掉了：不许空等

第一版草稿给了 AI「`picks` 可以为空、把航线留到下一轮」的权限。**用户口径
（2026-08-19）否掉了它**：

> 我觉得选择填满是正确的选择。第一我们要充分利用时间，第二往后 bot 只会被别人打，
> 而不会变得更有收益，所以一定是填满的。

**这条已经被量出来了**：收益曲线里的衰减项 `exp(−0.068 × 龄)` 就是它的定量版本。

```
每小时衰减 6.6%          半衰期 10.2 小时          6 小时后剩 66%
```

⚠️ 注意这里说的**不是**「军力会随时间自己变小」——**周一之外军力只在被打败时下降**
（2.6）。衰减项衡量的是**「在我们读到与打到之间，别人先到一步把库存取走了」的概率**，
也就是一个生存过程的期望值，**正是用户说的第二点**。

于是**空等的代价是双份的**：不光丢掉那 1 小时的航线产出，**手上所有候选同时贬值
6.6%**。等出来的不可能比现在好。

**⇒ `picks` 必须恰好填满本轮预算，这是硬约束，不是偏好。** 校验不满就整份作废。

### 那结构性差异还剩什么

既然「打不打」没得选，AI 能做出差异的只剩**「打谁、用什么编组」**里的两处：

- **往返时长的构成**。现有算法按 `军力 ÷ 往返小时` 贪心，这是个**每航线小时的瞬时速率**。
  但短程还有一层速率算不出的好处：**航线回来得快 = 用更新的情报再决策一次**，
  而情报每小时贬值 6.6%。⚠️ **这一层目前没有证据**——近弱那次实测，速率模型
  预测 1.59、实测 1.56，**残差里没看出额外的期权价值**（但 n=3，说明不了什么）。
- **预设的选择**。现在是按军力档位硬映射（≥60000→CCC 等），AI 可以按具体目标定。

- **以及指出池子本身有问题** —— 见 `pool_warnings`。今天最大的一次提升
  （近目标 0→13 个）正是来自「发现扫描够不着本地银河」，而不是选靶排序。

⚠️ **一期这些一律只记录、不执行**（第四节）。

## 四、第一期：打通框架 + 直接评估它的选择

用户口径：「**第一期完成基础框架后，直接评估他的选择**」。**一期不做 A/B，不影响派遣。**

### 4.1 挂在哪

控制台（`application` 层），`_military_assignments()` 算完之后、组命令行之前。
**读一份、记一份，返回值一个字不动。**

不挂 runner：runner 只负责「去点」，而且跑在另一台机器上、占着鼠标。

### 4.2 返回格式（严格 JSON，校验不过整份丢弃）

用户口径（2026-08-19）：**「他的返回应该直接是当前的目标选择，而不是旋钮。」**

也就是说 AI **不给配置建议**——它本身就是那个决策。第一版草稿里那个
`knob_suggestions` 字段已删掉：**既然它直接做选择，旋钮就没有存在的必要了**，
留着反而是把它退回「顾问」的位置。

```json
{
  "picks": [
    {"target": "3:98:12", "origin": "4:277:15", "preset": "BBB", "rank": 1,
     "reason": "军力 31,820、读数龄 0.3h、往返 125 分；按 0.141·军力·exp(−0.068×0.3) 折算后是本轮最高"}
  ],
  "pool_warnings": [
    {"severity": "high",
     "finding": "9 系 6 小时内新鲜读数 0 个，该出发点的候选全是跨银河",
     "suggested_check": "军力榜扫描深度是否够不着该银河"}
  ],
  "confidence": "high | medium | low",
  "notes": "一句话说清这一轮的主要取舍"
}
```

- ⚠️ **`picks` 必须恰好等于 2.1 给出的真实可派发数**——不多不少。
  **「留一条线等下一轮」是错的**，理由见第三节：情报每小时贬值 6.6%，
  等出来的不可能更好。**不满或超出都整份作废。**
- `target` / `origin` / `preset` 必须来自输入给过的集合，否则整份作废并记日志；
- 同一坐标不许在一份 `picks` 里出现两次。
- `pool_warnings` 是**次要**字段：它不是选择，是顺带看到的异常。留着是因为几乎不花钱，
  而公式在结构上说不出这类事。

### 4.3 一期怎么「直接评估」

一期**观察不到反事实**（AI 选 A、我们打 B，A 的收益永远不知道），所以评估只能靠这四条，
按重要性排：

1. **规则遵守率** —— 它有没有推荐撞在保护期里的、上次攻击不足 8 小时的、
   超出航线预算的、坐标不在给定集合里的。**这一条不合格就没有下文。**
2. **理由与数据是否自洽** —— 它给的 `reason` 里引用的军力 / 龄 / 往返，
   与输入是否一致。**编数字是最危险的失败模式**，要自动核对而不是人眼看。
3. **`pool_warnings` 的命中率** —— 人工复核，有几条是真的。
   ⚠️ **至少要喊对过一次我们没发现的问题**，这是它值不值得进二期的硬门槛。
4. **与现有算法的重合率** —— ⚠️ **这一条只能用来发现「它压根没在按规则做事」**，
   重合率高不代表好、低不代表坏。**不许拿它当好坏的判据。**

### 4.4 一期要落的记录

```
轮次 id / 时刻 / 现有算法选中的 / AI 选中的 / 重合数
/ AI 完整返回（原样）/ prompt 原文（原样）/ token 数 / 延迟 / 模型与版本
/ 自动核对结果（规则遵守、数字自洽）
```

⚠️ **prompt 与返回必须原样存**。模型换个版本答案就会变，事后复盘时
「当时喂进去的到底是什么」是唯一能对账的东西。

### 4.5 安全边界

- **一期绝不影响派遣。** 用例钉住：**注入一个返回垃圾的假 LLM，断言派遣结果与
  没接时逐字相同。**
- **失败一律静默降级**：超时、限流、校验不过 → 记一条日志，照常按算法派。
  ⚠️ 绝不能因为 LLM 挂了让攻击停摆。
- **限流**：一轮最多一次；`_facts` 每 tick 都走（页面轮询也会走），**绝不能挂在那里**。
- **不发送敏感数据**：坐标与军力要发，**账号名、玩家名一律不发**。
  ⚠️ 仓库公开，prompt 模板会进 git —— **模板里不许出现任何真实坐标当例子**。
- **默认关**，一个开关能整个停掉（同 `AUTO_ENABLED` 的惯例）。

## 五、第二期：A/B test

用户设想是「4 系走既定路线、9 系走 AI」。⚠️ **这个分组会被混杂吃掉**，实测：

| | 4:277:15 | 9:250:8 |
|---|---|---|
| 航线数 | 5 | 4 |
| 同银河 6h 内新鲜读数 | 66 | 21 |
| 48 小时内撞保护期 | 25 次 | 0 次 |
| 任务优先级 | **0（军力榜采完强制先跑它，读数系统性更新鲜）** | 1 |
| 08-18 派遣量 | 54 发 | 24 发 |

**这些差异会被整个算进「AI 的功劳」或「AI 的锅」。**

### 5.1 需要多少样本

```
每航线小时稀有产出：n=85，均值 1,816，标准差 855，变异系数 0.47

检出  7% 差异 → 每组约 710 发  ≈ 47 天
检出 15% 差异 → 每组约 155 发  ≈ 10 天
检出 30% 差异 → 每组约  39 发  ≈  3 天
```

（双侧 95%、功效 80%；按每颗星球每天 13–24 发折算。）

**排序层的预期效应就是 7%——用一个要跑 47 天的设计去测它，不划算。**

### 5.2 两个补丁，把设计救回来

**A. 每周一换臂。** 4=算法/9=AI 跑一周，下周对调。planet 效应在「差之差」里抵消。
换臂点对齐周一刷新，两臂看到的周内相位分布也一样。

**B. 两个决策每轮都算、都记，只执行一个。** 拿到的是**配对数据**（同一池子、同一时刻、
两个决策），而池子状态正是方差的主要来源，配对能把它消掉。粗估变异系数可从 0.47
降到 0.2 量级，样本需求从 710 掉到约 130 发/组 —— **9 天而不是 47 天**。

⚠️ **还有一处干扰躲不掉**：两臂共用同一个候选池，谁先派谁拿走好目标（24 小时复访会
把它从另一臂的池子里剔掉）。这是 SUTVA 违背，**换臂能让它对称，但消不掉**。
分析时要把它写进限制。

### 5.3 停止规则

⚠️ **预先定死最小样本量，不许看着数据决定何时停**——那是 p-hacking，
而这个仓已经因为「看着数据凑解释」错过一次（把日切口径差异当成 10 倍资源错误）。

### 5.4 进二期的门槛

1. 一期规则遵守率 **100%**（不合格直接否）；
2. 理由与数据自洽率 **≥ 95%**；
3. `pool_warnings` 人工复核命中率 **≥ 50%**，且**至少喊对过一次我们没发现的问题**；
4. JSON 校验通过率 **≥ 99%**；
5. 二期**保留一键切回**。

## 六、这个方案没解决的

- **反事实观察不到**，一期结构上无法证明「AI 选得更好」（4.3）。
- **周内相位那几条是零数据支撑的领域直觉**，喂进 prompt 等于写进一个未验证的先验。
  必须标证据强度（2.7），否则 AI 会当事实用。
- **分层抽样可能把它想要的裁掉了**——它看不到样本之外的个体。二期可以做成两轮
  （先让它挑格子，再给那一格的全部）。
- **决策的可复盘性会变差**。这个仓的惯例是「判据只能有一份、出事能只靠库里日志定位」，
  而 LLM 输出天然带随机性。**这是接入它的真实代价**，不是实现细节能绕过去的。
- **今天最大的几次提升都不在选靶层**（利用率 40%→99% 带来产出 ×3.4、扫描加深让近目标
  0→13 个）。**如果 AI 只在选靶层动，它碰不到这些。** 而「不派遣」这条路
  已被否掉（第三节：情报每小时贬值 6.6%，空等是双份亏）。**剩下能够得着的只有
  往返时长构成、预设选择、以及 `pool_warnings` 指出池子问题**——前两者的上限就是
  那 7%，第三条才可能带来量级差异，但它靠的是人看了之后去改配置，不是 AI 自己动手。
