# 军力榜补数问题 —— 方案 v4（实施规格）

> v1 局部裁剪 → 撤回｜v2 观测口径不成立 → 重写｜v3 主线被接受 → 本版补齐定义
> 变更历史与被否决的方案见 v1/v2/v3。本版是**可实施的规格**。

---

## 0. 本版新增的一处核实（review 之外，我自己核出来的）

首屏不只是「日志漏了」，它**完全不参与自愈阀**：

```python
rows = read_rows()
first, reached_limit = collect(targets_from_rows(rows, ..., history=score_history))
score_anchor = next_score_anchor(rows, anchor=score_anchor)
screens.append(first)
...
for extra in range(1, 0 if reached_limit else bot_scrolls + 1):   # ← reached_limit 时循环一次都不跑
    ...
    blind_score_screens += 1        # 计数器只在循环里动
```

后果：

- 首屏可以把坏点写进历史，而**永远不会被计为一次失败**
- 首屏就采够 `bot_limit` 时，`range(1, 0)` 为空，**整个循环不执行** ——
  这一趟一条 `采集一屏` 日志都不会有

所以「首屏记为 `screen_seq=0`」不是补全语料的细节，**它是阀的一个覆盖漏洞**。

## 1. Phase 0 —— 只观测，不改行为

### 1.1 每屏计数（五个来源分开）

| 字段 | 取自 | 区分什么 |
|---|---|---|
| `verdict_trusted` | `Judgement.trusted` 里的正值个数 | 判据本身成没成功 |
| `history_appended` | 本屏实际追加进历史的记录数 | 名次缺失会让采信值进不了历史 |
| `history_new_ranks` | 其中**不同名次**的个数 | 历史不按名次去重，四条记录未必是四个独立支撑点 |
| `bot_measured` | 过滤后 bot 行里的实读值个数 | bot / 坐标过滤吃掉了多少 |
| `fresh_valued` | 去重后新增带值目标数（阀**现在**看的那个数） | 重复观测吃掉了多少 |

⚠️ 这些数必须由**同一次判定**交出来。`targets_from_rows` 要把它已经算出来的统计带出来，
**不是重判**。理由：历史追加发生在 bot / 坐标过滤**之前**，从返回值里统计取不到完整结果。

### 1.2 影子评估 —— 记的是「成功」，不是「触发」

⚠️ **v3 命名错了**：`verdict_trusted > 0` 为真时含义是**清零失败计数**，与「触发」正相反。

改为记录三个**成功**条件，各自维护独立的影子失败计数，**连续两次失败记一次假想重置后归零**：

| 名称 | 条件 |
|---|---|
| `success_old` | `any(t.military_score is not None for t in fresh)`（现行，含估算值） |
| `success_verdict` | `verdict_trusted > 0` |
| `success_history` | `history_appended > 0` |

现行阀**照旧实际生效**；三个候选都只影子运行。

⚠️ **产出的定性**：这只是「三种条件在**现行运行轨迹**上的比较」。
换条件之后历史会不同、后续采信也会不同，
**不能把影子事件直接当成换条件后的真实重置集合** —— 那个只有 1.4 的语料回放能给。

### 1.3 首选候选：`success_verdict`

反例（review 提供，已采纳）：连续两屏分数正常但**名次全部缺失** →
`verdict_trusted > 0` 而 `history_appended = 0`。按 `history` 条件会清掉此前健康的历史，
**却修不了名次缺失**。而重复名次又能持续追加，所以 `history_appended > 0`
也不代表曲线在有效推进。

**保证范围写清楚**：这道阀保护的是「**连续两屏没有任何正值被采信**」这一类故障。
它**不保证**解决局部污染，也**不保证**解决历史停滞。

### 1.4 每次重置的上下文

阀基于连续两屏，只记触发当屏不够。每次重置记：屏序、重置前历史点数、
当时 `unread` 规模、**连续那两屏各自的 1.1 五个计数**。

每趟收尾另记：**最后一次重置在第几屏、收尾时历史多少点、补数三个数**。

### 1.5 逐屏原始输入采样

**开关**：由调度器在启动子进程时以**命令行参数**传给本次扫描，绑定到它新生成的 `run_id`，
**消费一次即失效**。

⚠️ 不许把布尔值长期写进可重复使用的任务参数 —— 「子进程结束」并不保证下次不再开启。
调度器已经在起子进程前生成 `run_id`（`mission_scheduler.py:2876`），沿用那个位置。

**内容**：开启时在 `采集一屏` 的 payload 里附带本屏**原始行数组**（名次、坐标、分数、空值，保留行序）。

**完整性检查**（缺任何一项则该批语料标为不完整、不得用于验收）：

1. **首屏记为 `screen_seq=0`**；其后屏序连续、不重复；**空屏也必须记录**
2. 原始行数组长度与 `rows_read` 一致，行序与空值原样保留
3. 同一 `run_id` 下有开始记录、生效配置、代码版本、**结束记录**；
   结束记录说明：正常完成 / 达到上限 / 取消 / 异常，以及**是否执行了收尾补数**
4. 收尾记录的总屏数、总行数与实际收到的语料一致；**缺结束记录的批次标为不完整**
5. **先用原版本回放**，复现采信统计、重置位置、收尾结果，再比较候选版本

⚠️ 若要验收「实际写入数、最终库内空值」，还需给模拟仓储**相同的相关初始状态**；
只有 OCR 行时，只能验证算法层结果，不得声称验证了落库结果。

**采样覆盖要求**：首批 4–5 趟，且必须覆盖 —— 正常趟、含重置的趟、含重复观测修复机会的趟。
未覆盖的情形用**构造用例**补，**不得声称「生产已验证」**。

### 1.6 Phase 0 产出

1. 三种成功条件在现行轨迹上的差异（含「哪些屏会翻向」）
2. 最后一次重置的位置分布，及其与收尾历史规模 / 补数率的关系
3. 重复观测的可修复规模（按**不同坐标**计数）
4. 一批通过完整性检查的可回放语料

**不设通过线**。

## 2. Phase 1a —— 换阀的成功条件

依 1.2 的影子数据 + 1.5 的语料**配对回放**后选定，首选 `success_verdict`。

⚠️ **两屏阈值保持不动**，不许同时改两个变量。
⚠️ **不许靠调高阈值掩盖口径问题。**

---

## 3. Phase 1b —— 重复观测补回目标

### 3.1 状态规则（本趟内，按坐标）

| 观测序列 | 应有结果 |
|---|---|
| 空 → 空 → 实读 A | 补入 A |
| 空 → 估算 → 实读 A | 估算不更新；随后补入 A |
| 空 → 实读 A → 实读 B → 空 | 保留 A；后续不覆盖、不重新进入 `unread` |
| 首次已有实读或估算 | 保持原值（本次只补空） |

### 3.2 约束

1. **潜在收益按不同坐标计数。** `空→实读A→实读B` 只算**一个**可修复目标；
   Phase 0 需独立的模拟状态，不能每次拿首次空值去比。
2. **修复更新不许混进 `fresh`。** 否则会改变新增计数、连续空屏数和停扫行为。
3. **达到 `bot_limit` 后**：可以处理**本屏已经读到的**修复机会，不新增目标、不额外滚屏。
   （`bot_limit` 的语义是「最多采集多少个**不同 bot**」，更新已纳入批次的坐标不违反它。）

### 3.3 新的仓储契约

现有两个都不能用：`backfill_missing_military_scores()` 写死 `military_score_estimated = True`；
`save_ranking_targets()` 无条件覆盖。

> **只更新现存、未拉黑、且更新时仍为空的目标；不创建新行；写入实测值（非估算）、
> 用本次观测时间；返回逐坐标处理结果。**

「未拉黑」继承自 `save_ranking_targets` 现有的保护
（`if target.blacklisted_at_utc is not None: continue`）。

**逐坐标结果至少区分**：

| 结果 | `unread` 的处置 |
|---|---|
| 写入成功 | 移出 |
| 已有值 | 移出（它不需要补了） |
| 不可更新（不存在 / 已拉黑） | 移出，且**不得再进入曲线补数** |
| 失败 | **保留**，不得当作成功 |

## 4. Phase 2 —— 锚点改取自同一次判定

`next_score_anchor` 不再走第二遍无曲线判定，改取本屏 `Judgement.trusted` 的最大正值。
单独提交、单独验证。

⚠️ **不得要求它减少空值** —— 它修的是锚点来源，验的应是锚点来源正确 + 行为改善。

## 5. 验收条件

**基线口径**：所有「不降 / 改善」都必须与**旧版本在同一份语料、同一共同集上**的结果比。
⚠️ 不得拿历史总体数（如 73%）当共同集基线。

### 5.1 Phase 1a

| 项 | 通过线 |
|---|---|
| 连续失败保护 | 独立计数（不用会被重置归零的那个）；用**构造序列**验证能恢复 |
| 最后一次重置位置 | 后移，或重置总数下降，且收尾历史规模上升 |
| 补数 | 分三个数报：曲线推得出 / 真正写入 / 最终仍为空 |

### 5.2 Phase 1b

⚠️ **不要求「最终缺值必须下降」** —— 旧流程估算 9500、新流程实读补 9800 时，
两者缺值都是 0，但 1b 确实做了有效修复。

| 项 | 通过线 |
|---|---|
| 最终缺值 | **不增加** |
| 实读修复数 | 有合格机会时**必须增加**；此数**单列**，不并入曲线补数率 |
| 状态表符合性 | 数值、估算标记、时间戳、不覆盖行为逐条符合 3.1 |
| 仓储结果 | 四种结果与 `unread` 的处置逐条符合 3.3 |

### 5.3 估算质量（Phase 1a / 1b / 2 通用）

| 项 | 通过线 |
|---|---|
| 共同可补集准确率 | 相对**同一共同集上的旧版结果**下降 ≤ 2 个百分点 |
| **新增可补集准确率** | **≥ 共同集旧版结果 − 5 个百分点**（不再只是「单独报」） |
| **严重高估** | 定义：估算值 > 真值 × 1.5。**新增集里占比 ≤ 2%**，且绝对条数不增加 |
| 误差尾部 | P99 用绝对相对误差；**另报高估方向的尾部**；样本量与无法配对比例必须同报 |
| 配对方式 | 按**坐标**配对，报配对成功率与时间间隔 |

### 5.4 选靶影响

不只报「前列变了没有」—— **新进入前列的目标必须逐个检查有没有被严重高估**
（前列变化本身可能正是改进）。

### 5.5 诊断指标（不设上下界）

丢弃率、各理由占比、曲线覆盖行数。

## 6. 明确不做

- **判定与补数分离状态**——暂留共用。若修完误触发后**真实重置**仍主导历史损失，再评估
- 不同时调两屏阈值

## 7. 仍不确定

1. **首屏该怎么进阀的计数？** 它现在完全不参与（第 0 节）。
   把它算作第一屏失败/成功，会改变阀的行为——这算 Phase 1a 的一部分，还是单独一步？
2. **语料的模拟仓储初始状态**要复制到什么粒度？
   全量 `bot_targets` 快照太大，但只取本趟涉及的坐标又可能漏掉「已拉黑」这类判断所需的行。
