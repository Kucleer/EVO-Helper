# 军力榜补数问题 —— 方案 v3

> v1：提议把 `score_history.clear()` 换成局部裁剪 → **撤回**（切点不可信、空历史会崩、留下补不了的死带）
> v2：改为「先量阀的误触发」 → **口径不成立**，见下面第 1 节
> v3：本版。修正观测口径、把语料采集提前到 Phase 0、给 Phase 1/2 补上通过线。

---

## 0. 先更正我自己写错的两处（review 指出，已核实）

**(a) 「判据一个值没采信、但插值出了值」——不可达。**

```python
before = _nearest(out, index, step=-1)
after  = _nearest(out, index, step=1)
if before is not None and after is not None:      # 两端都要有
    out[index] = (before + after) / 2
```

全屏 `trusted` 都是 `None` 时插值没有两端，产不出任何数值。
**可达的是**：新增 bot 行本身没被采信，但同屏**被过滤掉的行**（真人 / 名字读不出）
上有采信值，插值借它们补出了数 —— 这才是漏触发的真实路径。

**(b) 两个数字不该写成事实。**
「每次约 80 名死带」是特定例子的算术结果；
「每趟 300–600 次重复观测」是按当前重叠量的估算，未实测。
v1 背景里「一屏判完才追加历史」也是错的 —— **实际是逐行采信后立即追加**。

---

## 1. v2 的口径错在哪

v2 的 Phase 0 计划从 `targets_from_rows()` 的返回值里统计「非空且非估算」当作
`judged_trusted`。**这个数取不到完整的判据结果**：

```python
if coordinate is None or not is_bot_entry(coordinate, row.score):
    continue                    # ← 真人行 / 名字读不出的行，在这里被丢掉
targets.append(RankingTarget(...))
```

而历史追加发生在**这个过滤之前**（在 `judge_scores` 内部逐行进行）。
所以「历史持续增长、而 `judged_trusted` 为零」是可达的 ——
v2 想用它区分「判据失败」和「去重导致的误触发」，但它自己也混进了 bot 过滤。

**结论**：不能为了「不穿透 `targets_from_rows`」而保留错口径。
它应当把**同一次判定已有的统计**交出来（不是重判，只是把已算出的数带出来）。

---

## 2. 修正后的核心假设

> ~~误触发多，所以修触发条件就能恢复补数~~
>
> **误触发会放大历史损失。但仅凭误触发占比不能推出「修触发条件就够」——
> 必须同时量出触发发生的位置和它造成的实际损失。**

反例（review 提供，我认为成立）：一趟里 7 次前段误触发 + 1 次临近收尾的真实触发。
误触发率 87.5%，但修掉前七次之后，**最后那次真实触发仍会清空全部历史**，
收尾补数照样很差。

**所以决定性的量不是「误触发占比」，是「最后一次重置发生在第几屏、以及收尾时的历史规模」。**

⚠️ 还有一点：新触发条件**不保证只会响得更少**。旧条件接受新增的**估算**值，
新条件排除估算值 —— 有些屏会从旧口径的「成功」变成新口径的「失败」。
所以 Phase 0 必须**并行影子评估**新旧两种条件，而不是直接换。

## 3. Phase 0 —— 只观测，不改行为

扩展已有的每屏结构化日志 `record_log("采集一屏", {...})`（它已经存在，有 payload）。

### 3.1 每屏计数（四个来源分开，不合并）

| 字段 | 取自 | 区分什么 |
|---|---|---|
| `verdict_trusted` | `Judgement.trusted` 里的正值个数 | 判据本身成没成功 |
| `history_appended` | 本屏实际追加进历史的记录数 | 名次缺失会让采信值进不了历史 |
| `history_new_ranks` | 其中**不同名次**的个数 | 历史没按名次去重，四条记录未必是四个独立支撑点 |
| `bot_measured` | 过滤后 bot 行里的实读值个数 | bot 过滤吃掉了多少 |
| `fresh_valued` | 去重后新增带值目标数（= **阀现在看的那个数**） | 重复观测吃掉了多少 |

### 3.2 影子评估：新旧触发条件并行记录

同一屏同时算出三种条件的判定结果，**都只记录、都不生效**：

- `trigger_old`：`any(t.military_score is not None for t in fresh)`（现行）
- `trigger_verdict`：`verdict_trusted > 0`
- `trigger_history`：`history_appended > 0`

Phase 0 结束时能直接给出：换条件之后**哪些屏会从触发变不触发、哪些反过来**。

### 3.3 每次重置的上下文（v2 缺的）

阀基于**连续两屏**，所以只记触发当屏不够。每次重置记：

- 屏序（第几滚）
- 重置前的历史点数
- 当时 `unread`（待补目标）的规模
- **连续那两屏各自的上述五个计数**

每趟收尾另记一条汇总：**最后一次重置在第几滚、收尾时历史多少点、补数三个数**。

### 3.4 逐屏原始输入采样（v2 放在 Phase 3，现提前）

**理由**：Phase 1a 会改变历史演化、Phase 2 会改变锚点。改完再采，
就失去了「同一输入下比较改动前后」的机会。

做法：一个**单次扫描的诊断开关**，默认关闭、本趟结束即失效。
开启时在 `采集一屏` 的 payload 里附带本屏**原始行数组**（名次、坐标、分数、空值）。

语料必须带：屏序、观测时间、配置、代码版本、**结束原因**、完整性检查。

首批采 4–5 趟，且**必须覆盖**：正常趟、含重置的趟、含重复观测修复机会的趟。
未覆盖到的情形用构造用例补，**不许声称「生产已验证」**。

### 3.5 Phase 0 的产出

1. 换触发条件后，触发集合会怎么变（3.2）
2. 最后一次重置的位置分布、以及它与收尾历史规模/补数率的关系（3.3）
3. 重复观测的可修复规模（按**不同坐标**计数，见 4.2）
4. 一批可回放的逐屏语料（3.4）

**不设通过线** —— 这一步是量，不是改。

⚠️ **Phase 0 的局限，写在前面**：计数能识别当前运行里明确的口径误判，
但**不能重建「如果当时没清历史」的判定结果** —— 历史变了，后续采信也会变。
那个只能靠 3.4 的语料做回放。

## 4. Phase 1

### 4.1 Phase 1a —— 换阀的触发条件

依据 3.2 的影子数据选 `trigger_verdict` 或 `trigger_history`，并说明为什么。

⚠️ 同时**保留两屏阈值不动**。不许一次改两个变量。

### 4.2 Phase 1b —— 让重复观测补回目标

**状态规则**（采纳 review 给的表）：

| 本趟观测序列 | 应有结果 |
|---|---|
| 空 → 空 → 实读 A | 补入 A |
| 空 → 估算 → 实读 A | 估算不更新；随后补入 A |
| 空 → 实读 A → 实读 B → 空 | 保留 A，后续不覆盖、不重新进入 `unread` |
| 首次已有实读或估算 | 保持原值（本次只补空） |

**三条约束**：

1. **潜在收益按不同坐标计数。** `空→实读A→实读B` 只算**一个**可修复目标。
   Phase 0 需要独立的模拟状态，不能每次都拿首次空值去比。
2. **修复更新不许混进 `fresh`。** 否则会改变新增计数、连续空屏数和停扫行为。
   批次达上限后，可以处理**本屏已经读到的**修复机会，但不新增目标、不多滚屏。
3. **需要新的仓储契约。** 现有两个都不能用：
   - `backfill_missing_military_scores()` 写死 `military_score_estimated = True`
   - `save_ranking_targets()` 无条件覆盖

   新契约：**当前仍为空才写入**、标为**实测**（非估算）、用**本次观测时间**、
   **返回处理结果**。确认成功后才把该坐标移出 `unread`。

### 4.3 Phase 2 —— 锚点改取自同一次判定

`next_score_anchor` 不再走第二遍无曲线判定，改取本屏 `Judgement.trusted` 的最大正值。
**单独提交、单独验证。**

## 5. 验收条件（v2 只说了「报什么」，这里补「什么算通过」）

前提：**同一份 Phase 0 语料、同一目标集合**下做配对回放。

| 指标 | 通过线 |
|---|---|
| **最终缺值数** | 必须下降。**「实读修复数」单列** —— 否则 1b 修掉容易的洞，会让剩余的曲线补数率看起来变差 |
| **估算准确率** | 共同可补集与新增可补集**分别评估**。共同集允许下降 **≤2 个百分点**（当前 73%）；新增集单独报，不与共同集混算 |
| **误差尾部** | P99 用绝对相对误差，**另报高估方向的尾部**；样本量与无法配对比例必须一起报 |
| **连续失败保护** | 独立计数（不用会被重置归零的那个），并用**构造序列**验证能恢复。**不许靠调高阈值掩盖口径问题** |
| **选靶影响** | 不只报「前列变了没有」——**新进入前列的目标必须逐个检查有没有被严重高估**。前列变化本身可能正是改进 |
| 丢弃率 | 诊断指标，不设上下界 |

## 6. 明确不做

- 局部裁剪（v1）—— 直到 Phase 0/1 的数据出来
- `screen_consensus`（屏内共识否决曲线）—— 已撤回，独立验证只有 58% 正确率（n=19）
- **判定与补数分离状态** —— review 建议暂留共用。若修完误触发后**真实重置**仍主导历史损失，
  那时再评估分离，就有明确依据
- 不同时调两屏阈值
