## 1. 这个功能是什么

用户口径（2026-08-14）：

> 底部菜单栏是可以横向拖动的，会有一个排名入口。进入后切换到军事评分，向底部拖动……
> 你的任务就是扫描这些信息，然后记录进星球列表，并且增加字段军力值。
> 并且攻击 bot 的任务，增加一个开关，优先攻击军力列表。另外需要优先挑选左边相对距离更近的优先攻击。

排行榜「玩家 / 军事评分」页翻过约 638 名真人之后，**剩下全是 bot**，每行长这样：

```
[639]   bot_4_30_12   ---   29.59K
 名次      名字        联盟   军力值
```

**名字直接编码坐标**（`bot_<银河>_<恒星系>_<行星>`）。所以这一张榜同时给出**坐标 + 军力值**，
而拿到一个 bot 坐标的成本从「逐坐标导航读面板」降到「一屏读 13 行」——
这是它值得做的全部理由。

用户的分期计划（2026-08-14）：

1. 启动任务后先扫**前 10–20 名 bot**，攻击舰队出发；
2. 然后再开始扫全榜（工作量 ≤ 原来的全星系扫描）；
3. 全榜扫完拿到分数分布之后，**恢复舰队分档**——含**上限**（"CCC 也打不动 → 不派"）。

本次交接只做 **1 + 2 的采集与入库**。分档是下一步，别顺手做。

用法：

```python
nav = RankingNavigator(
    driver=SlowDragDriver(LiveDriver()),      # allow_actions 保持默认 False，采集不需要动作能力
    read_labels=...,
    read_rows=...,
    on_military_board=...,
    say=say,
)
first_screen = nav.open_military_ranking()    # 认不出就抛 RankingNotReached，别兜底成"继续走"
while True:
    step = nav.scroll_once()
    if step.outcome is ScrollOutcome.SCROLLED:
        ...  # step.rows 就是拖完之后这一屏，别再读一次（那是另一帧画面）

```

`EXHAUSTED` 与 `OFF_PAGE` **必须区别对待**：前者收工入库，后者要把这一轮最后几屏当可疑的看，
并交给 `game.session_keeper` 重连。合成一个 `False` 就会把半截榜单当成完整榜单收工。

## 3. 这次要做的

### 3.1 读数层：`read_rows`

从整窗截图（`LiveDriver.capture()`）读出当前这一屏的 `RankingRow`。

**契约（`ranking_nav` 模块头写死的）：认不出的行必须丢掉，不留占位。**
因为上层拿「读到 0 行」当「我不在榜单页上」的唯一判据——留了占位，掉线就认不出来了。

流程建议：

1. 按 `ROW_FIRST_Y=257`、`ROW_PITCH_PX=44.8`、`RANKING_LIST_MAX_Y=815` 切出每一行；
2. 每行再按**列边界**切成 名次 / 名字 / 分数 三格（列边界见第 5 节 —— **还没标定**）；
3. 每格独立 OCR（配方见第 4 节）；
4. 组装成 `RankingRow(rank=..., name=..., score=..., coordinate=coordinate_of(name))`。

⚠️ **`SELF_ROW_Y = 837`（自己那一行）不是榜单行。** 它钉死在屏幕上不随滚动移动，
每滚一屏都原样出现一次。当成榜单行的话，既会重复入库，又会让「拖了一下内容没变」
这条到底判据变迟钝。`RANKING_LIST_MAX_Y=815` 就是为了卡在它上面，别调大。

### 3.2 判据层：`on_military_board`

判据在 `domain.ranking` 那一侧，形状是**「分数列全 0 就说明还在经济榜」**。
`domain/ranking.py` 目前**没有**这个函数——你要加一个（连测试），别写在 `game` 层。

### 3.3 一屏读完之后的自查（顺序有讲究）

```python
ranks  = repair_ranks([row.rank for row in rows])          # 名次连续 → 免费校验和，能修回来
breaks = descending_breaks([row.score for row in rows])    # 破坏降序的 → 只报，不改
scores = interpolate_scores([row.score for row in rows])   # 读不出的 → 取上下中点
targets = bot_rows(rows)                                   # 只留反解出坐标的
```

⚠️ `interpolate_scores` **插出来的值必须在库里标成「估算」**。这个仓有一条硬规矩：
猜出来的数不许长得像量出来的。函数只负责算，标记是你的事。

### 3.4 入库

还要能区分**这个坐标是扫出来的还是榜上抄来的**（`domain/ranking.py` 的

## 4. 已经定死的事实（实机换来的，不要重新发明）

### 4.1 榜单行的 OCR 配方（实测在用户提供的军事榜截图上：名次 12/12、名字 12/12、分数 10/12）

> **灰度 → 不二值化 → 3× LANCZOS → 逐格切 → `--psm 7`**

- **不要二值化。** 这个背景极易干扰（用户原话："这里的背景极易干扰"），二值化之后更糟。
- **逐格切、`--psm 7`**（单行）；整行 `--psm 6` 读得很碎。
- 标签行是另一套：`chi_sim`、`--psm 6`、3×（`nav_label_words` 里已经写好了，别动）。

### 4.2 名字 OCR 错误率约 8%，形态是**数字重复**

```
2:121:7   读作 bot_2_1121_7    ← 1121 > 499，被区间挡住
2:123:12  读作 bot_2_123_122   ← 122 > 20，被区间挡住
```

用户库里 435 个已扫 bot，35 个名字反解不出原坐标，全是这个形态。

### 4.3 三列的地位完全不同 —— 精度预算全给名字

| 列 | 读错的后果 |
|---|---|
| **名字** | **往一个不存在或不相干的坐标派兵** |
| 名次 | 顺序乱（而且能从邻居修回来） |
| 军力值 | 无（插值或留空即可） |

用户口径：「基于榜单排序，我不需要精确值……甚至有排名 我接受读不出值」。
**别为了把分数读准去加重试、加预处理。** 那是花在错的地方。

### 4.4 ⚠️「恒星系号连续」**不能用**当校验和

我一度以为可以——那是在**经济评分**页上看到的：bot 在经济榜全是 0 分，
并列时退化成坐标序，于是 1:1:5 / 1:2:20 / 1:3:9 一路连续。
**军事榜上 bot 有真实分数、按分数降序，坐标是乱的**（30 / 100 / 183 / 160 / 360…）。

用户原话：「0 分列是玩家 你不要关注，bot 都是有分数的，并且排名中坐标是不连续的」。

### 4.5 其它实机数

- bot 从**约第 639 名**开始（用户："榜单是从 600 之后才开始出现 bot，往后就都是 bot"）。
  但**判据是「名字反解得出坐标」，不是「名次 > 638」**——真人数量会变。
- bot 总数量级 **9 × 499**（用户估）。
- 一次滚动推进 **≈ 8.3 名**，连等待约 **5 秒**（`ROWS_PER_SCROLL`）。
  实机日志 `var/logs/rank-scan.log`：60 次拖动到第 473 名，与之相符。
- **关掉排名面板再打开，列表回到顶部**（用户实测确认），要重新拉。
- bot 军力**每周一 UTC+0 随机刷新**。

## 6. 安全红线（**违反任何一条都是事故，不是 bug**）

1. **`(1170, 70)` 是「$ 充值」——禁区。**
   `ranking_ui.RECHARGE_KEEPOUT_CENTER` 定义在那儿的**唯一理由是用来远离它**：
   `tests/unit/game/test_ranking_ui_geometry.py` 拿它把每一个会被点到的点都量一遍，
   离得不够远就红。**你新加任何一个点击坐标，都要过这把尺子。**

2. **认不出的画面绝不点击。** 空结果不是证据——所有"读一屏"都要走重读
   （`READ_ATTEMPTS=3` × `REREAD_WAIT_S=0.6`）。这条是实机通宵白跑两小时换来的。

3. **`nav.close()` 必须调。**
   导航条拖过之后，`pirate_ui.NAV_PLANET`(840, 862) 上坐着的不再是「行星」，
   而是**「太空舱」**（拖完中心在 830，差 10px）——那东西点开是材料仓库、还会盖住整条导航条。
   把条留在右段就交回控制权，等于给下一条链路埋雷。

4. **`LiveDriver(allow_actions=...)` 保持默认 `False`。** 采集不需要动作能力。
   这个开关全仓只有构造点这一处，翻一眼就知道哪个进程能把舰队送出去。

## 7. 仓库规矩

- **中文注释与文档**，源文件 `# -*- coding: utf-8 -*-`，读写一律 UTF-8。
- 闸门（**四个都要绿**）：

```bash
.venv/Scripts/python.exe -m pytest tests -q && .venv/Scripts/python.exe -m ruff check src tests && .venv/Scripts/python.exe -m ruff format --check src tests && .venv/Scripts/python.exe -m mypy src
```

  注意 `ruff format --check` 也在 CI 里；`mypy` 的参数是 `src`（不是裸跑）。
- **变异测试是真正的质量闸**：每条护栏都改坏一次，确认测试变红，再还原。
  测试全绿不算数——绿的测试可能什么都没测到（本次就抓到过一条这样的假测试）。
- ⚠️ **过期 `.pyc` 会让变异测试撒谎。** 改动只换了几个字符、文件长度不变时，
  Python 会读旧字节码（pyc 只按 mtime 秒 + 长度校验），于是**改坏了也是绿的**。
  `-B` 没用（只阻止写，不阻止读）。**每次变异前删 `__pycache__`。**
- 控制台是 GBK：输出里不要放 `✓`/`✗` 之类的字符，会 `UnicodeEncodeError`。
  仓里有 `make_console_encoding_safe()`。
- 可选依赖（pytesseract 等）缺失时**降级运行而不是报错**，新代码保持这个模式。
