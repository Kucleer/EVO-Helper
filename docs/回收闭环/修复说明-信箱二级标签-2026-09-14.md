## 1. 代码改动

### 1.1 ✅ 切不了二级标签的提前返回补 `aborted=True`（复核第一轮 P1）

**问题**：

```
tally.swept = not scan.deadline_hit and not scan.aborted   ← 不看 cut_short
   ↓  swept = True
record_daily_reconciliation(...)                            ← 对账时刻照写
   ↓
后续轮次因冷却跳过
```

一趟什么都没扫的行程被记成「翻完了」。**这与 09-13 夜那次事故是同一个病**：
失败的一趟被记成成功的一趟。

⚠️ `aborted` 字段的文档里**逐字写着这一档** ——「半路出事（丢了邮件列表重进不回、**切不回二级标签**）」。
字段是为这种情况设计的，我没设。

**改动**：`_scan_mail_rows` 里两处提前返回都加 `aborted=True`：

### 1.2 ✅ 守它的测试**重写**（复核第二轮 P1）

**问题**：我第一版测试是这样写的 ——

```python
returns = re.findall(r"return MailScan\((.*?)\)\n", source, re.S)
assert "aborted=True" in body
```

而两处 `return` 里的**注释**也含 `aborted=True` 这串字。

⚠️⚠️ **我当场做了实验**：把两处真参数删掉、只留注释，`pytest` **照样绿**。
那个测试守不住任何东西。

⚠️ 这正是我自己记忆里那条「守卫别扫源码文本」——**源码文本匹配分不清代码和注释**。
两天内第四次栽在同一类上，这次还是栽在专门用来守这个的测试里。

**改法**：真跑那两条路径、断言返回对象，并把下游那个结论一起断言：

```python
recycle = _scan_that_gives_up(fleet_sub_tab=True,  filter_looks_on=False)
report  = _scan_that_gives_up(fleet_sub_tab=False, filter_looks_on=True)
assert recycle.aborted is True
assert report.aborted  is True
for scan in (recycle, report):
    swept = not scan.deadline_hit and not scan.aborted   # 判据抄自 _scan_for_reconcile
    assert swept is False
```

**验证方式**：再做一次同样的删除实验 —— 新测试**红了**（2 failed），还原后绿。
⚠️ 这不是「我认为它有效」，是当场演示过的。
