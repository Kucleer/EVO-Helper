## 1. 结构性缺口：滑块这条路没有「接在哪」

### 1.1 文档说了什么

所有文档一致：触发点 = 航线释放（`_still_holding_a_line`）、按来源 `dispatch_id` 去重、`acc` 落库、目标 = 刚打过的那颗、
出发星球 = 那一发的出发星球、同一条线接着用。

### 1.2 代码现状决定了答案不能随便选

| 事实 | 出处 | 后果 |
|---|---|---|
| 「航线释放」是调度器每 tick 现算的状态 | `mission_scheduler._facts` / `_account_free_lines` | 运行器看不见它，只有调度器能做 `acc` 决策 |
| 运行器一轮只站一颗出发星球，目标清单和预算走命令行 | `_military_command`：「整轮只跑一颗星球不是可以放宽的实现细节」 | 回收要点游戏界面，只能发生在某颗星球的某一轮里 |
| 哪颗星球轮到出兵按公平性决定 | `_origin_taking_its_turn`：上次出兵最久远的那颗 | 线刚空的那颗**未必**是下一轮 |
| 轮内已派数只数攻击成功 | `bot_loop._sweep`：`if self._attack_once(...): dispatched += 1` | 回收派出后不计入 `max_dispatches`，轮会超派 |

### 1.3 所以滑块路径实际是三段，且一段都没写

    ① 调度器 tick：对「已释放、未决策」的攻击派遣做 acc 决策 → 决策行落库（幂等键 = dispatch_id）
    ② 选中的 → 生成一条回收作业（坐标、出发星球、来源 dispatch_id）
    ③ 那颗星球下一轮运行器的命令里先带回收作业、再带攻击目标；预算按实际派遣扣

要补的文档至少回答：

1. 决策在调度器哪个位置执行（`_facts` 之后？`_launch` 之前？），每 tick 扫一次还是只在起轮前扫？
2. 回收作业怎么进运行器命令（`bot_command` 加一类目标？还是新的 `MissionKind`？）
3. 预算：回收占用 `max_dispatches` 的一个名额，并以 `mission_kind = RECYCLE` 写 `attack_dispatches`，
   让 `_still_holding_a_line` 自动把它算进账号级空线数
4. 幂等键在三段之间怎么传（决策行 → 作业 → 派遣行）
5. 决策做了但那颗星球好几轮没轮到时，作业过期吗？（残骸会被别人收走）

### 1.4 顺带回答了 README §6.2「要不要攒批」

批就是「那颗星球的下一轮」。切星球的 37.8 秒是每轮付一次，不是每次回收付一次，
不需要另设计攒批。`流程图.md` §3 的 R1「出发星球还在当前视图吗」在这个结构下恒为「是」。

### 1.5 预算问题要从「入口 A 专属」改成通用

`设计.md` §7.2 把「攻击被拒、但回收已派出」的预算表达只挂在入口 A 上。
滑块路径同样会在轮内派回收，同样需要计入 `dispatched`。两条入口共用一个规则：
**按实际派遣、分任务类型扣三处预算**。

## 2. 算法缺陷：误差累加用浮点数会算错

`节奏滑块.md` §3.2 给的序列 `0.6 1.2✓ 0.8 1.4✓ 1.0✓ …` 在实数上成立，在浮点上不成立：

| 实现 | 前 10 发命中 | 前 20 发命中 |
|---|---|---|
| `acc: float`，`r = 0.6` | **5** | 11 |
| `acc: int`（十分位），`R = 6`，阈值 10 | **6** | 12 |

原因：`0.2 + 0.6 + 0.6 − 1 = 0.39999…`，再 `+ 0.6 = 0.99999…`，过不了 1。
`acc` 要落库、跨重启累积，误差只会越来越大。

**改法**：滑块本身步进 0.1，所以 `r` 存 0–10 的整数、`acc` 存 0–9 的整数、阈值 10。
顺带避开了「档位改过之后历史怎么解释」里的浮点比较。

**加一条构造用例**：`r = 0.6` 连跑 100 发必须正好 60 发；`r = 0.1` 连跑 100 发正好 10 发。

复现脚本：

```python
acc = 0.0; r = 0.6; hits = 0
for _ in range(10):
    acc += r
    if acc >= 1: acc -= 1; hits += 1
print(hits)   # 5，不是 6
```

### 4.2 入口 A 和滑块的关系（`设计.md` §7.2 标为「必须补齐」）

建议：把入口 A 也当成一次「尝试机会」走同一个 `acc`：

    攻击被拒（保护期） → acc >= 1 ? → 是：acc -= 1，读面板找「回收」按钮
                                    → 否：跳过，照旧下一个目标

这样「滑块管尝试节奏」的语义对两条入口一致，`r = 0` 自动禁止入口 A，不需要单独的规则。

⚠️ 未决：幂等键。攻击被拒时没有 `dispatch_id`，而 `attack()` 里弹窗检查发生在 `_record_intent` **之前**，
也没有意图 id。只能用 `(坐标, protection_seen_at_utc)`。

### 4.3 `_still_holding_a_line` 第三档（航线钟为 NULL、按 `hold` 兜底）算不算返航

**建议算。** 理由：

- `acc` 管的是节奏，不是物理航线。
- 真正执行回收时，调度器已经用**同一个判据**算过该星球的空线预算；没有线就 `MissionIdle`，不起轮
  （`_military_command`：`budget < 1 → MissionIdle`）。所以第三档计数**不会**造成「舰队还在天上就派回收」。
- 不算的代价是那批读不出飞行时间的派遣永远不触发，那是**系统性偏差**，比偶尔多等一轮贵。

### 4.4 原型没按滑块更新

结论不变，但排在实现之后。页面规格已在 `概览面板.md` 定死（四个数分开显示、`acc` 当前值、
「残骸实收」恒为「未知」），原型只是插图。
