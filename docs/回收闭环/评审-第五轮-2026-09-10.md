## 1. 入口 A 的幂等键：`(坐标, protection_seen_at_utc)` 不成立

三条代码事实：

| 事实 | 出处 |
|---|---|
| `protection_seen_at_utc` 是 `bot_targets` 上**一列**，每次撞上就覆盖，不是事件表 | `repository.note_protection_period`：`target.protection_seen_at_utc = seen_at_utc` |
| 坐标没有 `bot_targets` 行时**什么都不写**、返回 False | 同上：`if target is None: return False` |
| 运行器 `_ensure_run()` 交出的 run_id 是**整条链路共用的持久实例**，不是这一轮的 | `pirate_loop._ensure_run_row`：按 `RUN_KEY` 找或建 `RunInstance`，跨轮复用 |

后果：

- 用覆盖列当键，决策表里那条记录和 `bot_targets` 上的值一秒后就对不上，事后重建不出「当时是哪次撞上」。
- 海盗位（1–4 号位）撞保护期时根本没有那个时刻，键为空。
- 若有人顺手用 `_ensure_run()` 的 run_id 组键，同一坐标跨轮再撞就撞键。

**正确的键：`(本轮 mission_runs.run_id, 坐标)`。**

- 这一轮的 run_id 由调度器起子进程前生成，经环境变量 `EVO_HELPER_LOG_RUN_ID` 交给运行器（`system_log.py:133` 已在读它）。
- 一轮的目标清单里每个坐标只出现一次（`_military_command` 交整组，坐标不重复），所以「一轮里每个目标最多撞一次」成立，键唯一。
- ⚠️ 文档里必须写死「是 `EVO_HELPER_LOG_RUN_ID` 那个，不是 `_ensure_run()` 那个」，两个都叫 run_id。
- ⚠️ 手工直跑没有那个环境变量时 run_id 为 NULL：入口 A **不做**，记一条「无轮次、跳过」。别退回时间戳键。

## 2. 只有回收作业的轮起不来

`调度接线.md` §2 说「那颗星球下一轮运行器起来时，命令里先带回收作业、再带攻击目标」。但起轮的判据现在全部围着**攻击目标**：

| 代码 | 现状 | 对回收作业的后果 |
|---|---|---|
| `_military_command` | `assignments` 为空 → `MissionIdle("本轮没有可派遣的军力攻击目标")` | 候选池空、或全在保护期时，**有作业也不起轮** |
| `_origin_taking_its_turn(assignments)` | 只在**分到了攻击目标**的星球里轮 | 只有作业、没目标的星球**永远轮不到** |
| `budget = min(max_dispatches, len(primaries))` | 只按正选攻击目标算 | 作业占了名额后，攻击预算没有相应减少 |

`r = 1` 时这不是边角：单航线星球攻击一释放，下一轮**就应该是**纯回收轮，而它正好是起不来的那种。

要补的三句：

1. 起轮判据：`有攻击目标 或 有待执行作业` 才 `MissionIdle` 之外。
2. 轮换候选：`分到目标的星球 ∪ 有待执行作业的星球`。
3. 预算：作业先占名额，攻击目标只拿剩下的；`--max-dispatches` 仍是总数。

## 3. 决策扫描放在 tick 的哪儿

§3.1 写「在 `_facts` 之后、`_launch` 之前」。`_facts` 在 `_step()` 里按参与调度的任务算，而 `tick()` 的注释明写「`_step` 一个 tick 里会转好几圈，每圈都去数一遍在飞舰队纯属白付」。

`tick()` 里已经有一块「按 tick 算一次就够」的位置：`_cut_off_a_stalled_round` → `_resume_tasks_waiting_for_a_line` → `_resume_tasks_after_a_backoff` → 然后才进 `_step` 循环。**决策扫描放在这一排**，每 tick 恰好一次，起轮时作业已经在库里了。

⚠️ 扫描范围除了 `mission_kind = ATTACK`，还要加 **`target_kind = BOT`**。海盗链路（1–4 号位）的派遣同样在 `attack_dispatches` 里、同样会释放航线；它们要不要喂 `acc`，文档没说。按用户口径（回收的是刚打过的 bot），应当排除。

## 4. 三条「没答的」，两条现在能答

### 4.1 作业过期时长：不用等「残骸衰不衰减」

过期的代价只是**时间**：到了没按钮就不派，不占线、不占名额（§3.3 只数实际派遣）。所以不需要精确值，需要的是两个**已知**锚点：

- **被更新的攻击取代**：同一坐标又被我们打了一发，新那发的决策覆盖旧作业（每个坐标最多一条待执行作业）。
- **时间上限可配置**，默认给一个宽的值（例如 24 小时），落成运维旋钮而不是常量。

过期和被取代都记原因，页面「跳过原因」那一列分得出「去了没残骸 / 过期没去 / 被新一发取代」。

### 4.2 `--recycle` 一轮带几个：带一组，和 `--targets` 同形

- 一颗星球等轮换期间可能攒下多条作业（两条线的星球尤其），所以 `--recycle` 应 `nargs="+"`。
- 运行器按顺序执行，直到名额用完；没执行到的**留在库里**，下一轮再带（受 4.1 的过期约束）。
- 顺序：**新的先**。残骸越新越可能还在；旧的自然过期。
