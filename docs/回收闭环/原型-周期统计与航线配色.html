合计卡：怎么算

⚠️ 必须从上面那几张卡加出来，不能另走一趟查询。 现有注释写得很清楚：读这一页的人正是拿「合计」和「明细」判此刻还能不能派， 一个和明细矛盾的合计比不显示合计更糟。LineTotals.of(cards) 的入参就是模板遍历的那个元组，新增的攻击/回收计数照样从里面 sum()。

合计卡仍然不画格子（那是刻意的），改成一条占比条 + 一行拆分数字。 「空」那一档在全满时是 0，条形里就不占宽度。

公式

派遣 = count(attack_dispatches) where accepted and mission_kind in ('ATTACK','RECYCLE') 攻击 = 同上，mission_kind = 'ATTACK' 回收 = 同上，mission_kind = 'RECYCLE' 攻击战报 = count(battle_reports) where reported_at_utc ∈ [start, end) ← 口径未变 战报回收率 = 攻击战报 ÷ 攻击 回收率 = 回收 ÷ 攻击 挂机 / 利用率 —— 原样不动

两条实现注意

  • ⚠️ 「—」只给功能还不存在的日子。 加 RECYCLE_STATS_START_UTC = 2026-09-10（照 RESOURCE_STATS_START_UTC 的先例）。 09-10 起，真的零回收必须显示 0 —— 显示「—」会把「回收挂了」伪装成「没数据」。
  • colspan="11" 在 _overview_periods.html:78 是写死的。 列数 11 → 12（+攻击 +回收 +回收率 −残骸趟数 −残骸占线），必须同步改。
  • PeriodRow.empty 只看 dispatches / reports / rare 三样。现在回收进了 dispatches， 「只有回收、没有攻击和战报」的末尾行不会再被误砍 —— 这条顺带修好了。
