## 2. 现在定下来的是什么

### 配置：只有一个

    回收节奏  0.0 – 1.0，步进 0.1，全局，默认 0.0（关）

拉到 1 就是「攻击-回收-攻击-回收」，**攻击和回收共用同一条航线**。

### 机制（⚠️ 整数十分位，`R` = 滑块 × 10，阈值 10）

    调度器 tick：攻击那条航线释放（且 target_kind = bot）
      → 这一发决策过了吗？（dispatch_id 查重，防重启重放）
      → acc += R
      → acc >= 10 ?  是 → acc -= 10，生成一条**回收作业**
                     否 → 记一条「未选中」，这条线改派攻击

    那颗星球的**下一轮**运行器起来：命令里带着作业
      → 面板上有「回收」按钮吗？   没有 → 不派、记观察、acc 不回退
      → 有 → 残骸框 → 绿✓ → 派遣页（舰队自动配好）→ 点勾
             ⇒ **点勾没弹窗 = 已派出**（R21），记一发派遣、占线
             → 简报页（读飞行时间；⚠️ 读任务类型**只告警不拦**，R24）→ 点「出发！」
             → **到此为止，不追结果**（R16）

⚠️ **不看战报**（用户 2026-09-10：「派不派和战报没关系，不要进行耦合」）。
「有没有残骸」由面板上那个按钮回答。

⚠️ **决策在调度器、动作在运行器，中间隔着一次公平轮换** —— 见
[`调度接线.md`](调度接线.md)。批就是「那颗星球的下一轮」，不用另设计攒批。

⚠️ **`acc` 落整数、决策按 `dispatch_id` 唯一记一条**（含当时档位、acc 前后、执行状态）。
「航线空出来」是每次查询现算的状态、不是事件，不查重的话重启会重复计数。

⚠️ **作业不许跨周**（周一 00:00 UTC 是 bot 刷新日，全库军力读数整批作废）——
用户裁决保留，R23。

## 3. ⚠️ 这一版**答不了**什么

    能记的： 决策（选没选中）→ 观察（有没有按钮）→ 派遣 → 占线 / 释放
    记不了： 这一趟实收多少、那颗星球原本有多少残骸

因为用户 2026-09-10 把**回收邮件**和**残骸框数字**都 hold 了，
并且定了「**收走就被收走，暂时不追踪数据**」（R16）⇒ **派出即终态**。

⇒ **页面上「残骸实收」必须显示为「未知」** —— 不许显示 0、不许拿别的数顶替。
⇒ **这一版不能叫「实收闭环完成」**，数据链在「派出去了」那一步就断了。

⚠️ **页面也不体检了**（R17：「不需要跳过原因……写未派出就可以了」）——
页面只给**应尝试 / 已派出 / 未派出**三个数，五种原因全在 `system_log` 里。
⇒ **回收正不正常，只能查日志。**
