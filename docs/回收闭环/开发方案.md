## 2. PR-A：弹窗分流改造

**规格全文**：[`弹窗分流改造.md`](弹窗分流改造.md)

### 要改的

    src/evo_helper/game/pirate_ui.py     三个 enum + 一张六格表 + dialog_action()
    src/evo_helper/tools/pirate_loop.py  _handle_dialog 及其 4 个调用点 + 各自上游
    tests/                               三处引用现有 DialogKind 的用例

### 形状

```python
class DialogMessage(Enum):      # 观测：游戏说了什么
    NO_MISSION / NO_SHIPS / LINES_FULL

class DispatchPurpose(Enum):    # 意图：这一次点击是为了派什么
    ATTACK / SCOUT / RECYCLE

class DialogAction(Enum):       # 处置：我们该做什么
    SKIP_PROTECTED / SKIP_NO_DEBRIS / SKIP_NO_RECYCLERS / STOP_ROUND

_ACTIONS: dict[tuple[DialogMessage, DispatchPurpose], DialogAction]
def dialog_action(message: str, *, purpose: DispatchPurpose) -> DialogAction: ...
```

### ⚠️ 四个地雷

1. **`purpose` 必须从顶层贯穿到底，每一层都是必填关键字参数、不设默认值。**
   `_handle_dialog` 有 **4 个**调用点（`_require_origin_before_dispatch` 2533 /
   `_launch` 2646 / `scout` 2673 / `attack` 2751）。
   ⚠️ **只在分类那一处传 `purpose` 挡不住这个坑** —— 回收起点读不出时会走
   `_require_origin_before_dispatch`，那里若固定传 ATTACK，「没有可执行的任务」
   照样判成保护期、**往库里写 8 小时排除**。
2. **`(NO_MISSION, RECYCLE)` 绝不能调 `_note_protection_period`。**
   后果是一颗打得了的 bot 被排出候选池 8 小时，**页面和日志都看不出异常**。
3. **`(NO_SHIPS, RECYCLE)` 是 `SKIP_NO_RECYCLERS`，不是 `STOP_ROUND`。**
   回收和攻击是两拨船（R19），照抄会让「回收船不够」把这一轮的攻击也停掉。
   ⚠️ 这一支要按 **WARNING** 记：用户说它不该发生，真发生了多半是走错屏。
4. **`SCOUT` 那一档要一并写死**，否则六格表变成九格表缺三格。

### 验收

- **行为一个字不变**：这一版全部传 `ATTACK` / `SCOUT`，回收那三格只是先摆在那儿
- ⚠️ **变异测试**（改了必须红）：
  - `(NO_MISSION, RECYCLE)` → `SKIP_PROTECTED`
  - `(NO_SHIPS, RECYCLE)` → `STOP_ROUND`
  - 把 `purpose` 维度整个拆掉
  - **让 `_require_origin_before_dispatch` 固定传 ATTACK**
- ⚠️ **两条源码级断言**（不能靠跑流程）：
  - `_note_protection_period` 全仓**只有一处**调用点，且只在 `SKIP_PROTECTED` 那一支
  - `_handle_dialog` 的**每一个**调用点都显式传了 `purpose`
- 必须有一条用例真的走「**回收 + 起点读不出 + 弹窗**」这条路

## 3. PR-B：保护期排除计数 + 历史基线

**规格**：[`概览面板.md`](概览面板.md) §6

### 要做的

1. 概览页加一个数：**本周期新写入了几条 8 小时保护期排除**
2. 上线时**把历史基线一并算出来**（过去几周）

### ⚠️ 数据来源只有一个是对的

    ✅ system_log —— _note_protection_period 每次撞上都写一条，两个分支都写：
         recorded = True   → INFO
         recorded = False  → WARNING（bot_targets 里没有那一行）
       payload：target / seen_at_utc / exclusion_hours / recorded / evidence="dialog"

    ❌ bot_targets.protection_seen_at_utc（repository.py:2585 那个查询）
       ⚠️ **那一列是覆盖的** —— 同一坐标一周撞三次只算一次，数出来必然偏小

### ⚠️ 两条过滤条件，缺一个基线就是错的（第八轮评审 §3）

| 条件 | 为什么 |
|---|---|
| **只数 `recorded = true`** | `false` 那一档**根本没落库、没排除任何目标**（`bot_targets` 里没有那一行）。数进去会把基线**抬高**，而这个探针的全部意义就是「涨了就说明串链路」 |
| **只数 `evidence = "dialog"`** | 别把 `#299` 那条**邮件侧认出的保护返航**混进来 —— 那是另一条路径的证据，不是派遣时撞的弹窗 |

### 为什么值得单独一个 PR

它是 PR-A 那个坑**唯一的探针**：回收撞「没残骸」若被误记成保护期，
这个数会异常上涨，而**别处一点异样都没有**。
⇒ 最好和 PR-A 一起发，让它在只有攻击的日子里先跑着。

## 4. PR-C：预算扣减

**规格**：[`设计.md`](设计.md) §7.2

### 病根

    bot_loop.py:541    if self._attack_once(coordinate): dispatched += 1
                       ← 只有攻击**成功**才算进本轮已派数

保护期那条路 `_attack_once` 返回 **False** ⇒ 不计数、继续试下一个目标。

⇒ 当本轮只剩 1 条空线、攻击被拒、而回收**已经占走那条线**时：

    照旧返回 False  →  runner 以为预算没用  →  继续试攻击  →  撞「航线已达上限」
    草率改成 True   →  被当成一次攻击成功记账 ❌

### 要做的

- 让 `_sweep` 能表达「**攻击被拒、但回收已派出**」这个结果
- 按**实际派遣**统一扣减 本轮 / 账号 / 起点 三处预算，**任务类型分开记账**
- ⚠️ 规则对**两条入口通用**（滑块路径 + 攻击被拒就地改回收），不是入口 A 专属

## 5. PR-D：调度接线 —— 让纯回收轮起得来

**规格**：[`调度接线.md`](调度接线.md) §3.2.1

### ⚠️ 四层都挡着，而第 4 层最凶

| 层 | 代码 | 现在会怎样 | 自愈 |
|---|---|---|---|
| 1 | `_military_command`：`if not assignments: raise MissionIdle` | 有作业也不起轮 | 会 |
| 2 | `_origin_taking_its_turn(assignments)` | 只有作业的星球**永远轮不到** | ⚠️ 不会 |
| 3 | `budget = min(max_dispatches, len(primaries))`，`< 1` ⇒ `MissionIdle` | 作业占了名额、攻击预算没减 | 会 |
| 4 | ⚠️ `bot_command`：`if not targets: raise MissionParamError`（`missions.py:227`） | **任务被停用**，`DisabledRecovery.MANUAL` —— **用户不去页面点「恢复」就永远不跑** | ⚠️⚠️ 不会 |

⚠️ `r = 1` 时这不是边角：**单航线星球（7 颗里 5 颗）攻击一释放，下一轮本来就该是纯回收轮。**

### 要改的四句

1. **起轮判据**：⚠️ **攻击目标和待执行作业「都」为空才 `MissionIdle`**
2. **轮换候选**：`分到目标的星球 ∪ 有待执行作业的星球`
3. **预算**：作业**先占名额**，攻击目标只拿剩下的；`--max-dispatches` 仍是总数
4. ⚠️ **空目标不再是 `MissionParamError`**：`bot_command` 与 `bot_loop` 都要允许
   `--targets` 为空（前提是 `--recycle` 非空）；`--targets` 现在是
   `nargs="+" required=True`（`bot_loop.py:690`）

⚠️ **只改前三层，第 4 层会把「今晚跑一轮纯回收」变成「bot 任务被停用一整夜」。**

### E2 · 决策扫描（调度器侧）

**位置**：`tick()` 里那一排「按 tick 算一次就够」的动作，**排在 `_step` 循环之前**：

    _cut_off_a_stalled_round (1564)
      → _resume_tasks_waiting_for_a_line
        → _resume_tasks_after_a_backoff (1573)
          → 【回收决策扫描】        ← 放这里

**扫描条件**（⚠️ `target_kind` 不在派遣行上，必须 JOIN）：

```sql
attack_dispatches JOIN attack_intents ON attack_dispatches.intent_id = attack_intents.id
  WHERE mission_kind = 'ATTACK'
    AND attack_intents.target_kind = 'bot'        -- ⚠️ 海盗不回收（R13）
    AND 那条线已释放（_still_holding_a_line 为假，hold 传 _unknown_line_hold()）
    AND dispatch_id 不在 recycle_decisions 里
```

**计数**（⚠️ 整数，页面上也不许用浮点）：

    acc += R;  若 acc >= 10:  acc -= 10，生成一条 recycle_jobs（待执行）

⚠️ **首次启用的历史边界**：滑块从 0 调到非 0 的那一刻，库里躺着一大批早已释放的航线。
**只对「开启之后才释放的」计数** —— 开启时刻落库，作为决策记录的下界。

⚠️ **`acc` 本身不跨周清零**（第八轮评审 §5 提醒）。R23 说的是**作业**不许跨周，
**不是计数器**。⇒ 周一 00:00 那一刻 `acc` 原样带过去，别顺手清成 0 ——

## 7. ⚠️ 十五条地雷 —— 每一条都会**静默**出错

| # | 地雷 | 踩了会怎样 |
|---|---|---|
| 1 | `purpose` 在任何一层漏传 / 给了默认值 | 那条路悄悄拿到攻击那一档的处置，**一年才走到一次** |
| 2 | 回收撞「没有可执行的任务」写了保护期排除 | **打得了的 bot 被排出候选池 8 小时**，页面日志都正常 |

| 5 | `acc` 只放进程内存 | 一天重启不止一次（09-09 四次），比例被系统性拉低 |
| 6 | 入口 A 的幂等键拿错 run_id | 用 `EVO_HELPER_LOG_RUN_ID` 那个（`system_log.py:133`），**不是 `_ensure_run()` 那个**（`RUN_KEY` 跨轮复用）；手工直跑没那个环境变量 ⇒ run_id 为 NULL ⇒ **入口 A 不做**，别退回时间戳键 |
| 7 | 这个键上挂外键 | `mission_runs` 那一行在 `supervisor.start()` **之后**才写（2842），run_id 在 2823 就生成 ⇒ **别挂** |

| 9 | 「顺手修好」`cycle_start_utc` | `pirate_loop.py:4872` 写的是 `now` 而不是周一 00:00 —— ⚠️ **那个 bug 是承重的**：改对了，同一坐标一周的第二发攻击当场抛 `StorageConflictError`（R14） |
| 10 | 只看 `line_free_at_utc` 判「航线释放」 | 漏掉**人工放手**与 **NULL 兜底**两档，后者占过 **13%**。必须用 `_still_holding_a_line`，`hold` 必填 |
| 11 | 空目标继续抛 `MissionParamError` | **bot 任务被停用到手点恢复** |
| 12 | 回收按钮**写死坐标**定位 | ⚠️⚠️ **R24 之后这是唯一的防线** —— 简报页类型只告警不拦，定位错了没有第二道闸 |

## 10. 上线与观测

- **发布在晚上**，一次重启带一批；说「已上生产」之前**先查启动日志的 sha**
- **滑块默认 0** ⇒ PR-E 上线当天不会有任何回收发生，可以先只看日志有没有异常
- 打开之后**头几天节奏会偏慢**：回收自己那一档的距离公式系数还没学到，
  读不出飞行时间的那 13% 走 90 分钟兜底（实际中位 51.4 分）⇒ 约 **4% 产能**，
  **会自愈，别当故障**
- ⚠️ **每天看一眼「保护期排除条数」**（PR-B 那个数）—— 它异常上涨就说明两条链路串了
