# 军力榜采集 — 实机验证清单

> 配套文档：[军力榜采集-交接.md](军力榜采集-交接.md)（第 5 节列的就是这里要量的东西）。
>
> **这份清单的目的不是"跑通"，是"量准"。** 底下三层已经合进 main，路径基本是通的；
> 缺的是一批**没量过的数**。量不到就如实写"待标定"——
> **拍脑袋填一个看起来合理的数，比空着危害大得多**，因为它会被下一个人当成实测。
>
> 日期：2026-08-14。

---

## 0. 前提

- **需要用户当次授权才能启动游戏。** 工作日 UTC+8 工作时间内尤其如此，
  而且授权**不跨场次继承**——上一次批过不算这一次。没拿到就停在这里。
- 前提条件：浏览器最大化 1920×1080、系统缩放 100%、窗口不动。
- 全程**约 40 分钟**（V9 那一项单独算，可能一小时以上且大概率会断线）。

## 1. 安全红线（违反任何一条都是事故）

| | |
|---|---|
| 🚫 | **`(1170, 70)` 是「$ 充值」。** 整个验证过程中**永远不要点它附近 100px**。 |
| 🚫 | **`(838, 212)` 是「经济评分」页签**——除了 V5 那一处受控对比，不要点。经济榜是另一套数据。 |
| 🚫 | **认不出的画面绝不点击。** 读不出东西就采图、停下、报告，不要"再试试点点看"。 |
| 🚫 | **不要开 `allow_actions`。** 验证只导航、只读，不派舰队、不领奖励、不删邮件。 |
| ✅ | **急停保持开启**（`pyautogui.FAILSAFE`，鼠标甩到屏幕左上角）。 |
| ✅ | **收尾必须还原导航条**（V10）。留在右段就给下一条链路埋雷。 |

## 2. ⚠️ 采图只有一种正确方式

`ranking_ui.py` 里所有数都是 **client 空间 1920×917**（含 38px 标题栏）。
用 mss / 系统截图工具抓到的是**屏幕空间**，y 会差 38px，量出来的数直接是错的。

**只用这一种：**

```python
from evo_helper.tools.scan_coordinates import LiveDriver
d = LiveDriver()          # allow_actions 保持默认 False
d.focus()
d.capture().save("var/logs/rankv-01-baseline.png")
```

每一步都存一张，文件名按 `rankv-<序号>-<在做什么>.png`。
**每个报出来的数都要附上是从哪张图量的。**

## 3. 验证项

按顺序做，这就是实机上的自然路径，能一趟走完。

### V1 · 基线：导航条**没拖**之前长什么样

**做**：任意一屏（主界面即可），采图。

**记**：底部导航条上看得见哪几个项、各自中心 x。

**为什么**：`pirate_ui.NAV_PLANET`(840, 862) 现在是「行星」——这是 V10 还原之后要回到的状态。
没有基线就没法判断"还原成功了没有"。

---

### V2 · 标签行 OCR（⚠️ **最关键，卡住后面全部**）

**做**：

1. 慢拖导航条：`(1122, 862) → (860, 862)`（**必须分步慢拖**，一步式 `dragTo` 会被面板当成点击）；
2. 等 1.2s，采图；
3. 按 `NAV_LABEL_ROI = (760, 880, 1220, 906)` 裁剪，灰度、3× LANCZOS、`chi_sim`、`--psm 6`，
   跑 `image_to_data` 拿**词框**。

**记**（这是本次验证最重要的一张表）：

| 要记的 | 说明 |
|---|---|
| 每个词框的 `(中心 x, 文字)` | 原始的，**合并之前** |
| 同一标签内两字的中心距 | 如「联」→「盟」 |
| 跨标签最相邻两字的中心距 | 如「盟」→「排」 |
| 五个标签合并后的中心 x | 与标定值 `太空舱 830 · 商店 918 · 联盟 998 · 排名 1079 · 设置 1159` 比 |

**判据**：合并（阈值 `NAV_LABEL_WORD_GAP_PX = 40`）之后必须恰好得到
`太空舱 / 商店 / 联盟 / 排名 / 设置` 五个标签，一个不多一个不少。

**失败了怎么办**：

- 读出 `联盟排名` 被**合成一个** → 阈值太大，往下调（真实上界应在 57 附近）。
- 「排名」只读到 `排` 或 `名`、贴不回词表 → 阈值太小，往上调（同标签内字距约 24）。
- **把量到的两个真实字距报出来**，40 这个数就能从"推出来的"变成"量出来的"。
  这是本模块唯一一个还没量过的数。
- ROI 完全读不出东西 → 先确认 `NAV_LABEL_ROI` 的 y 范围（880–906）在这张图上确实压着文字。

---

### V3 · 面板打开时默认停在哪个页签

**做**：点 V2 那一屏 OCR 出来的「排名」中心 x，y 用 `NAV_BAR_Y = 862`。等 1.8s，采图。

> ⚠️ 点的必须是**这一屏读出来的 x**，不是写死的 1079。

**记**：面板打开时高亮的是「玩家 / 联盟」哪一个、「经济评分 / 军事评分」哪一个；
第一屏榜单的前三行原文。

**判据**：能明确说出默认页签。代码已经兜住了（先读后点、点完回读），这一项是**确认现状**，
不是找 bug。

---

### V4 · 面板会不会盖住底部标签行

**做**：在 V3 那张图上，看 `NAV_LABEL_ROI`(760, 880, 1220, 906) 那一条还看不看得见。

**记**：看得见 / 被盖住。

**为什么**：`close()` 关面板之后要回读标签行来确认还原。如果面板开着时标签行也读得出来，
那"读到排名"就不能单独当作"条还停在右段"的证据。**这条影响 `close()` 的判据是否成立。**

---

### V5 · 军事榜 vs 经济榜（受控对比，**只此一次**）

**做**：

1. 在军事榜上采一屏，记前 5 行的 名次 / 名字 / 分数；
2. **只此一次**点「经济评分」`(838, 212)`，等 1.6s 采一屏，记前 5 行；
3. **立刻切回**「军事评分」`(1084, 212)`，等 1.6s，回读确认。

**判据**（这是 `on_military_board` 判据的实机依据）：

- 经济榜：bot 分数**全是 0**、坐标**连续**；
- 军事榜：bot 有真实分数（29.59K 这种）、按分数**降序**、坐标**乱**。

**记**：两边的原始行，以及**"分数列全 0"这个判据在实机上到底成不成立**。

> 做完这一项之后，`(838, 212)` 就回到禁区，别再点。

---

### V6 · ⚠️ 榜单列边界（**阻塞 `read_rows`，量不到后面写不了代码**）

`ranking_ui.py` 白纸黑字：「x 方向的列边界还没标定，所以这里只给 y」。**这一项就是来补这个的。**

**做**：在军事榜一屏的截图上，取一行的纵向范围（`ROW_FIRST_Y = 257`，行高约 `ROW_PITCH_PX = 44.8`），
横向取满（0–1920），灰度、3× LANCZOS、`--psm 6`，跑 `image_to_data` 拿**词框的 left/width**，
把 x 聚成簇。

**记**：

| 列 | 要记的 |
|---|---|
| 名次 `[639]` | 左右 x 边界 |
| 名字 `bot_4_30_12` | 左右 x 边界 |
| 联盟 `---` | 左右 x 边界（用来确认名字列的右界不会吃进它） |
| 军力值 `29.59K` | 左右 x 边界 |

**注意**：名字列最宽（`bot_4_100_13` 比 `bot_4_44_10` 长），
**边界要按最长的那个名字取，并且左右各留余量**。

**顺带验证配方**：拿量到的边界**逐格切**，灰度、**不二值化**、3× LANCZOS、`--psm 7`，
在同一屏 12 行上跑，报三列各自的正确率。参考值（在用户提供的截图上）：
名次 12/12、名字 12/12、分数 10/12。**明显低于这个就说明列边界切歪了。**

---

### V7 · 行几何核对

**做**：在同一张军事榜截图上核对四个已标定的数。

**记 / 判据**：

| 常量 | 标定值 | 怎么核 |
|---|---|---|
| `ROW_FIRST_Y` | 257 | 第一行文字中心 y |
| `ROW_PITCH_PX` | 44.8 | (最后一行中心 − 第一行中心) ÷ (行数−1) |
| `ROW_LAST_Y` | 795 | 最后一行中心 y |
| `SELF_ROW_Y` | 837 | **自己那一行**的中心 y |
| `RANKING_LIST_MAX_Y` | 815 | 必须落在 `ROW_LAST_Y` 与 `SELF_ROW_Y` **之间** |

⚠️ **重点确认「自己那一行」**：它钉死在屏幕上、不随滚动移动。
**滚一屏之后再采一张，确认它原样还在同一个 y。** 这一条要是不成立，
`RANKING_LIST_MAX_Y` 的整个设计就要重来。

---

### V8 · 滚动

**做**：慢拖 `(960, 700) → (960, 300)`，等 2.0s，采图。**连做 5 次**，每次都采。

**记**：

| 要记的 | 标定值 |
|---|---|
| 每次滚动推进多少名（后一屏首行名次 − 前一屏首行名次） | `ROWS_PER_SCROLL ≈ 8.3` |
| 一次滚动连等待的实际耗时 | 约 5 秒 |
| 2.0s 够不够惯性停下（拖完立刻采 vs 等 2s 采，有没有差别） | `SCROLL_SETTLE_WAIT_S = 2.0` |
| 有没有出现**滚了但内容没变** | 这会被判成"到底了" |

**为什么要记第四条**：`scroll_once` 拿"拖了一下内容没变"当到底判据。
如果实机上偶尔会出现"这一拖没生效"，那这个判据就会**提前收工**，
把半截榜单当成完整榜单——这是要提前知道的。

---

### V9 · 全榜长跑（可选，**大概率会断线**）

**做**：一直滚到底，或滚到断线为止。全程记日志。

**记**（这三个数决定"军力榜能不能取代全星系扫描"）：

1. **bot 从第几名开始**（第一个名字反解得出坐标的行）；
2. **bot 总数**（滚到底才知道；用户估计是 9 × 499 量级）；
3. **全榜滚完的总耗时**。

**已知**：上次实机滚到**第 473 名断线**（公司网络波动），从没到过第 639 名。
所以**断线是预期结果，不是失败**——记下断在第几名、滚了多久就有价值。

> ⚠️ 断线时**不要自动重连后继续拼接**。用户实测确认：**关掉面板再打开，列表回到顶部**。
> 所以断线之后是从头再来，不是接着滚。

---

### V10 · 收尾还原（**必做，不许跳过**）

**做**：

1. 点 `RANKING_CLOSE = (750, 71)` 关面板，等 1.2s；
2. **反向**慢拖导航条：`(860, 862) → (1122, 862)`；
3. 等 1.2s，采图，重跑 V2 的标签行 OCR。

**判据**：

- 标签行**读得出东西**（读到 0 个永远不算证据），且
- 里面**没有「排名」**，且
- `(840, 862)` 上坐着的重新是**「行星」**（与 V1 基线一致）。

**这一项是这次验证里唯一没被实机走过的动作**（`close()` 里那把反向拖是推出来的）。
拖过头 / 拖不够都要记下来——差 10px 就会让 `NAV_PLANET` 落在「太空舱」上，
那东西点开是材料仓库、还会盖住整条导航条。

**失败了**：手动把导航条拖回左段再收工，**并明确报告 `close()` 不可用**。

## 5. ⚠️ 绝对不要做的事

- ❌ **不要改 `src/` 下的任何代码。** 这一趟只测量。发现常量不对，**报告差多少**，
  由实现方去改（改常量要连测试一起改，那是另一件事）。
- ❌ **不要把没量到的数填成实测。** 空着比编好。
- ❌ **不要为了"跑通"绕过认不出的画面。** 读不出就停下采图报告——
  这一层每一条重读/放弃的逻辑都是实机通宵白跑两小时换来的，绕过去就白换了。
- ❌ **不要点充值、不要点经济评分（V5 那一次除外）、不要开 `allow_actions`。**
