## 四、怎么复算（把查询记下来，别每次重想）

全部只读，连接前先 `SET default_transaction_read_only = on`。

**A. 资源识别的覆盖率（先看这个，它决定别的能不能算）**

```sql
SELECT count(*) AS reports,
       count(*) FILTER (WHERE EXISTS (SELECT 1 FROM battle_report_resources r WHERE r.report_id = br.id)) AS with_resources
FROM battle_reports br
WHERE reported_at_utc >= TIMESTAMPTZ '2026-08-18 00:00:00+08';
```

**B. 单位数 → 三种稀有材料（第 7 条）**

```sql
SELECT br.defender_units,
       max(amount) FILTER (WHERE slot = '5') AS 合金碎片,
       max(amount) FILTER (WHERE slot = '8') AS 泰坦立方,
       max(amount) FILTER (WHERE slot = '9') AS 收割者碎片
FROM battle_reports br JOIN battle_report_resources r ON r.report_id = br.id
WHERE br.defender_units IS NOT NULL
GROUP BY br.id, br.defender_units ORDER BY br.defender_units;
```

**C. 运力封顶（第 4 条）**

```sql
SELECT br.attacker_units, sum(r.amount) AS haul,
       round(sum(r.amount) / br.attacker_units) AS per_unit
FROM battle_reports br JOIN battle_report_resources r ON r.report_id = br.id
WHERE br.attacker_units IS NOT NULL
GROUP BY br.id, br.attacker_units ORDER BY br.attacker_units;
```

**D. 军力 ↔ 守方单位（第 5 条）**

```sql
SELECT br.defender_units, bt.military_score
FROM battle_reports br
JOIN bot_targets bt ON bt.galaxy = br.defender_target_galaxy
                   AND bt.system = br.defender_target_system
                   AND bt.position = br.defender_target_position
WHERE br.defender_units IS NOT NULL AND bt.military_score IS NOT NULL;
```

**E. 飞行模型（第 2、3 条）**

对比 `attack_dispatches.flight_seconds` 与
`2 + 26.5165 × sqrt(D)`，其中 `D = 跨银河 ? 20000×银河环距 : 1162 + 31.71×恒星系环距`。
**环形距离**：银河 9 个成环，恒星系 499 个成环，绕近的那边算。

**F. 单位是否衰减（第 8 条）**

```sql
SELECT defender_target_galaxy, defender_target_system, defender_target_position,
       array_agg(defender_units ORDER BY reported_at_utc), count(*)
FROM battle_reports WHERE defender_units IS NOT NULL
GROUP BY 1,2,3 HAVING count(*) > 1 ORDER BY 5 DESC;
```

## 四·五、⚠️ 拟合时必须带上「暴露时长」这个变量（用户 2026-08-18 提出）

> 「攻击触发的快照军力时间要记录，因为这期间可能被其他玩家攻击过，导致实际攻击时，
> 已经被严重削弱了。」

**数据已经在记了**（PR #183 快照 `target_military_score` + `target_military_score_at_utc`，
PR #185 补 `target_military_score_estimated`），落地时刻由 `dispatched_at_utc + flight_seconds`
推出，所以**暴露窗口 = 落地时刻 − 读数时刻**，现成可算。

### 首批 15 条快照实测：大头不是飞行，是读数本身就旧

| 目标 | 军力 | 读→派 | 飞行 | 读数到落地 |
|---|---|---|---|---|
| 9:205:14 | 31,940 | 11.2h | 2.1h | **13.3h** |
| 9:231:7 | 22,050 | 11.1h | 0.3h | 11.4h |
| 4:289:10 | 24,020 | 8.5h | 0.3h | 8.8h |
| 9:237:19 | 30,135 | 9.5h | 0.3h | 9.7h |

**「读数到派出」占 84–98%，飞行只占 2–16%。**
所以「跨银河飞得久所以更容易被别人先打」是**二阶效应**；
一阶的是**军力读数在派出那一刻已经旧了 8–11 小时**。

（成因已知：有效期设 3 小时，但「军力截断 500 > 窗口内 193 个」使每轮都触发放宽，窗口不生效。）

### 拟合时怎么用

把「读数到落地的时长」当**协变量**，或者只用暴露窗口短的样本去拟合
「军力 → 材料」——否则拟出来的曲线里混着「被别人削弱了多少」，而那与军力本身无关。

### 「被别人打过」有一个现成的检测手段

`defender_units` 是目标在**开打那一刻**的强度，而它已被确认是 bot 的**固定属性**
（打光 100% 之后 0.3 小时再看仍是同一个数，见第一节第 8 条）。

⇒ **同一个目标这次的 `defender_units` 明显低于它的历史值，就是「被别人先打过」的证据。**

库里已有 107 个目标的历史单位数，这个判据**现在就能算**，不需要新增记录。
它同时能填上第一节里一直空着的「打空」那一格——之前判断「连自变量都没在记录」，
是因为只想到了「被拦下」事件（`system_log` 里 311 条纯文本、没落库），漏了这一条。

## 五、攒够之后要做的决策

1. **选靶依据换不换**（军力 → 守方单位）。今天的回测说同样 33 发能多拿 51% 稀有材料、
   还少花 13% 线小时，但那建立在第 7 条的 5 个样本上。
2. **要不要探索/利用两段**：只有 105 个目标有已知单位数，而一天能打 89–118 发，
   几乎打光已知池——光排序不够，得留一部分发数去测未知目标。
3. **`bot 重复攻击间隔` 要不要缩短**：第 8 条若成立（单位不衰减），缩短就是纯收益；
   但现有样本不是现在这批 bot。
4. **`军力截断` 要不要彻底取消**：若第 5、6、7 条都坐实，军力只剩「安全上限」一个用途。

## 六、⚠️ 今天踩过的两个坑，复算时别再踩

1. **别把拟合出来的指数外推出区间。** `单位^1.9` 是在 1,010–3,550 上拟的，
   用到 93,390 上会得出「按单位数选反而差 90%」这种荒谬结论。要么截断在区间内，
   要么先剔离群。
2. **⚠️ 这一条 2026-08-18 当天就被推翻了，保留原文以记录教训。**

   原文写的是：「别用『军力总量』当目标函数——军力和收获不相关」。**那个结论是无效的**：
   我用来论证它的 5 个样本里，军力读数与战报时间相差 **15–25 小时**（唯一一个在 1 小时内的
   是 `4:200:19`），其中最倚重的反例 `4:20:6`（军力 10,560 却拿到最肥的 7,111）**那个军力是
   战报之后 15 小时才读到的**——也就是**打完之后**的军力。
   `r = −0.148` 那 22 组配对是同一个毛病。

   **拿「打完之后的军力」去论证「打之前的军力不预测收获」，这个论证不成立。**

   用户口径（2026-08-18）：「**已知军力和材料产出正相关，但是没有具体数据来拟合相关曲线**」。
   这条来自实际游戏经验，而本仓没有能否定它的数据。

   仍然成立的那一半：**「军力总量」不能当目标函数**——按军力相关的键排序会让军力总量最大化，
   那是**自证的**，证明不了材料产出。目标函数只能是三种稀有材料的产出。

   **能真正检验这件事的数据从 2026-08-18 起才开始积累**：PR #183 让 `attack_intents`
   快照了**派出那一刻**的 `target_military_score` 与读数时刻。攒够之后重跑，就能第一次
   干净地回答「打之前的军力预不预测材料」。
