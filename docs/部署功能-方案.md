## 一、现状：这个功能所在的位置，正是本仓刻意不碰的那一块

行星列表浮层里每颗星球一行，**每行八个图标，四列两排**（实拍
`var/logs/calib-切换星球-基准.png`）：

```
上排 y ≈ 名字行 + 60 ：运输 / 部署 / 传送 / 前往此处
下排 y ≈ 名字行 + 130：转移 / 投送 / 保护 / 扩张
```

`domain/planet_switch.py` 与 `game/pirate_ui.py` 里写着同一条规矩：

> 八个里只有「前往此处」是我们要的，其余七个点错任何一个都是**真实操作**
> （把资源送出去、把舰队部署出去、把星球让出去）。
>
> **只有「前往此处」那一个 x 进代码**（`PLANET_GOTO_COLUMN_X = 1166`）——
> 转移/投送/保护/扩张/运输/部署/传送的 x 一个都不写下来，**不存在就点不错**。

**做部署 = 主动放弃这条安全属性。** 这一点必须在动工前被明确承认，而不是做着做着
才发现。它是本仓迄今为止风险最高的一次改动。

### 已经踩过的相邻教训（两条，都在注释与测试里）

1. **偏移量改大一档不会报错，只会在实机上把星球扩张出去。**
   「前往此处」正下方 70px 坐着「扩张」，`PLANET_ICON_ROW_OFFSET_Y` 是唯一的相对量。
   `tests/unit/game/test_planet_list.py` 单钉了这一条。
2. **纵向拖动的按下点 x=961，往下 60px 就是「部署」。**
   所以按下点的 y 必须跟着当前这一屏识别出来的行走，写死就会按在部署图标上，
   而「按下再拖起来游戏可能当成点击」。

## 二、可以复用的（比想象的多）

| 已有 | 用途 |
|---|---|
| `PLANET_ICON_ROW_OFFSET_Y = 60` | **部署和「前往此处」在同一排**，所以 y 已知，只缺 x |
| `domain/planet_switch.PlanetRow` | 认行、认坐标、给出 `name_row_y`，逐屏回读，一套现成 |

| `game/action_guard.py` | 「点击前重新观察」 |
| `game/overlay.py` 的 ✕ 形态校验（2026-08-18 起） | 关浮层不再盲点 |

**净缺口比看上去小：几何上只缺一个 x。** 真正的缺口在语义和意图，见下。

## 三、第 3 条答案带来的关键推论：**可能根本不用碰那一排图标**

用户说「和攻击一样的流程，只是目标换成了自己的星球」。如果成立，那条路是：

```
导航到自己星球的坐标（SystemNavigator.goto，现成）
  → 开派遣面板
  → 选预设（PresetPicker，现成）
  → _launch(coordinate, "部署")
```

**`_launch` 的形状正好接得上**：它读简报上的任务类型、要求与期望值**精确相等**才点
「出发！」，而任务类型是**游戏根据目标自己定的**，不是我们选的。`MISSION_LABELS`
里已经有「部署」，`snap_mission` 按编辑距离贴回封闭集合且要求唯一命中。

也就是说 **闸门是现成的**：简报上没写「部署」它就不点，还会存现场、点返回。

### 这条路成立的话，第 0 期整个可以取消

不需要量部署图标的 x，**「其余七个图标的坐标本仓根本不存在」这条安全属性原样保住**。

### 但有一步是未知的，实拍图要专门拍它

打 bot 时开派遣面板走的是 bot 面板上的「攻击」按钮（`ATTACK_BUTTON`）。
**站在自己星球的坐标上时，开派遣面板的是哪个按钮？** 三种可能：

- **a)** 自己星球的面板上有个对应按钮 → 走这条，完全不碰图标排
- **b)** 只能从行星列表的「部署」图标进 → 只好碰图标排，回到原方案
- **c)** 两条都行 → 选 a

**实拍图 B 要拍的就是这一屏**：导航到自己星球坐标之后，那颗星球的面板长什么样、
上面有哪些按钮。

## 四·五、真正的难点：手动选舰艇 + 填数量（用户 2026-08-18 指出）

> 「部署的难点在于手动选择舰艇和配置数量，这个需要等实机。」

这推翻了「预设现成、开箱即用」那半句乐观。攻击走预设是**绕开**了舰船格，部署可能绕不开。

### 可能绕开它的一条路：专门建一个部署预设

用户的预设是自己在游戏里维护的（口径 2026-08-09：**只按标题匹配，不读不校验内容**），
而第一期用户要的就是「固定参数」。那么在游戏里建一个部署专用预设（如 `DEP`），
部署就仍然走「选预设 → 简报核对 → 出发」这条现成路径，**完全不碰数量输入框**。

代价是数量固定——但第一期本来就是固定参数。等第 4 期要按军力自动决定数量时再啃手填那条路。

**这条可行的话，第 1 期难度从「新做一套舰船格识别 + 数字输入 + 回读」降到「和攻击几乎一样」。**

### 走不通的话，这是本仓从没做过的一类动作

现有的所有数字输入只有导航栏那三个框（`SystemNavigator._set`：点开 → 等 →
`type_number` → 点 OK → 等）。舰船格是另一回事。

实拍图 C 必须拍清四件事：

1. 舰船格的形态：一格一格点选，还是列表？
2. 数量怎么填：输入框 / 加减按钮 / 滑块 / 「全部」按钮？
3. **填完之后那个数显示在哪** —— 决定回读校验做不做得了
4. 有没有「已选：X 艘」这类汇总

⚠️ **第 3 条最要紧。** 填数字没有回读就等于闭眼开枪，而本仓的硬规矩是「点击前重新
观察」「拿不准就不点」。若数量填完在屏幕上读不回来，第 3 期的三道闸就少一道，
必须另想办法（只用预设 / 只部署固定档位），**不许硬上**。

## 五、语义答案对设计的影响

| 用户的答案 | 对设计的意思 |
|---|---|
| **可逆**（只是舰队转移） | 风险等级**大幅下降**。误部署可以再部署回来，不是 8-18 原方案里假设的不可逆损失 |
| **占航线** | 要和攻击抢那 9 条共享航线，**必须进调度器排队**，不能另起一套 |
| **不返航** | 航线只在**单程飞行期间**被占（待实拍确认）。若是，一次部署的线小时约为一次攻击的**一半** |
| **无二次确认** | 点了「出发！」就生效。所以 `_launch` 那道简报核对是**唯一一道闸**，不许绕过 |

## 六、方案（分期，安全优先）

### 第 1 期：只读探路（等实拍图之后立刻可做）

- 导航到自己星球的坐标，把那一屏整屏读下来并**存进 `system_log` 的 `payload_json`
  带缩略图**（照 `record_overlay_evidence` 的写法）。
- 目的：确定 a) 路线通不通，以及派遣面板要不要填数量。
- **绝不点「出发！」。**

### 第 2 期：干跑

- 全流程走到简报页，`_launch` 的核对**照做**，但确认那一下换成只记日志。
- 复用 `SwitchResult.DRY_RUN` 那个既有形状。

### 第 3 期：真跑，按条件触发

按用户「第一期按条件设置（固定参数 / 时间）」的口径：

- 新增一种任务（形如 `MissionKind.DEPLOY`），配置项 = 出发星球 + 目标星球 + 预设 +
  定时窗口。**定时窗口的机制现成**（`enabled_from_utc` / `enabled_until_utc`）。
- 进调度器正常排队，和攻击共用那 9 条航线与那一只鼠标。
- 三道闸：坐标点前回读、简报核对（现成）、一轮最多一次。

### 第 4 期（留空间，本次不做）

按军力自动决定何时/往哪部署。第 3 期的配置结构要**能被自动填**，别写成只有人填得了的形状。

## 七、该做成配置项的

按仓库口径（取值取决于用户处境 → 运维旋钮；由版面几何决定 → 标定常量）：

| 项 | 归类 |
|---|---|
| 部署的舰船种类与数量 | **运维旋钮**，必须可配 |
| 触发条件（定时 / 阈值） | **运维旋钮** |
| 部署图标的 x、图标排偏移 | **标定常量**，注释写明「这不是偏好项」 |
| 数量回读的重试次数 | **标定常量**（会动的画面上单帧不是证据，次数由这条决定） |
