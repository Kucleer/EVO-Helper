# AI 选靶 一期 —— 需求（2026-08-19）

方案见 [`AI选靶-方案.md`](AI选靶-方案.md)。这一份只写**一期怎么落地**。

用户口径（2026-08-19）：「**先做第一期**」「第一期完成基础框架后，直接评估他的选择」。

---

## 一、一期做什么 / 不做什么

| | |
|---|---|
| **做** | 把局面组成 prompt → 调 LLM → 拿到它选的目标 → 存下来 → 页面上能对比 |
| **做** | 自动核对它有没有守规则、有没有编数字 |
| **不做** | **绝不影响派遣**。派遣照旧走 `assign_by_capacity_and_value` |
| **不做** | 不做 A/B（二期）、不让 AI 改任何配置、不让它决定扫描 |

## 二、⚠️ 两个现状决定了架构，必须先说

### 2.1 `src/` 里此前**没有任何对外网络调用**

全仓搜不到 `httpx` / `requests` 的生产用法。**这会是第一个。** 后果：

- **凭据只能走环境变量**，不能进库、更不能进代码——本仓库是公开的，
  `config.py` 里 `database_url` 那段注释已经把这条口径写死了（「真实连接串只放在
  `.env` 里：本仓库是公开的，凭据不进代码」）。
- 控制台进程从此有了一个**外部依赖**。它挂了、慢了、限流了，都不许影响调度。

### 2.2 ⚠️ 挂载点在**同步的调度器 tick 里**

`_military_assignments`（`application/mission_scheduler.py:2764`）由 `_launch` 调用，
而 `_launch` 在 `tick()` 里同步跑。**一个几秒的 LLM 往返会把整个调度器卡住。**

**一期的解法：发出去就不管（fire-and-forget，另起线程）。**
一期本来就不用 AI 的答案，决策早已做完，这个调用是**纯观测**——不占用关键路径最自然。

⚠️ **但这条路走不到二期。** 二期要按 AI 的结果派遣，它就必须回到关键路径上，
派遣得等它。**这是一次真实的架构分叉，不是实现细节**：一期的异步骨架到二期要重写，
而且届时的失败模式（超时了到底派不派）需要单独设计。**现在就把它写下来，
免得二期时以为「一期已经打通了」。**

## 四、输入：prompt 里给什么

五大块，逐条见方案 [`AI选靶-方案.md`](AI选靶-方案.md) 第二节。这里只补实现口径：

### 4.1 航线预算（★ 用户特别要求）

直接给**可派发数**，并给出减法过程，不让它自己算。⚠️ **「时长未知」那几条要单独标**
——它们是按兜底 90 分钟（`report_wait.UNKNOWN_LINE_HOLD`，可配置）占着的，
实际可能早回来了。不标出来 AI 会把猜测当事实。

⚠️ **占用判据必须复用 `repository._still_holding_a_line`**，不许另算。

### 4.2 候选池的裁剪

⚠️ **不许按现有得分排序后取前 N**——那是把要验证的那条公式的答案泄露给它。

- **摘要**：`银河 × 往返档 × 军力档` 三维交叉表，每格给个数 / 军力中位 / 龄中位。
  往返档按每个出发点各算一份。
- **样本**：每个非空格子取「军力最高 3 个」+「读数最新 3 个」，去重。
  ⚠️ 这两个键都不是要验证的那条公式。
- **prompt 里写明「这是分层抽样，不是全池」**，并给出每格真实总数。

样本总量做成旋钮（见第七节），默认取到约 60 个。

### 4.3 已知规律要标证据强度

给 AI 的收益公式**就是方案 2.5 那一个**：

```
稀有三样 ≈ 0.141 × 军力 × exp(−0.068 × 快照龄小时)     n=74, R²=0.781
```

⚠️ **不要用旧文档里的 −0.115** —— 那是幂律（指数 0.79）里的衰减；线性把指数钉死为
1.0，曲率全压到衰减项上，所以是 **−0.068**（每小时 6.6%）。两个数混用会算错。

⚠️ **基础三样（金属/晶体/气体）绝不能进模型**：实测它由我方货舱容量决定，
不由目标决定（方案 2.5 末尾有数据）。

见方案 2.7。⚠️ **周内相位那几条是零数据支撑的领域直觉**，不标出来 AI 会当事实用。

### 4.4 ⚠️ 不给的东西

- **五个旋钮的当前值一律不给**（`score_max_age_hours`、`top_n`、`bot_revisit_hours`、
  `max_score`、档位表）——AI 的定位就是替代它们。
- **单位数量不给**（我方与敌方都不给），用户口径。
- **账号名、玩家名不给。** ⚠️ prompt 模板会进 git，**模板里不许出现任何真实坐标当例子**。

## 五、输出：格式与自动核对

```json
{
  "picks": [
    {"target": "3:98:12", "origin": "4:277:15", "preset": "BBB", "rank": 1,
     "military": 31820, "reading_age_hours": 0.3, "round_trip_minutes": 125,
     "reason": "……"}
  ],
  "pool_warnings": [
    {"severity": "high", "finding": "……", "suggested_check": "……"}
  ],
  "confidence": "high|medium|low",
  "notes": "……"
}
```

### 5.1 ★ 为什么强制它把 `military` / `reading_age_hours` / `round_trip_minutes` 报回来

**为了让「编数字」变成可自动检出的。** 只让它写自由文本的 `reason`，
「军力 31,820」是真是假只能人眼比对；把三个数做成结构化字段，我们拿自己的数据一比
就知道。**编数字是 LLM 最危险的失败模式**，这一条把它从「靠人看」变成「靠断言」。

### 5.2 硬校验（不过就整份作废并记日志）

1. `len(picks)` **恰好等于**可派发数——不多不少。
   ⚠️ 「留一条线等下一轮」是错的，理由见方案第三节（情报每小时贬值 10.9%）。
2. `target` / `origin` / `preset` 必须来自输入给过的集合。
3. 同一坐标不许出现两次。
4. 每个 pick 的 origin 分到的发数不许超过该 origin 的预算。
5. JSON 能解析且字段齐全。

### 5.3 软核对（记录，不作废）

1. **数字自洽**：`military` / `reading_age_hours` / `round_trip_minutes` 与我方数据
   的偏差。容差：军力必须精确相等，龄 ±0.1h，往返 ±1 分钟。
2. **规则遵守**：有没有推荐**撞在保护期里**的、**距我方上次攻击不足 8 小时**的。
   ⚠️ 判据用**游戏规则的 8 小时**，不是我们那个 24 小时旋钮。

## 六、存哪：新表 `ai_target_decisions`

| 列 | 说明 |
|---|---|
| `id` | `BigInteger().with_variant(Integer, "sqlite")`，同 `system_log` 的先例 |
| `decided_at_utc` | **产生时刻**，不是入库时刻 |
| `task_id` / `run_id` | 哪个任务、哪一轮（`run_id` 可空，不带 CASCADE，同 `system_log`） |
| `cycle_start_utc` | 本周期起点，便于按周内相位分组 |
| `budget` | 本轮可派发数 |
| `algorithm_picks_json` | 现有算法选中的 |
| `ai_picks_json` | AI 选中的（解析后） |
| `overlap` | 按 target 算的重合数 |
| `prompt_text` / `response_text` | ⚠️ **原样存**。模型换版本答案就变，这是唯一能对账的东西 |
| `model` | 模型名与版本 |
| `prompt_tokens` / `completion_tokens` / `latency_ms` | 成本与延迟 |
| `status` | `ok` / `timeout` / `http_error` / `invalid_json` / `schema_violation` |
| `violations_json` | 硬校验与软核对的结果 |

**量级**：约 26 轮/天 × 7 KB ≈ 180 KB/天 ≈ **66 MB/年**。给一个保留天数旋钮
（默认 90 天），口径同 `system_log_retention_days`。

⚠️ **迁移合进 `main` 就完事，开发一侧一次都不许跑 `alembic upgrade`**——
用户重启 bat，生产自己升。

## 七、配置

**运维旋钮**（进 `military_attack_config`，那张表就是「攻击配置页上的全局值」）：

| 旋钮 | 默认 | 调它的代价 |
|---|---|---|
| `ai_shadow_enabled` | **false** | 同 `AUTO_ENABLED` 的惯例，默认关 |
| `ai_model` | 待定 | 换模型答案就变，历史记录里存了 model 才对得上账 |
| `ai_timeout_seconds` | 30 | 调小省钱但丢样本；调大占线程 |
| `ai_sample_size` | 60 | 调大它看得更全、更贵；调小可能把好目标裁掉 |

⚠️ 一律**可空、不给 `server_default`**：NULL = 跟着代码默认走。
理由见 `military_attack_config.blind_scrolls` 的注释（给了默认值就分不开
「没配」和「恰好配成当前默认」）。

**凭据**（只走环境变量，`Settings` 加一项，`EVO_HELPER_` 前缀）：`ai_api_key`。
⚠️ **不进库、不进代码、不进日志**。记 `prompt_text` 时要确认它不在里面。

## 八、安全边界

1. ★ **一期绝不影响派遣。** 用例钉死：**注入一个返回垃圾（乱码 / 超时 / 合法但
   完全不同的选择）的假 LLM，断言 `_military_assignments` 的返回值逐字不变。**
2. **任何失败都静默降级**：超时、限流、连不上、JSON 坏、校验不过 → 记一条日志，
   照常派遣。⚠️ **绝不能因为 LLM 挂了让攻击停摆。**
3. **不占关键路径**：另起线程，主 tick 不等它（见 2.2）。
   ⚠️ 线程要有上限，不许每 tick 堆一个。
4. **限流**：一轮最多一次。⚠️ `_facts` 每 tick 都走（页面轮询也会走），
   **绝不能挂在那条路径上**——只在真的要派遣时调。
5. **开关关掉时零开销**：不建线程、不组 prompt、不查库。

## 九、页面

诊断页加一块「AI 选靶（影子）」，**一期只要能看**：

- 最近 N 轮：时刻 / 预算 / 重合数 / status / 延迟 / token
- 展开看：算法选了谁、AI 选了谁（并排）、校验与核对结果、prompt 与返回原文
- 顶部四个数：JSON 通过率、硬校验通过率、数字自洽率、平均重合率

⚠️ **重合率要标注「这不是好坏的判据」**——它只能用来发现「AI 压根没在按规则做事」。
不写这句，页面上一个百分比摆在那里，早晚被当成分数看。

## 十、验收标准

| 项 | 门槛 |
|---|---|
| ★ 派遣结果不受影响 | **逐字不变**，用例钉死 |
| LLM 挂掉时调度继续 | 用例钉死（超时 / 异常 / 坏 JSON 三种） |
| JSON 校验通过率 | ≥ 99% |
| 硬校验通过率 | ≥ 99% |
| 数字自洽率 | ≥ 95% |
| `pool_warnings` 人工复核命中率 | ≥ 50%，且**至少喊对过一次我们没发现的问题** |

后四项要**跑满两个完整周期（两周）**才算数——周内相位是最可能出错的地方，
而一周只产出一个 D1。

## ★ 十一、下周一之前必须动手：现在一条历史都没在攒

用户口径（2026-08-19）：「**快照时间的话，周一的数据最为重要**，但是这一轮没沉淀数据，
之后也需要将这些记录，并且给到 AI。这是下周的安排。」「周一还没有记录资源和快照军力，
所以得等到下周一才有全面的数据。」

### 11.1 ⚠️ 现状比「没沉淀」更糟：不改的话下周一同样留不下

| | `military_ranking_*`（快照表） | `bot_targets`（实时表） |
|---|---|---|
| 谁写 | **只有 `POST /api/military-rankings/snapshots`，全仓没有任何代码调它** | `ranking_scan` 每读一屏就写 |
| 写法 | 追加 | **按坐标覆盖** |

库里唯一那份快照是 **2026-08-16** 的，而且是迁移 `fa1c3d4e5f67` 从 `bot_targets`
**播种**出来的，不是采到的（来龙去脉写在 `storage/military_rankings.py` 的模块头）。

**⇒ 军力读数一直在采，但一条历史都没留下。** `bot_targets` 覆盖写，同一坐标只有最新值。

⚠️ **所以「等下周一就有数据」这个前提本身不成立。** 下周一采到的东西会被当天后面的
扫描覆盖掉，什么都不做就是**再空一个周期**——而一周只产出一个周一。

### 11.2 周一为什么特别重要

1. **刷新那一刻的军力基线** —— 本周期所有目标的「满血值」。有了它，任何时刻的读数
   才算得出「这个 bot 已经被打掉了多少」；现在只看得到读数本身，看不出离满血差多远。
2. **衰减系数在真实跨度上的标定** —— 现有的 −0.068 来自龄中位 1.27h 的样本。
   刷新当天龄跨度最大、竞争最激烈，是这个系数最该被检验的一天。
3. **[`周内相位-策略模型.md`](周内相位-策略模型.md) 那六条预测** ——
   全部按「周内第几天」分组，⚠️ 目前**零数据支撑**。

### 11.3 要落什么

**最小可行**：让 `ranking_scan` 每趟采完**追加一份快照**，而不只是覆盖 `bot_targets`。
接口现成（`repository.append_snapshot`），缺的只是调用方。

⚠️ **量级先算**：一趟约 1,700 行、一天多趟。三种口径评估过：
A 全量 383 MB/年、B 只写变化量 46 MB/年、C 聚合 0.3 MB/年。
**建议 B** —— bot 军力一周内不动，绝大多数行是重复的；B 既留住「什么时候变的」
又不至于爆表。

### 11.4 ⚠️ 时间点

**「用」是下周的安排，「记」必须赶在下周一（2026-08-24 UTC+0 刷新）之前落地。**
晚一天就少一个周期，而这个周期要等到 08-31 才补得回来。

## 十二、一期不做、但要记下来的

- **反事实观察不到**：AI 选 A、我们打 B，A 的收益永远不知道。
  一期结构上**无法证明「AI 选得更好」**。要比高下必须二期 A/B（方案第五节，
  含混杂与功效的计算）。
- **异步骨架到二期要重写**（见 2.2）。
- **分层抽样可能裁掉它想要的**——它看不到样本之外的个体。二期可做成两轮
  （先让它挑格子，再给那一格的全部）。
- **可复盘性会变差**：本仓的惯例是「判据只能有一份、出事能只靠库里日志定位」，
  而 LLM 输出天然带随机性。**这是接入它的真实代价。**
