# 部署到挂机机器

两台机器分工：

| | 工作机 | 个人机（挂机） |
|---|---|---|
| 角色 | 开发、调试、看数据 | 24 小时跑实机 |
| 有什么 | AI 工具、开发环境 | 常开、能一直登录着 |
| 谁在这上面动鼠标 | 你 | **助手的 runner** |

⚠️ **任何时刻只许一台机器跑自动化。** 只有一个游戏账号，海盗每天 32 次是账号级硬限制；
两台同时跑不是「数据冲突」，是真的超额、舰队被强制返回。没有技术手段挡着，靠约定。

**库只有一个**：PostgreSQL 装在个人机上，两台机器都连它（2026-08-16 从 SQLite 切过来）。
所以工作机看到的就是实时数据，不用同步任何文件。**单写多读**——写的永远是正在跑自动化
的那一台，见上一条。

⚠️ `var\` 下的东西**不在库里**：现场图（`var\logs\dump-*.png`）、配置固化记录
（`var\mission-config-freezes.jsonl`）都是文件，只在产生它的那台机器上。

## 一、个人机：装环境

### 1.1 装底子

需要：Git、Python 3.12、[uv](https://docs.astral.sh/uv/)、Chrome、
[Tesseract-OCR](https://github.com/UB-Mannheim/tesseract/wiki)（装的时候**勾上中文简体
`chi_sim`**，不勾的话所有中文都读不出来）、
[PostgreSQL](https://www.postgresql.org/download/windows/)（库放在这台常开的机器上，
见 1.4）。

### 1.2 拉代码、装依赖

```
git clone https://github.com/Kucleer/EVO-Helper.git D:\eternal-void
cd /d D:\eternal-void
uv sync --extra vision --extra live --extra db --extra dev
```

`uv.lock` 在版本管理里，所以装出来的版本和工作机一致。

- `vision` = 截屏与 OCR（mss / opencv / pillow / pytesseract）
- `live` = 真点鼠标（pyautogui / pywin32）
- `db` = PostgreSQL 驱动（psycopg）
- `dev` = pytest / ruff / mypy，第七节那份自检要用

⚠️ **四组一个都不能少，而且以后每次 `uv sync` 都要把它们带齐。** `uv sync` 会把
**不在参数里的组卸掉**（`--dry-run` 可以先看它打算删什么）：

| 漏了哪组 | 症状 |
|---|---|
| `live` | 控制台起不来（`No module named ...`），不是「缺个包」这种一眼能认的报错 |
| `db` | 连不上库，或者更坏——**静默回落到空的 SQLite** |
| `vision` | 截屏 / OCR 整条链路瘫掉 |
| `dev` | `pytest` 直接没了，自检第 3 步跑不了 |

（2026-08-16 之前 psycopg 只是手动装在 venv 里、没进 `uv.lock`，就是这个坑：
库连得上，但下一次 `uv sync` 会把驱动卸掉。）

⚠️ **别加 `--extra yolo`**。它拖 torch 几百 MB，而实机链路一次都不碰它。

### 1.3 写 `.env`

在 `D:\eternal-void\.env`（这个文件不进 git）：

```
EVO_HELPER_TESSERACT_PATH=C:\Program Files\Tesseract-OCR\tesseract.exe
EVO_HELPER_CHROME_PATH=C:\Program Files\Google\Chrome\Application\chrome.exe
EVO_HELPER_WEB_TOKEN=这里换成一串你自己的随机字符
EVO_HELPER_DATABASE_URL=postgresql+psycopg://用户:密码@127.0.0.1:5432/库名
```

- **`EVO_HELPER_DATABASE_URL`**：本机跑的 Postgres 写 `127.0.0.1`。不写这一行会
  **静默回落到 `sqlite:///var/evo-helper.db`**——控制台照样起得来、页面照样能开，
  只是里面空空如也，而你要过一会儿才会反应过来它在读另一个库。工作机那份 `.env`
  写的是同一个库的 Tailscale 地址（`100.x.y.z:5432`）。
- **Tesseract / Chrome 路径**：装在别处就改这两行。Chrome 留空会按候选列表找，
  但**显式指定时找不到就报错、不回落**——这是有意的：回落的话你以为跑的是自己指定的那个
  （比如带着已登录 profile 的），实际跑的是另一个。
- **`EVO_HELPER_WEB_TOKEN`**：跨机器调接口要带的票。不设的话只有同源请求能写，
  工作机就指挥不动它。生成一串：

  ```
  powershell -Command "[guid]::NewGuid().ToString('N')"
  ```

- 还有一处**可能**要改：页面缩放率（`EVO_HELPER_DEVICE_SCALE_FACTOR`）。见第五节。

### 1.4 建库

装完 PostgreSQL 之后，先建库和用户（`psql -U postgres`）：

```
CREATE DATABASE evo;
CREATE USER evo WITH PASSWORD '一串你自己的';
GRANT ALL PRIVILEGES ON DATABASE evo TO evo;
```

⚠️ **让它只监听回环和 Tailscale 那块网卡**（`postgresql.conf` 的 `listen_addresses`、
`pg_hba.conf` 的来源网段）。别开成 `0.0.0.0` 再靠路由器挡——这个库里是账号的全部数据。

然后把结构建出来：

```
cd /d D:\eternal-void
.venv\Scripts\python.exe -m alembic upgrade head
```

（`.env` 里的 `EVO_HELPER_DATABASE_URL` 决定它建到哪个库；`alembic.ini` 里那个
`sqlalchemy.url` 只是没配环境变量时的兜底。）

从**空库**跑全套迁移。⚠️ **不要**把工作机的 `var\evo-helper.db` 拷过去当起点——
库结构跟着代码走，跨机器拷文件迟早对不上 `alembic_version`。

要把历史数据搬过来，用 `tools/migrate_sqlite_to_pg.py`（只读源库、只写目标库，
带 `--verify-only` 可先逐表比行数），详见 `docs/postgres-migration.md`。

## 二、个人机：登录游戏、校窗口

### 2.1 起一次，手动登录

```
cd /d D:\eternal-void
start-console.bat
```

浏览器开 `http://localhost:8770`，控制台应当能打开。同时会弹出一个 Chrome `--app` 窗口
（就是游戏）。**在那个窗口里手动登录游戏**，登录状态存在专用 profile 里，以后自动重连用得上。

### 2.2 确认窗口几何

所有点击坐标和 OCR 的取字框，编码的都是 **client 1920×917** 这个版面。核一下：

```
.venv\Scripts\python.exe -c "import ctypes; ctypes.windll.shcore.SetProcessDpiAwareness(2); from evo_helper.game.game_window import ensure_game_window; print(ensure_game_window())"
```

期望输出 `rect=(0, 0, 1938, 926)`（外框，含 38px 标题栏）。

⚠️ **那句 `SetProcessDpiAwareness(2)` 不能省。** 少了它，读到的是逻辑像素
（125% 缩放下 1938 会读成 1550），而 `ensure_game_window()` 会照着这个错值去 resize，
**把一个本来正常的窗口改坏**。四个 runner 的 `main()` 里都有这一句，写临时脚本时最容易忘。

如果收敛不到 1920×917，多半是屏幕分辨率或缩放率不同——见第五节。

## 三、个人机：开机自启

⚠️ **不要用 SSH 或计划任务的「不管用户是否登录都运行」来起它。**
那两种方式跑在独立的 session 里，看不见交互式桌面；而这个项目要真的点鼠标、抢窗口前台，
在那种 session 里会直接倒在「游戏窗口抢不到前台」上。

正确做法是**登录时在用户自己的桌面会话里起**：

### 3.1 开机自动登录

`Win+R` → `netplwiz` → 取消勾选「要使用本计算机，用户必须输入用户名和密码」→ 填密码。

⚠️ 这台机器从此开机即进桌面，**物理接触到它的人不需要密码**。挂机机器放在你自己家里
才这么做；放在别处就别开，改成开机后你手动登录一次。

### 3.2 登录时自启

`Win+R` → `shell:startup` → 在打开的文件夹里建一个快捷方式，指向：

```
D:\eternal-void\start-console.bat
```

重启一次验证：登录进桌面后，控制台和游戏窗口应当都自己起来。

## 四、工作机：连过去

### 4.1 组网

两台都装 [Tailscale](https://tailscale.com/)，登同一个账号。之后个人机会有一个固定的
`100.x.y.z` 地址（或 MagicDNS 名字）。

⚠️ **不要用端口转发把 8770 暴露到公网。** 控制台读页面不验票（这是明确的设计取舍），
公网上等于把你的账号数据摆出去。Tailscale 是私有网络，只有你自己的设备连得上。

### 4.2 验证连通

工作机上：

```
curl http://100.x.y.z:8770/api/scheduler
```

能返回 JSON 就通了。

### 4.3 从工作机起停任务

读接口直接打。**写接口要带 token**：

```
curl -X POST http://100.x.y.z:8770/api/scheduler/start ^
     -H "x-evo-helper-token: 你在 .env 里设的那串"
```

常用的几个：

| 接口 | 方法 | 作用 |
|---|---|---|
| `/api/scheduler` | GET | 查调度器与全部任务的状态 |
| `/api/scheduler/start` | POST | 启动 |
| `/api/scheduler/stop` | POST | 结束 |
| `/api/missions` | POST | 新建任务（目前只收 `BOT`） |
| `/api/missions/{task_id}` | PATCH | 改任务配置 |
| `/api/missions/{task_id}` | DELETE | 删任务（每条链路至少留一行） |
| `/api/missions/{task_id}/new-round` | POST | bot「重开一轮」 |
| `/api/backfill` | GET | 查战报补录（状态、日志尾巴、摘要） |
| `/api/backfill` | POST | 排一趟补录 `{"kind":"pirate\|bot","since":"YYYY-MM-DD"}`，回 202 |
| `/api/backfill/cancel` | POST | 排队中撤掉 / 跑着杀掉，之后立刻放行任务 |
| `/api/backfill/resume` | POST | 「继续任务」：看过摘要，放行 |

⚠️ **任务按 `task_id` 寻址，不是按 `PIRATE`/`BOT`/`SCAN`。** bot 攻击可以有多个任务
（各带各的出发星球与航线数），按类型寻址会打到不确定的那一行上。`task_id` 从
`GET /api/scheduler` 的 `tasks[].task_id` 取。

浏览器直接开 `http://100.x.y.z:8770` 也一样能用——页面上的操作走的是同一组接口。

⚠️ **调度器运行中不能改任务配置**（返回 409）。要改先点「结束」。这是刻意的：
上一轮拿着旧参数在跑，中途换参数意味着一轮之内两套口径，事后从日志分不清用的哪一套。

⚠️ **`/api/scheduler/start` 默认会先跑一趟战报对账**（海盗、bot 各一趟），读完信箱里
应读未读的战报才放行任务。不带请求体就是这个默认；要跳过得显式送
`{"reconcile": false}`。补录期间**一个任务都不起**，跑完还要 `POST /api/backfill/resume`
才放行——补录改的正是任务读来做决策的那批数据（战报在不在库里决定 bot 目标要不要
再打一遍、海盗还剩几次配额），抢在它前面跑就会白打一遍。没有欠账时那一趟几十秒
走完（信箱单子一空就早停）。

⚠️ **补录正在跑或正在排队时不能启动调度器**（同样 409）：一个游戏窗口，一只鼠标。

## 五、换机器时最可能出问题的四处

### 5.1 分辨率与缩放

坐标编码的是 **client 1920×917**。这要求物理分辨率至少 1920×1080。

缩放率不必是 100%——`launch_game()` 会用 `--force-device-scale-factor` 把页面 DPR 钉死，
所以 125% 的机器上也能得到同样的版面。但**钉的那个值要对**：

```
EVO_HELPER_DEVICE_SCALE_FACTOR=1.25
```

⚠️ 变量名就是这个（`Settings.device_scale_factor` 加 `EVO_HELPER_` 前缀）。写成
`EVO_HELPER_DPR` 之类**不会报错**，只是被 `extra="ignore"` 静静丢掉，然后你以为自己
配过了。

它同时是**标定常量**：取值必须等于 `game_window.CALIBRATED_SCALE_FACTOR`（当前 1.25），
填别的会被 `verified_scale_factor()` 当场拦下。也就是说，如果这台机器的系统缩放率不是
125%，不是改这个数，而是把系统缩放调成 125%——否则整套坐标和 ROI 都要重新实测。

### 5.2 Tesseract 没装中文

读中文的地方（面板标题、弹窗、预设名、邮件主题）会全部读成噪声。
装的时候勾 `chi_sim`，或者事后用安装器补装。

### 5.3 游戏没登录 / 掉线

第一次一定要手动登录一次。之后掉线有自愈：认出「连接已断开」会点掉弹窗重连；
认出「连接已断开，**无法重新连接**」会关窗重开 Chrome（上限 3 次 / 滚动 1 小时）。

### 5.4 库连不上 / 连错库

三种症状分别对应三件事，都不难认，但错认了会绕远路：

| 症状 | 原因 | 怎么办 |
|---|---|---|
| `ModuleNotFoundError: psycopg` | 装依赖时漏了 `--extra db`，或者被后来一次不带它的 `uv sync` 卸掉了 | 重新 `uv sync --extra vision --extra live --extra db` |
| `connection refused` / 超时 | Postgres 没起、没监听那块网卡，或 `pg_hba.conf` 不放行来源网段 | 先在库那台机器上 `psql` 连本地确认服务本身没问题，再查监听与 `pg_hba` |
| 页面能开、数据是空的 | `.env` 没写 `EVO_HELPER_DATABASE_URL`，**静默用了默认的 SQLite** | 补上那一行 |

第三种最坑：它不报错。要当场确认在读哪个库：

```
.venv\Scripts\python.exe -c "from evo_helper.config import Settings; print(Settings().database_url)"
```

## 六、日常怎么用

| 想干什么 | 谁做 | 怎么做 |
|---|---|---|
| 改代码 | 工作机 | 开发、推 GitHub |
| 部署新代码 | **你手动** | 个人机 `git pull` → `uv sync --extra vision --extra live --extra db --extra dev` → `alembic upgrade head` → 重启 `start-console.bat` |
| 起停任务、改配置 | 工作机（或助手） | 打接口，见 4.3 |
| 看数据 | 工作机 | 浏览器开 `http://100.x.y.z:8770` |
| 排障（要看画面） | **只能在个人机上** | 见下 |

### 为什么部署不做成自动

自动 `git pull` + 自动重启，等于让一次**没实机验证过**的提交自动部署到一台
无人看管、正在真点鼠标的机器上。这个项目的历史里，「合并了但没实机跑过」的东西
咬过不止一次。手动那一步的成本是几秒钟，换来的是一个明确的确认点。

### 排障的边界

助手在工作机上**能读个人机的库、能起停它的任务，但看不见它的画面**。
而这个项目里绝大多数真 bug——按钮点在空白处、预设条拖不到、战报要拖一屏才读得到——
都是靠看截图查出来的。

所以画面级的排障只有两条路：你在个人机前面看，或者在个人机上也跑一个助手。
`var\logs\` 下的现场图（`dump-*.png`）是折中：出问题时 runner 会自己存图，
把它们同步回工作机就能事后看。

## 七、装完自检

按顺序过一遍，全过才算装好：

1. `uv sync --extra vision --extra live --extra db --extra dev` 无报错
2. `.venv\Scripts\python.exe -c "import psycopg, pyautogui, cv2, mss"` 不报错
   （四组 extra 真的都在；`uv sync` 漏组的症状不长这样，得单独确认一次）
3. `.venv\Scripts\python.exe -m pytest tests -q` 全绿
4. `.venv\Scripts\python.exe -c "from evo_helper.config import Settings; print(Settings().database_url)"`
   打印的是**你配的那个 Postgres**，不是 `sqlite:///var/evo-helper.db`
5. `alembic upgrade head` 跑完，`select version_num from alembic_version` 与工作机一致
6. `start-console.bat` 起得来，`http://localhost:8770` 能打开，**页面上有数据**
   （空页面就是第 4 步没过）
7. 游戏窗口 `ensure_game_window()` 收敛到 `(0, 0, 1938, 926)`
8. 游戏已手动登录，能看到自己的星球
9. 重启机器，登录后控制台与游戏窗口**自动**起来
10. 工作机上 `curl http://100.x.y.z:8770/api/scheduler` 返回 JSON
11. 工作机带 token 打一次 `/api/scheduler/stop`，返回 `running: false`
12. **只读实机验一轮**：个人机上跑
    `.venv\Scripts\python.exe -m evo_helper.tools.pirate_loop --systems 2:137`
    （不带 `--scout --attack`，一发都不派），确认它能开工读战报、认出海盗、正常收尾

第 12 步过了，再放开真派遣。

## 附：紧急停止

- **鼠标甩到屏幕左上角**——`pyautogui.FAILSAFE`，任何时候都能立刻掐断正在进行的点击。
  这是最后一道保险，**不要关掉它**。
- 控制台点「结束」，或打 `/api/scheduler/stop`。**远程也能打**，这是挂机机器
  前台被游戏窗口占着时的主路。

> 桌面悬浮窗上那个 `Ctrl+Alt+F9` 全局快捷键 **2026-08-17 随悬浮窗一起删了**
> （用户口径：控制台能远程控制了）。急停从三条变两条，剩下的两条都还在：
> 本机甩鼠标、远程点「结束」。
