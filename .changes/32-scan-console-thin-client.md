桌面悬浮窗 `tools/scan_console.py` 从「进程启动器」降级为「调度器的瘦客户端」。
设计规格第十一节。

## 为什么

它是全仓**唯一**真正起 runner 的第二处。调度器一上线，就会有两个互不知情的东西
抢同一个鼠标：调度器以为只有自己在派舰队，而 Alt+F8 还能另开一轮扫描。第八节的
安全不变量 1「任何时刻最多一个子进程在点鼠标」（一个游戏窗口，一个鼠标）靠约定
守不住，只能靠取消第二个启动器。所以这条排在页面（Task 11）之前做——在悬浮窗还能
自己起进程的那段时间里，不该给用户任何能启动调度器的入口。

## 改了什么

- **`ScanSupervisor` 与 `launch_scan()` 整个删掉。** 起进程那份职责已经在
  `application/mission_supervisor.MissionSupervisor` 那边。现在这个模块里
  `Popen` / `subprocess` / `spawn` 一个字都不出现，并有一条测试盯着这件事——
  查的是**能力**而不是某条分支的行为，因为「连不上就自己跑一轮扫描」正是最容易被
  当成贴心降级重新写回来的那一种。
- **显示当前任务。** 轮询 `GET /api/scheduler`：跑着任务显示链路名 + **这条链路**
  已跑多久（不是调度器的总时长——「现在这一轮跑了几分钟」才是判断该不该去看一眼的
  那个数）；调度器在跑但空闲显示「待命」+ 它自己的运行时长；已停止显示「已停止」。
  链路中文名由服务端下发（`web/display.py` 的 `MISSION_LABELS`），悬浮窗不自己拼。
- **快捷键控制整个调度器**：Alt+F8 → `POST /api/scheduler/start`，
  Alt+F9 → `POST /api/scheduler/stop`。等同网页上的开始/结束。
- **右键仍然只停不启**，理由不变（做成切换的话，在状态刚变过的那一瞬右键会变成
  又起一轮——实机上撞见过）。它现在停的是整个调度器。
- **连不上显示「未连接」，什么都不做。** 不自己拉起 Web 服务，更不退回「自己跑扫描」
  的旧行为——调度器可能其实正在跑、只是一时接不上，那时自己再起一个进程正是要防的
  双主人。快捷键按下去只在第三行提示「服务未启动」。
- **一次问不到不算断线**（`OFFLINE_AFTER_MISSES=3`）。调度器抢占扫描那一下会
  `terminate()` 之后再 `wait(5)`，那几秒里状态问不出来，而它其实正在好好地派舰队；
  立刻翻脸说「未连接」会让用户去重启一台没坏的服务。
- **403 与「服务没起」分开提示**（「令牌不符」/「服务未启动」）：提示同一句话的话，
  用户会去重启一台活得好好的服务，而真正该做的是对一下 `EVO_HELPER_WEB_TOKEN`。
- **HTTP 在后台线程里做**（`SchedulerPoller`），跟 `HotkeyListener` 另起线程同一个
  理由：tkinter 主循环只泵自己的事。服务忙那几秒若同步等在界面线程里，状态窗会连拖
  都拖不动。
- **双击退出不再顺带停调度器**。旧版本里两者绑在一起是因为窗口一关子进程就没人管；
  现在进程归调度器管，关掉状态窗只是不看了，任务该跑还跑。要停按 Alt+F9 或右键。

保留不动（都是实机踩坑换来的）：置顶且**不抢焦点**（抢了焦点，runner 下一次点击就会
打到它身上）、无边框、左键拖动、快捷键**逐个注册逐个报告**（实机上 Alt+F9 被 NVIDIA
Overlay 占过，一个键被占不该让整个控制台起不来）、`SetProcessDpiAwareness(2)`、
贴**工作区**右下角而不是屏幕右下角（贴屏幕底会被任务栏压住）。

## 令牌

- 配置：写请求要么同源、要么带 `X-Evo-Helper-Token`。悬浮窗是本机进程、不是浏览器，
  **没有 Origin 可言**，只能走令牌。原先散在 `web/app.py` 里的 `_default_token()`
  提成 `web/security.default_local_token()`，服务端与悬浮窗**调同一个函数**——
  各写一份 `os.environ.get(..., "…")`，哪天默认值改了就是一边 403、另一边看着服务
  活得好好的。刻意仍只读 `os.environ` 而不走 `Settings`（`Settings` 会顺带读 `.env`，
  改成读 `.env` 会让已经在跑的部署换一个令牌）。
- 地址从 `config.Settings` 读，端口不写死；`host` 是 `0.0.0.0` 这类通配值时连回环——
  那是「监听所有网卡」，不是一个能连的地址。
- HTTP 用标准库 `urllib` 而不是 `requests`：后者在本仓是可选依赖，而「缺依赖」与
  「服务没起」在这个 200×92 的小窗上都长成「未连接」，用户只会去重启一台好服务。

- 数据库：无。
- 验证：`pytest`（889 passed / 8 skipped，较基线 872 +17：删掉 10 条 `ScanSupervisor`
  的用例——那套 `FakeProcess` + 可注入 `Clock` 的写法已被 `MissionSupervisor` 自己的
  测试继承——另加 27 条）、`ruff check`、`mypy`（90 源文件零问题）。
  两处做了变异验证（改坏 → 确认变红 → 还原）：**断连时退回自己起进程**（红 2：
  能力检查 + 断连只提示）、**右键改成切换**（红 1）。
- 安全：本模块改造后**没有任何创建子进程的能力**，`grep -n "Popen\|subprocess\|spawn"`
  零命中，并由测试守着。不抢焦点这条不动。`pyautogui.FAILSAFE` 本模块不碰。
- 回滚：`git revert` 本次提交即回到自带 `ScanSupervisor` 的旧版——但那样会重新出现
  第二个启动器，回滚前先确认调度器没在跑。
