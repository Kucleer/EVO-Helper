扫描的常驻控制台：全局快捷键启停 + 屏幕右下角的状态窗（状态 + 持续工作时间）。

```bash
.venv/Scripts/python.exe -m evo_helper.tools.scan_console
.venv/Scripts/python.exe -m evo_helper.tools.scan_console --stop-key ctrl+alt+f9
```

- `Alt+F8` 开始、`Alt+F9` 结束（`--start-key` / `--stop-key` 可换）
- 状态窗常驻工作区右下角，三行：状态、持续工作时间 `H:MM:SS`、当前生效的快捷键
- 状态：`已停止` / `扫描中` / `等待重试 Ns· 续N` / `已扫完`，颜色之外还有文字，
  灰度与色盲下同样可读
- 安全停止后自动退避 60 秒续扫；**退出码 0 表示整段计划跑完，不再续扫**
- 右键状态窗=停止、双击=退出、左键拖动

为什么要这个窗：扫描期间游戏窗口一直占着前台，控制台被压在后面看不见，
「它还在不在跑、跑了多久」原本只能靠翻日志猜。

## 设计要点

- **持续工作时间把退避等待算在内**。那时扫描仍然在岗，只是在等机器空出来；
  排除掉会让一段被频繁打断的扫描看起来只干了几分钟活。停止后计时冻结。
- **起停逻辑与界面、Win32 完全分开**（`ScanSupervisor`）。这是唯一有分支的部分，
  摘出来才测得了——有 12 个用例覆盖重复启动、退避续扫、退避中停止、干净收工不续扫。
- **状态窗不抢焦点**：一旦抢了，扫描下一次点击就会打到它身上。

## 实机上撞见并修掉的三件事

- **`Alt+F9` 和 `Alt+F10` 在这台机器上被占用**（`RegisterHotKey` 错误码 1409），
  是 NVIDIA ShadowPlay 的默认录制/即时重播键。第一版实现两个键一起注册、失败就抛错退出——
  用户既用不了另一个能用的键，也不知道是哪个键出的问题。现在逐个注册、逐个报告，
  能用的照常生效，并直接给出可用的替代（实测 `ctrl+alt+f9` 空着）。
- **右键做成「切换」是错的**。实机上本想停，结果在状态刚变过的那一瞬右键，
  变成了又起一轮扫描（日志里两条启动记录只隔 3 秒）。停是安全动作，必须在任何状态下
  都说得准，所以右键改成**只停不启**。
- **`.venv/Scripts/python.exe` 是个 shim**，会再拉一个 uv 缓存里的解释器。
  子进程用 `sys.executable` 而不是写死 venv 路径，才不会多一层进程、也不会丢依赖。

- 配置：无变更
- 数据库：无变更
- 验证：`pytest`（581 passed）、`ruff check`、`ruff format --check`、`mypy src`；
  实机验证 `Alt+F8` 真的拉起扫描（日志出现新一轮运行）、状态窗落在

- 安全：控制台自己不碰游戏，只起停扫描子进程；扫描的只读性质与急停不变
