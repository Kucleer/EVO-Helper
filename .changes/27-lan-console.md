控制台默认绑 `0.0.0.0:8770`，局域网内的手机/平板可以直接打开。

```bash
.venv/Scripts/python.exe -m evo_helper.web.runtime
# 控制台监听 0.0.0.0:8770
#   本机   http://127.0.0.1:8770/
#   局域网 http://192.168.31.156:8770/
#   [警告] 未设访问口令：同网段内任何设备都能读取情报并启停任务
```

- `EVO_HELPER_HOST` 默认从 `127.0.0.1` 改为 `0.0.0.0`
- `EVO_HELPER_PORT` 默认从 `8000` 改为 `8770`，避开常规端口
- 启动横幅打印本机与局域网两个地址，暴露在回环之外时附带警告

## 设计要点

- **`Settings.model_post_init` 里那条「只许监听 127.0.0.1」的硬校验删掉了。**
  它原本是安全不变量，现在被局域网可访问这个明确需求取代。取代它的是
  `Settings.lan_exposed` + 启动横幅上的警告——把「已经暴露出去了」这件事
  说出来，而不是让它不可能发生。要退回本机独占：`EVO_HELPER_HOST=127.0.0.1`。
- **不加访问口令，是用户明确确认过的选择。** 同源校验（`LocalSecurityMiddleware`）
  挡的是跨站请求伪造，不是局域网里的人：局域网设备打开控制台本身就是同源的，
  读写都不受阻。安全边界因此是「这个网段可信」，不是这个中间件。
  公共 Wi-Fi 下不要开。
- **局域网地址用连 UDP 的办法向路由表要**，而不是 `gethostbyname(gethostname())`。
  后者在装了 VPN / WSL / 虚拟机桥接的机器上经常给出一个连不通的地址，
  而这个地址是打印给用户拿手机去输的，给错还不如不给。不发包。
- **横幅里不能有 `⚠`。** 它不在 GBK 里，而这行是打到默认代码页 cp936 的
  Windows 控制台上的，`print` 会抛 `UnicodeEncodeError`——启动横幅把服务本身弄崩。
  实机上撞到了，改用 `[警告]`。
- 安全测试原本把 `dry_run is True` 和 `host == "127.0.0.1"` 写在同一个用例里。
  放开监听时很容易顺手把 dry_run 一起改掉，所以拆成两个用例，
  让「默认不真的点游戏」单独有人守着。

- 配置：`EVO_HELPER_HOST` 默认 `0.0.0.0`、`EVO_HELPER_PORT` 默认 `8770`
- 数据库：无变更
- 验证：`pytest`（651 passed）；实机确认横幅在 cp936 控制台上不报错、
  局域网地址解析为 `192.168.31.156`
- 安全：**读写均无身份认证**，见上；`dry_run` 默认仍为 `True`
- 回滚：`Settings.host` / `port` 改回 `127.0.0.1` / `8000`
