**一次性的逐屏语料采样开关，加离线回放工具。** 同一个 PR 的第二块（第一块见
`278-ranking-phase-zero-observation.md`）。

## 为什么必须有回放

换阀的触发条件之后，历史会不同、后续采信也会不同，**轨迹在第一次被去掉的误重置
之后就分叉了**。所以「换了会怎样」这个问题**观测不出来** —— 影子计数只能给出
「三种条件在**现行**轨迹上的比较」。

真正的对照只有一条路：把同一份**原始输入**喂给新旧两套算法，各自从头重建历史。

## 一次性请求：新表 + 一条原子语句

`ranking_capture_requests`（迁移 `b3e8f1a26d47`）。调度器起子进程前一条语句领走：

    UPDATE ranking_capture_requests
       SET consumed_at_utc = :now, consumed_by_run_id = :run_id
     WHERE consumed_at_utc IS NULL

再看 `rowcount`。形状照 `release_attack_lines` —— **全仓一次 `SELECT ... FOR UPDATE`
都没有**，不发明新写法。

⚠️ **不能放任务参数**：那是可重复使用的，写个布尔进去每趟都会录，而一趟约 1,250 行。
「子进程结束」也不保证下次不再开 —— 它只保证那一个进程没了。

⚠️ **不能绑 `begin_mission_run`**：它在子进程起来**之后**才跑。子进程起不来时请求
被白白消费掉，用户再点一次即可 —— 这个失败方向比「多录一趟」便宜，也没有崩溃窗口。

## 两条通路，在扫描器内部汇成一个变量

- **调度器** → 环境变量。`command` 在 `run_id` 生成**之前**就建好了，而标记必须和
  那一趟的 `run_id` 绑在一起（语料的完整性检查要回答「这批是哪次请求采的」）
- **手工直跑** → `--capture-rows`（本机是备份挂机机，要能不经调度器就开）

默认关。

## 语料里有什么

- 逐屏原始行（名次 / 坐标 / 分数 / 空值）。⚠️ **保留空值** —— 名次读不出、分数读不出、
  坐标反解不出这三种 `None` 正是判据要处理的情形，补个默认值就等于把语料改了
- 落库**之前**那几个坐标的库内状态（有没有值、估算标记、拉黑时刻）。
  ⚠️ 回放要验「已有值」「不可更新（已拉黑）」那几档结果，而它们取决于写之前的样子
- 开工记录带判据指纹与包版本。⚠️ **不用 git sha** —— 运行机上不一定拿得到
- 离页那一屏也补一条记录（`break` 在算日志之前，原先屏序会断）
- 收尾汇总带结束原因与「补数到底跑没跑」

## ⚠️⚠️ 回放工具是采集循环的第二份实现

`scan()` 里那个循环绑着导航、驱动、仓储，没法直接跑离线数据，所以照它的形状重写了
一遍 —— 而「同一件事两份实现，两边迟早分家」是这个仓库反复栽过的坑（#275 那次就是
日志另起一遍重算理由，走到判据到不了的分支，交出一套很像真的假话）。

**唯一的对策是让分家立刻暴露**：`verify()` 比逐屏六个计数**以及重置位置**，
对不上就说明两份已经漂了，此时回放结论一律不可信 —— 先修实现，别急着解释差异。

### 这一条我做错了两次，都是变异验证抓出来的

1. **第一版 `verify` 只比计数、漏了重置位置。** 把真循环的 `screen_seq > 0` 闸改成
   `if True` → 回放用例全部照绿。而重置位置正是 Phase 1a 唯一关心的那个量。
2. **补上位置比对之后还是绿**，因为 `SCENARIO` 的首屏是成功的 —— 那个变异在它上面
   是**行为惰性**的（首屏进不进阀只是把失败计数归零）。于是加了
   `SCENARIO_BLIND_START`（首两屏都读不出值），两边重置位置才不同，变异这才变红。

- Configuration: 无新增配置项。诊断开关是一次性请求（表）+ 命令行参数，默认关。
- Database: **迁移 `b3e8f1a26d47`**，新建 `ranking_capture_requests`。SQLite 与远端
  PostgreSQL 都验过 up / down / up。
- Verification: `pytest -q` 4293 passed / 256 skipped。迁移用例含「第二次领取必须
  什么都领不到」（直接发 SQL，验列语义不验仓储接线）。
- Safety: 判据仍然一条都没动。⚠️ 录语料不可能把扫描搞挂 —— `payload_json` 是 `Text`
  无长度限制，写入路径四层吞异常、在后台线程做、队列满只丢最旧的（已有先例往
  payload 塞 base64 PNG）。
- Rollback: 迁移可回退；开关默认关，不开就完全没有额外行为。
