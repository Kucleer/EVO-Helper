游戏内显示的一切时间都是 UTC+0（用户 2026-08-07 确认）。修正把游戏时间当 UTC+8 解析的错误。

`parse_iso_utc` 原先把不带时区后缀的时间按 UTC+8 解析，而那正是游戏报告头的格式。每份报告会被
提前 8 小时记录，「攻击方出发坐标 + 目标坐标 + 报告时间」的严格匹配将整体失效或错配到相邻报告。

- 新增常量 `evo_helper.vision.parsers.GAME_DISPLAY_ZONE = UTC`，并在文档里写明它与调度时区的区别：
  游戏画面时间用 UTC+0，用户配置的运行时间窗口（如 08:00–10:00）仍用 `domain.scheduling` 的 UTC+8。
  两者不得混用。
- 带显式时区后缀的时间行为不变，仍按该后缀解析。
- 配置：无变更
- 数据库：无变更。**注意**：若已有用裸时间写入的报告记录，其 UTC 时间偏移 8 小时，需要重算；
  当前尚无真实派遣与报告落库，因此本次无需迁移。
- 验证：`pytest`（129 passed）、`ruff check src tests`、`ruff format --check src tests`、`mypy src`；
  新增回归用例覆盖裸时间按 UTC+0 解析、显式时区仍优先
- 安全：报告匹配的时间维度由此才可用；此前必须排除时间条件
- 回滚：还原 `parse_iso_utc` 的默认时区与相关测试
