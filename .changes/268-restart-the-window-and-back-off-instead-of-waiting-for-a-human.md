**窗口拉不起来时就地重开；自动停用改成按退避自愈，不再一停就等人。**

## 那一夜（生产，2026-08-28）

00:01 游戏窗口没了（Chrome 挂了 / 机器休眠）。六个任务（1 个 RANKING + 5 个 BOT）
每轮起来**约 1 秒就死**，`exit=1`，日志只留下一行：

    00:25:28.622  [__main__] 模式：真打；目标 1:453:7=CCC, …    （完，pid=23032）

01:02 环境故障豁免用尽（6 次 ≈ 半小时），连计 3 次 → 六个任务全部自动停用，
恢复方式 `MANUAL`。**然后就没有然后了** —— 一直关到早上用户手动打开，军力榜多关了
两小时才被发现。用户口径（逐字）：「早上bot也是我手动开的，军力扫描挂了，我没有
看到」「我的预期是这些任务都应该自动重启才对」。

两个缺口互相独立，任一存在都足以让这一夜重演。

## 缺口一：没有任何东西去重开窗口

整个故障时段 `game.session_keeper` **一行日志都没写**，上一次活动是前一天 17:39。

层次错了 —— 会重开 Chrome 的 `restart_and_reenter` 是在 `BotLoop.run()` **里面**调的，
而进程死在它上面一行的 `driver.window()`。那套自愈的前提是「窗口已经在、只是走岔
了」；窗口本身没了的时候，它够不着。

新增 `GameWindowMissing`，把「重开能救 / 救不了」做成**异常类型**而不是消息文本。
判据是一句能验证的话 ——「同一步再走一遍，结论会不会不一样」：

- **能救**：拉起游戏后没等到窗口（昨夜那一句）、调尺寸时窗口消失、校验尺寸后消失
- **救不了**：DPR 配错（重开第一句就再校验一次，必倒在同一处）、找不到 Chrome
  （重开走同一个 `chrome_path()`）、有两个 EVO 窗口、收敛不到标定

一份实现（`ensure_window_or_restart`），三个入口共用，顺带补上坐标扫描那条。
`session_keeper` 一路透传，**整轮只有一份重开配额**（不透传的话入口和循环各建一份，
配额翻倍）。

⚠️ **抢不到前台那一档逐字不变。** `ForegroundUnavailable` 与 `GameWindowMissing` 是
`GameWindowError` 下的**兄弟**，所以「让路那一档永不重开」由类型层次保证，不只靠
用例 —— 它的语义是「什么都不做、纯粹让路」，重开反而会去抢用户正在用的窗口。

**收场刻意是硬失败而不是 `EXIT_ENVIRONMENT_BUSY`**：走到「重开也没救回来」说明这一轮
已经关过窗、重开过 Chrome 还是没窗口，那不是「没人管也会自己好」。

## 缺口二：自动停用之后没有任何自愈路径

`DisabledRecovery` 原先只有 `FREE_LINES`（每 tick 现算，自愈）和 `MANUAL`（只有人），
连崩到上限一律给 `MANUAL`，理由是「连崩到上限说的是『这不是暂时的』」。**这个担心
对，但结论下猛了**：防「满速空转」靠的是冷却，不是永不恢复。

新增 `BACKOFF` 一档：**15 分 → 30 分 → 1 小时封顶，不设终点**。按这条曲线昨夜那次会
在 **01:17** 自己回来。恢复时**不清** `consecutive_failures`（它此刻正等于上限），
所以放回来后再崩一次就立刻重新停用、落到下一档 —— 真坏了的链路一天最多白试 24 次、
每次约 1 秒。

状态全部落库（`retry_after_utc` + `backoff_rounds`），零内存状态：调度器进程会重启，
内存里的闹钟一重启就没了。归零点是任何任务 `exit=0`，与 `_exemptions.clear()` **同一
处** —— 那一刻环境被证明是好的。

### ⚠️⚠️ 判据只认 `disabled_reason`，一个字都不看 `enabled`

用户自己关掉的任务（生产上：侦查+攻击海盗、扫描全星系 bot、5 系攻击、9 系攻击）
`disabled_reason` 是 NULL（`update_mission_task` 会连 recovery 一起清掉），**永远不会
被自动打开**。

抽成 `domain` 层纯函数是为了让这条**能被直接钉住**：写在调度器的列表推导里的话，
「改成看 `enabled`」会被仓储层的事务内二次确认悄悄兜住（行没变、日志没写、集成用例
照样绿）。三道闸互相兜底的问题正是「拆掉任何一道，用例照样绿」，所以还有一条用例
绕过所有写入口、直接把行摆成最坏情形（用户关着 + 过期 `BACKOFF` 标记 + 早就到点的
闹钟），只留判据一道挡着。

迁移**刻意不认领任何历史行**：升级前 `MANUAL` 停着的任务保持要人工 —— 库里已经分不清
它当初是「连崩到上限」还是「参数填错」，两者当年写的都是 `MANUAL`，认错的代价是把一条
配置填错的链路每小时白起一次。

### 顺带补上的一个洞

**连崩自停这条链路原先整个是哑的** —— 它写在 `repository.record_mission_failure` 里、
不走 `_disable_task`，所以昨夜六个任务被关掉那一刻 `system_log` 里一个字都没有。

- Configuration: 无新增配置项。退避曲线是标定常量不是运维旋钮 —— 它的物理含义绑在
  `RESTART_COOLDOWN` 上，开一个次数框会让两个数各说各话（同 `MAX_ENVIRONMENT_EXEMPTIONS`
  那条注释的既有口径）。
- Database: 迁移 `f2c04b8ae153`（`down_revision = a7d3e91c05b2`，单一 head）。
  `mission_tasks.retry_after_utc` 可空无默认（NULL = 没在等冷却；给任何默认时刻等于
  把全库每一行摆成「随时可自动打开」，**包括用户手动关掉的那四个**）；
  `backoff_rounds` 非空 `server_default="0"`（计数，「不知道」对它没意义；留 NULL 的话
  每处读它都要写 `or 0`，漏一处就是静默的「退避不递增」）。
- Verification: `ruff format --check` / `ruff check` 干净；`mypy src` 3 条既有错误未新增；
  `pytest -q`（与 CI 同一条命令）→ 4208 passed / 256 skipped。**真 PostgreSQL 上单独
  验过迁移**（远端 `evo_helper_test`，本机 SQLite 证不了方言）：4 个迁移相关文件
  24 passed。**变异验证 25 处**（缺口一 12 + 缺口二 13）各有对应用例变红；其中最要紧
  的四条合并前独立重跑过（拆掉「不碰用户手动关掉的任务」/ 让那条判据永不生效 /
  退避不递增 / `exit=0` 不归零）。
- Safety: 抢不到前台那一档行为逐字不变，`FREE_LINES` 那一档行为逐字不变；自愈永不触碰
  用户手动关掉的任务，四条用例加变异钉着。
- Rollback: 缺口一 —— 三个入口退回裸 `driver.window()`、删掉 `ensure_window_or_restart`
  与 `GameWindowMissing`。缺口二 —— `record_mission_failure` 改回写 `MANUAL`、`tick()`
  去掉那一句恢复扫描；两列留着不碍事。
