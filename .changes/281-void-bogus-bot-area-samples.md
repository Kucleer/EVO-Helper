**一趟没读到 bot，就不许留下盲滚实测样本。** 2026-09-07 早上 7 趟里 6 趟一条都没采到，
根因在这。

## 那个自我强化的圈

盲滚行数是自动标定的：`min(最近 5 次实测) − 83`，样本来自 `system_log` 里那句
`翻了 N 行到达 bot 区`。

而那句话原先打在**检测段刚结束、采集段还没跑**的那一刻 —— 那时候还不知道这一趟会不会
读到东西。而 bot 区检测**会误报**（明明还在真人段就宣布「到了」）：

    滚得不够 → 误判「到了」→ 记一个偏小的数 → 下一趟滚得更少 → 又误判 → 数更小

**自我强化，而且永远转不回来。** 当天的实际数据：

    09-06 全天  自动  实测 821–832  落库 750  ->  下一趟盲滚 738  正常
    09-06 22:13 手工  实测 685      落库 0    ->  602
    09-07 08:07 自动  实测 679      落库 0    ->  596
    09-07 08:09 自动  实测 679      落库 0    ->  596
    09-07 09:26 自动  实测 679      落库 0    ->  596

bot 区在 **821 行**。停在 596 之后每一趟都落在真人段，每屏 `bot 0`，再记一条 679，
一直到有人手工把盲滚行数填死才停下。

## 改法

样本推迟到**第一次真读到 bot 行**的那一屏再发 —— 那一刻才有资格说「到了 bot 区」。

检测段原地只报一句进度：`检测段判定已进 bot 区（本趟走了 N 行），开始细读`。
⚠️ 措辞刻意避开 `翻了 ` 这个取样前缀（`domain.ranking.BOT_AREA_REACHED_PREFIX`）——
撞上就等于没改。

余量告警跟着样本一起走。它算的是同一个实测量，数不作数、据它算出来的告警也不作数：
08:07 那条就误导了一次，它让人去查「攻击配置页上的盲滚行数是不是填得太大」，
而那个数正是标定自己算错的。

## ⚠️ 刻意不按机器名筛

用户口径（2026-09-07，逐字）：**「谁拉代码谁就是实体机，未来也可能有新的」**。

按 host 筛只是把问题挪走 —— 备份机上的调试跑一样会误报，而实机自己误报时照样没人挡。
判据只有一条：**这一趟到底有没有见到 bot。** 一条规则同时堵住两个来源，
而且不需要维护一份「哪台是实机」的名单。

## 判「见到了」为什么用 `outcome.targets`

用的是 bot 过滤**之后**那一批非空，不是 `fresh` 也不是 `written`：

- `fresh` 在去重之后 —— 一屏全是已见过的坐标时它为空，而那种屏照样证明了「我在 bot 区」
- `written` 会被拉黑挡掉 —— 写不进库不代表没见到 bot

## 用例

新增 `test_ranking_bot_area_sample.py`（5 条）与共用场景 `SCENARIO_NO_BOTS`
（当天那 6 趟空跑的最小复现：检测段说「到了」，整趟一个 bot 都没读到）。

⚠️⚠ **场景里真人行的 `coordinate` 必须是 `None`。** `is_bot_entry` 判的是
「名字反解得出坐标 + 军力不为 0」，**根本不看名字前缀** —— 我第一版给了坐标，
于是那屏「真人行」照样被当成 bot，用例假绿（跑出来样本还在，才发现）。
实机那几屏读到的就是 `coordinate=None`。

五条各钉一件：

1. 正常一趟留**恰好一条**样本。留两条更隐蔽：`min(最近 5 次)` 的窗口会被同一趟灌满，
   标定从「看最近 5 趟」悄悄变成「看最近 2 趟」，而日志里样本条数照涨。
2. 一个 bot 都没读到 → **不留样本**（本文件的重点）。
3. **不留样本 ≠ 不说话。** 空跑必须仍然看得见，否则症状变成「日志里一句都没有，
   而盲滚行数莫名其妙地不动了」—— 比原来的错更难查。
4. 样本发在进度句**之后**。顺序本身就是这次改动的内容，倒过来等于没改。
5. 空跑不许按那个假实测报余量告警。

特征化基准两处各加一行，先 `diff` 确认过：只多了那句进度，样本句的相对位置一字未动。

- Configuration: 无新增配置项。
- Database: 无迁移。
- Verification: `ruff check` / `ruff format --check` / `pytest -q`（4288 passed /
  256 skipped）全绿。
- Safety: **判据一个字没动**，只动了那句实测日志的发出时机。
- Rollback: 把 `report_bot_area_reached` 的调用挪回 `if stretch.reached_bots:` 那一段
  即可 —— 但那正是这次要修的东西，所以 `report_bot_area_reached` 的 docstring 上写着
  别挪回去。
