**军力读数的判据改成对曲线判：参照名次相近的多个历史点，不再参照旁边那一行。**

用户口径（2026-09-02，逐字）：

> 「军力的降序速度是可预估范围内的，实际上仅需要几个锚点就可以对其整个长链路」

## ⚠️ 前两版栽在同一处：参照物是**单个**值

- **原始判据**参照屏内上一行。一个「读小了却仍然递减」的错读会顺利通过判据、当上
  基准，把它后面每一行正确的值都判成逆序 —— 实测被丢的行里 **75.2%** 是这么误伤的
  （被丢 ≥2 行的 1,099 组里，867 组「整组自身完美降序」，组内跨度中位 0.31%）。
- **`screen-bracket/1`（#271）**参照本屏首尾。端点被打中就整个失效 —— 上线后实测
  **28%** 的屏「区间不作数」，丢弃率没降。

## 这一版：参照多个点的中位数

按名次取邻近历史可信点的中位数。**中位数抗少数坏点** —— 窗口里混进一两个错读，
参照纹丝不动。这就是「几个锚点对整个长链路」的落地形式。

⚠️ **有曲线参照时只听曲线的**，那三条单点判据不再有否决权。两套并行等于让那个可能
读错的单点仍能否决，前两版栽的正是这个。历史不够（< `CURVE_MIN_POINTS`）就**不表态**，
退回原判据 —— 每趟头几屏历史本来就少，而榜首那几段恰恰是断崖最陡的地方。

## 阈值是量出来的

生产反推，近 3 天 8 趟扫描 574 个非估算点，每点对「同名次 ±60 名邻居中位数」算偏差：

    偏差   0– 2%   460  80.1%   ← 真值紧贴曲线
    偏差   2–15%    82  14.3%
    偏差  15–30%     6   1.1%
    偏差  30–40%     0   0.0%   ← 空隙
    偏差  40–70%    24   4.1%   ← 错读簇
    偏差  70%+       2   0.3%

`CURVE_TOLERANCE = 0.35` 落在那个空档里。>30% 那 26 个里有 **20 个（77%）把首位换回
邻居中位的首位就对上了** —— 确凿的首位互串（3↔9↔5）。

⚠️ **阈值和窗口是一对**：上面那张表是在 ±60 名的窗口下量出来的，改一个必须重新量
另一个。也**不要往 15% 调** —— 15–30% 那 6 个点是真值（屏边界、名次跨度大的地方）。

## 回放抓出了库里现存的错值

这些**现在就在生产库里**，过了所有既有判据（比上一行小、没到 5 倍断崖）：

    名次 1584  读到 9,730  邻居中位 5,690  → 换回首位 5,730 ✓
    名次 1634  读到 3,480  邻居中位 9,540  → 9,480 ✓
    名次 1603  读到 3,650  邻居中位 9,415  → 9,650 ✓

32 个被标出的里只有 4 个是逆序 —— 另外 28 个是「读小了」那一半，既有判据**结构上
看不见**。

## 用中位数而不是拟合

榜单不是一条直线（整段 570 名跌 10%，而榜首那几屏能从 5.97M 跌到十万级）。拟合要选
参数形式，选错了到处是系统偏差；滚动中位数**不假设形状**，只假设「邻近名次的军力
相近」—— 那是「榜单按军力降序排」的直接推论。

- Configuration: 无新增配置项。`CURVE_TOLERANCE` / `CURVE_RANK_SPAN` /
  `CURVE_MIN_POINTS` 是**标定常量**不是运维旋钮 —— 它们是从识别误差的分布量出来的，
  改它们不会「更适合我」，只会让判据变错。
- Database: 无迁移。
- Verification: `ruff format --check` / `ruff check` 干净；`mypy src` 3 条既有错误未
  新增；`pytest -q`（与 CI 同一条命令）→ 4241 passed / 256 skipped。
  **八处变异各有对应用例变红**（曲线不用 / 参照用平均值 / 容差放到 200% / 容差收到
  5% / 历史不够也给参照 / 判错的值也进历史 / 曲线没有独占权 / 名次用未修过的原始值）。
- Safety: 历史不够时行为逐字不变；`renderable_score` 与插值那两层没动。
  曲线历史**不跨趟复用**（bot 军力每周一 UTC+0 刷新，两趟之间还隔着几十分钟的攻击）。
- Rollback: `_judge` 里 `if reference is not None` 那一支删掉即可，其余判据原样还在。

## ⚠️ 一条方法论教训

这一版之前我做过三次回放，**三次都拿错了样本**：拿被丢的行当一屏（级联的构造让它们
天然是干净降序，用结果污染的样本预测结果）、拿全库 rank+score（两列来自不同轮次）、
拿单趟切片逐点外推（去重后名次稀疏）。第四次改成**拟合而不是外推**才成立。

变异验证也抓了同类问题：M8「名次用未修过的原始值」第一版是绿的 —— 用例把错读放在
屏中间，区间判据自己就丢掉了它，两条路结果一样。改成放在末行（兜底会放行、只有曲线
拦得住）之后才接住。**用例没能分开两条路时，它证明的是零。**
