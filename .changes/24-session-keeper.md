扫描期间每 10 分钟巡检会话，掉线自动重连。

调试过程中游戏会话掉了四次，所以「掉线」是常态而非异常，扫描流程必须能自己接回去。

- `game/session_keeper.py`：`SessionKeeper` 按 `HEALTH_CHECK_INTERVAL_S = 600`（用户指定
  10 分钟）巡检，掉线时走已知入口序列（语言页 → 进入 → START）接回去。
- **认不出的画面绝不点击**。可能是维护公告、弹窗或改版；乱点可能误触派遣、删信或领奖。
  点击前的判定一遇 UNKNOWN 就停。
- **过渡态容忍**：点完「进入」后的加载屏 OCR 读出来是花的（`GE RERNAE / Vege`），
  那只说明「此刻读不清」，不等于「这一屏认不出」。轮询期间容忍 UNKNOWN 继续等到超时，
  但仍只在**真的观察到 START** 时才点——安全性质不变。
- 固定等待改轮询：切屏时间不稳定，死等 4 秒常常还停在入口页，整条序列在第一步就断。

**判据改用 OCR 读得稳的词。** 底部导航条实测读成「和量 般队 太空能 商店 联盟」——
行星/舰队/太空舱 三个都被读错，只有 商店、联盟 稳定。早先的判据恰好只用了被读错的那几个，
导致**在线的会话被判成「认不出」**。现在用 `IN_GAME_MARKERS = (商店, 联盟, 银河系, 恒星系)`，
并且优先 OCR 导航条的紧凑裁剪而不是整屏。

实机验证：在线会话正确识别为 `in_game`（`session still alive`，不触发重连）。

顺带记录一条调试结论：恒星系视图的 `«` / `»` 是**切换恒星系**，不是翻页——
点三次后恒星系从 137 变成 140，画面几乎不变但坐标变了。这意味着换系只要一次点击，
比「点字段 + 输入 + 点 OK」三步快得多。

- 配置：无变更（间隔可传参覆盖）
- 数据库：无变更
- 验证：`pytest`（494 passed）、`ruff check src tests`、`ruff format --check src tests`、`mypy src`；
  用例覆盖 10 分钟间隔、慢过渡轮询、过渡态花字容忍、认不出不点击、只在观察到 START 时才点、
  以及导航条真实 OCR 读数能被识别
- 安全：只做画面识别与入口序列点击，不含派遣路径；演习模式仍是默认
- 回滚：删除 `session_keeper.py` 与其测试
