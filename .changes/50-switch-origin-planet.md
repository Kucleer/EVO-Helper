助手现在**真的会在游戏里切换出发星球**了。#49 那道临时闸门
（`domain.missions.check_origin_dispatchable`）连同它的两个调用点、三条用例一起删掉。

这是那两个 PR 里的第二个：#49 做的是「数据模型 + 记账」，配一颗不是主星的出发星球
会在起子进程之前被拒；现在 runner 开工时会把当前星球切过去，配哪颗就从哪颗出发。

## 路径

```
星球地表 / 恒星系视图
  → 点底部导航「行星」`pirate_ui.NAV_PLANET` (840, 862) → 行星列表浮层
  → 拖 + 每屏认坐标，找到目标那一行
  → 点该行的「前往此处」(1166, 名字行 y + 60)
  → 开舰队/派遣面板回读「起点: [2:137:18] …」，确认真的换了
```

分两层：`domain/planet_switch.py` 是纯逻辑（认哪一行、要不要切、拖到底没有、
切没切成），`game/planet_list.py` 只做「拍一屏 → 交给纯逻辑 → 按它给的坐标点一下」。

## 三条不许妥协的

1. **先认坐标再点。** 纯函数按「每一行 OCR 出来的坐标」找目标；一行都认不出就
   **什么都不点**，本轮以 `EXIT_ENVIRONMENT_BUSY` 退出等下一轮。绝不按行号盲点——
   那一排八个图标里，运输/部署/传送/转移/投送/保护/扩张点错任何一个都是真实操作。
2. **点之前再回读一次那一行**（与 `game.action_guard` 的「点击前重新观察」同形）。
   两次读到的 y 对不上就当这一屏没有，接着拖。
3. **只有「前往此处」那一个 x 进代码**（`PLANET_GOTO_COLUMN_X = 1166`），
   其余七个图标的坐标本仓一个都没写下来——不存在就点不错。
   ⚠️ 「扩张」和「前往此处」**在同一个 x 上**，分开它俩的只有 60 与 130 那点差。

## 翻页与拖动

做法与预设条那条完全一致（`game.preset_picker`，#100）：拖一次 → 重读这一屏每一行的
坐标 → 目标在不在这一屏？在就点**当屏那一行**，不在就继续拖；「这一屏读到的和上一屏
一样」= 到底了，仍没找到就什么都不点。位置只来自当前这一屏，不缓存、不外推、
不跨屏换算 y；拖动次数有上限。

拖动的**按下点跟着当前这一屏识别出来的行走**（面板横向中点 x=961、某一行星球名的 y），
不写死：横向中点只在星球名那一行是空白，往下 70px 就是图标排，同一个 x 上坐着「部署」。
拖动走 `slow_drag`——一步式 `dragTo` 会被游戏面板当成点击。

## 回读只认「起点」那一行

行星列表浮层上**没有任何「当前星球」标记**：基准图上当前就是第一行，它和另外两行
长得一模一样，八个图标一个不差、连「传送」上那个红禁标都一样。所以「真的换过去了吗」
全仓只有一个地方答得上来——派遣面板的「起点: [2:137:18] [奥格瑞玛]」。
切完开一次舰队面板读它，读不出或对不上一律**当作没切成，本轮一发不派**。

## 一轮只切一次

切换在 runner 开工阶段（`PirateLoop.ensure_origin_planet`，进目标循环之前），
不在每个目标前面。纯函数 `switch_needed` 判要不要切，runner 记住本轮已切到哪——
而那份记忆**只在回读确认之后**才写，与 `SystemNavigator.current` 同一条规矩。

- 配置：**没有新配置项**。任务上的出发星球（#49 加的那三列）从「配了也派不出去」
  变成「配了就真从那里出发」。既有取值一个没动
- 数据库：无迁移
- 验证：`pytest`（1631 passed / 51 skipped）、`ruff check src tests`、
  `ruff format --check src tests`、`mypy src`。
  两个 ROI 与它们的配方拿**真实像素**验过（`tests/integration/vision/
  test_planet_switch_live.py`，离线读 `var/logs/calib-切换星球-基准.png` 与
  `calib-舰队面板-client.png`，缺图时跳过）——坐标列第一套配方读全三颗星球，
  识别出来的行 + 偏移量落回量出来的 (1166, 250/480/710)，起点行逐套配方全对。
  **配方顺序是实测挑的**：3× LANCZOS 会把 `[9:250:8]` 读成 `8:250:8`（不是读不出，
  是读成另一颗星球），所以最近邻排在前面。
  14 条变异逐条确认变红（图标偏移改成 130、点击列改成「传送」那一列、配方改成
  LANCZOS 打头、起点 ROI 右界放宽、认不出也当成一行、回读读不出当成切成了、
  `switch_needed` 恒真、按下点写死、去掉点前复核、去掉「到底了」判据、
  回读没过也记下当前星球、切不成也照样扫目标、切不成按 0 收场、dry-run 照样点）
- 安全：**这个 PR 里没有任何一行代码在 CI 上驱动过游戏**，实机验证由用户做。
  新增 `python -m evo_helper.tools.switch_planet --origin X:Y:Z --dry-run`：
  走完「开浮层 → 拖 → 认坐标」，只打印「打算点 (1166, 480)，因为这一屏在 y=420
  读到 9:250:8」，**不点「前往此处」、也不开派遣面板**。`--commit` 才真的切，
  两档必须显式选一个、没有默认值。
  回读失败时 runner 报 `EXIT_ENVIRONMENT_BUSY`（不计入连续失败）而不是照样派
