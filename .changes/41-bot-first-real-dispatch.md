## 一、攻击按钮点在空白处（根因，最难看出来）

`attack()` 用的是 `pirate_ui.ATTACK_BUTTON = (1032, 540)`——那是**敌对海盗**面板上的
位置。bot 星球是**有主**面板，布局完全不同：上面先列坐标/玩家/联盟三行，中间是
「攻击/侦察/扫描/回收」四个小图标一排（图标 y≈398、标签 y≈435），(1032, 540) 落在
图标排和舰船格之间的空白处。

点了等于没点，派遣面板压根没开，接着去读预设条自然读到噪声（实机 `['4', 'i]']`），
于是报「找不到预设 探路」——**失败信息指向预设，真正的问题在按钮**。
`ATTACK_BUTTON` 改成类属性，`BotLoop` 覆盖成 `BOT_ATTACK_BUTTON = (821, 398)`；
坐标用 OCR 字框量出来：标签中心 (821, 435)，图标在其上约 37px，与海盗面板
「标签 575 / 按钮 540」的偏移一致。

## 二、中文预设名被 tesseract 按字切开

按钮修好后面板开了，预设条读到 `['AAA', '探', '路']`——预设看得见了，但 `pick()`
是逐词做 `name in text`，没有任何一个词包含「探路」。AAA 是拉丁字母不分词，所以
海盗链路一直没事，**只有中文名的预设选不中**。改为按词框间距把相邻词合成一段再
匹配，阈值 40px 的依据是实测：同名相邻两字差 10px（探 x=984 / 路 x=994），不同
预设之间差 237px（AAA x=747）——两个量级隔着一个数量级，合不过头也漏不掉。

## 三、关掉派遣面板之后没清导航器缓存

`SystemNavigator.goto` 只重设它认为变了的字段，而 `PresetNotFound` 那条分支关掉
面板后**漏了 `invalidate()`**（`_leave_dispatch_list` / `_close_mail` 都有）。后果
最贵：缓存仍以为银河系是 2 → 下一个目标跳过重设银河系 → 那一下「设恒星系」落到
银河系框上 → 游戏把 136 截断成最大值 9。此后导航栏是 `[9:137:12]` 而缓存说
2:137，**银河系再也不会被重设**，44 个目标坐标核对全不过；现场图上顶栏写着
银河系 9 / 恒星系 137 / 行星 12，坐实了这条。

坐标判据一个字都没动，而且不许动——那一轮里有一次读到的是上一个目标的星系
（请求 2:321:5、面板 2:320:5），核对**拦对了**；放松成「位次对上就行」就是往错误
的星球扔舰队。补的是 `invalidate()` 与 `_goto_confirmed()`：核对不过就复位画面、
清缓存、重新导航、再读一次（只重试一次，无限重试会把整轮卡死在一个目标上）。
清缓存是这条重试的全部意义——不清的话重试会一字不差地重演上一次失败，实机验证过。
顺带补上「核对不过存现场图」（封顶 3 张）：那 13 分钟原先只留下一行文字，证据就是
这么白丢的。
