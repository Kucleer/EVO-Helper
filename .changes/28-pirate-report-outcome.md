```bash

    --detail var/logs/pir1-detail.png --bottom var/logs/pir1-bottom.png
# 胜负            : VICTORY
# 战损（我方/对方）: 0 / 783
# 单位（我方/对方）: 100 / 783
```

- `vision/pirate_reports.py`：只读详情页的轻量读取
- `report_screens`：新增 `loss_totals()`、`outcome_banner()`
- `battle_reports` 新增 `outcome` / `attacker_losses` / `defender_losses`
- `tools/ingest_pirate_report.py`：两张详情页截图入库，不碰回放页

## 设计要点

- **口径是用户定的（2026-08-09），理由是性能。** 逐舰种明细要进回放页、
  读两列名称与数量、还要反复重拍到合计对上，一份报告两三秒；而海盗全是同一个
  预设打的，明细没有分析价值。战损也只要总数，不按舰种拆。
- **不复用 `LiveReportReader`。** 那边要求参战两列非空（这里根本不读），
  而且「海盗攻击报告」在 `classify_report_subject` 里不可与派遣匹配，会被整份拒收。
- **不写 `fleet_snapshots`。** 明细一旦混进去，情报中心会把我方预设的舰船
  当成对方的舰队——比缺数据坏得多。测试里专门守着这一条。
- **要两屏截图**：未滚动那屏有胜负横幅与 VS 坐标，「损失单位」那一行却被面板
  下沿切掉；拖到底之后「损失单位」全了，胜负横幅又滚出了可视区。
- **拖到底是可标定的姿势**：面板会夹住，实测拖 280px 与拖 520px 落点完全一致。
- **三个新字段都可空，而且必须可空。** 这之前入库的战报没读过胜负与战损，
  给 `outcome` 补值等于凭空造战果，给战损补 0 等于凭空造「零损失」。

## 三个实测撞出来的 OCR 坑

- **锚点不能取最靠下那条亮带。** 详情页拖到底之后，最靠下的亮带是黄色的
  「查看战斗回放」按钮，照它算出来的行落在按钮下方的空白上，读回来是空字符串,
  于是报「战损读不出来」，而真正的毛病是锚点找错了。改成「哪条亮带下面第一行
  是两个能解析的数，就是它」——判据和答案是同一件事。回读标签行不可行：
  「单位:」是暗灰小字，`chi_sim` 实测读成 `后亿:` / `下`。
- **行窗高度 24 → 20。** 窗口碰到下一行的顶边，`--psm 7` 当场读空：
  同一张图 height=20 读出 `100`，height=24 读出空。
- **`TOTALS_RECIPES` 比 `COUNT_RECIPES` 多一档 2×。** 战损常是孤零零一个 `0`，
  实测只有 2× 配数字白名单读得出来，3×/4×/5×/6×/8× 一律读空——白名单剥掉了
  tesseract 定位字形的上下文，单个窄字形放得越大越像噪点。白名单不能去掉：
  这一行背后压着 `-17003` / `COMMAND OFFICERS` 那层水印。
