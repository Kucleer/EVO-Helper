**舰队标签里有四种信，不是两种。** `#344` 的取证一上线 15 分钟就把它打出来了。

## 真因：同一个仓库里两处说法不一致

    vision/parsers.py:367   「舰队标签里的四种信（实拍 2026-09-13：
                             舰队返回 / 回收报告 / 矮星系统战报 / 部署报告）」
    tools/pirate_loop.py    「舰队标签里**只会**出现这两种主题」
                             FLEET_TAB_KINDS = (RECYCLE, FLEET_RETURN)

**判据用的是错的那一份。**

## 代价（实机实测 2026-09-14 晚）

舰队标签第 0 行常驻一封**矮星系统战报**（最新那封），于是每次都是
「非舰队类 = 1」，`here > 0 and other == 0` 不成立：

    回收趟开工 6 次 → 切到「舰队」2 次、切不到 4 次 → 实收入库 0 份

而当时库里有 **325 发回收在等实收**。`#344` 的取证日志把它写死了：

    └ 第 0 行 kind=STARGATE     主题='BS   矮星系统战报'   ← 就是它
    └ 第 1 行 kind=FLEET_RETURN 主题='se  舰队返回'

⚠️ **主题读得干干净净，不是 OCR 读花** —— 是那张表少列了两种。

## ⚠️ 这不是放宽判据

判据仍旧是「读得出的行必须**全都**属于舰队标签」，只是「属于舰队标签」
这件事现在照实测写全了。混着**确凿攻击报告**的屏幕（没筛过的列表）照样拦住。

⚠️ 我先前为这个现象提过两个假设 —— 「判据太严」和「点击没生效」——
**两个都不对**。真相是第三种：判据是对的，但它手里那张事实表是错的。
这也是为什么 `#344`（先取证、不动判据）是对的顺序。

## 用例

  而且那四种都得被 `classify_report_subject` 认出来 —— 任一处变了另一处会红；
- 回放实机那一屏（矮星战报 + 5 行舰队返回）→ 判成「筛选开着」；
- 反向：混着攻击报告的屏幕仍旧判不成立。
