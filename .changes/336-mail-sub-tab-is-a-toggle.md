**信箱那一排二级标签：「舰队」是个筛选开关，不是页签。** 三个错叠在一起，
外加判据一侧永远拿不到正面证据。2026-09-13 夜实机逐点取证。

症状：回收读信那一趟**切不到「舰队」、整趟不读**；切回去 **3/3 全失败**；
而且在没切成的列表上把攻击报告也开了，每封白花 8 秒。

## ① 坐标点的是「侦察」

四个按钮中心实测 **战斗 772 / 侦察 897 / 舰队 1033 / 系统 1150**（y=218）。
`MAIL_BATTLE_SUB_TAB = (897, 218)` 的 x 是从一级标签「报告」抄来的 ——
两排的 x 中心确实一样，但**第二排第二个是侦察**。

## ② 那不是一排页签

逐个点过，只有「舰队」有反应：

    起始 列表=舰队类 ×6
    点 772（战斗） → 没变     再点一次 → 还是没变
    点 1033（舰队）→ 变成攻击报告   再点 → 又变回舰队类

所以**两个方向点同一个坐标**，`MAIL_BATTLE_SUB_TAB` 整个删掉。

## ③ 开关状态跨次记住，而代码无条件先点再看

    第 1 轮 进来时 fleet ×6 → 点一下 → attack ×4
    第 2 轮 进来时 attack ×4 → 点一下 → fleet ×6
    第 3 轮 进来时 fleet ×6 → 点一下 → attack ×5

上一趟把信箱留在「舰队」上时，这一趟第一下就把它翻掉 —— 本该一下到位的按钮
变成了赌奇偶。改成**先看再点**。

## ④ 判据一侧永远拿不到正面证据

开着筛选时列表只有「舰队返回 / 回收报告」两种主题，**读得准**（每次量到都是 6/6）；
关掉之后混着攻击报告，而**攻击报告的主题读不准**，实测经常 6 行全 `unknown`。
原判据两侧都要求正面看到对方（`there > 0`），于是「关掉」这一侧**永远判不成立**。
改成不对称：开着要正面证据，关掉只判「一封舰队类都没有」。

⚠️ 这不是放松闸门：`_on_mail_list()` 已经挡住「根本不在列表上」那一档。

等待 `MAIL_SUB_TAB_WAIT_S` 1.8 → 4.0：生产日志里那条「舰队类 3 行、攻击报告 2 行」的
**混合**读数只可能出自重绘中间。
