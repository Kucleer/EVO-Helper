**军力选靶那两格——「军力分数有效期」与「窗口门限」——改成全局设置。** 所有军力任务
共用一份，在攻击配置页（`/settings`）改；任务行上那两个框撤掉。

用户口径（2026-08-23）：

> 军力攻击的有效期 门限 改为全局设置，不再根据单个星系进行调整

## 「有效期」和「门限」是两个东西，都搬，理由是同一条

选靶第 3 步是一道判据的两半（`domain.target_order` 模块头第 3 步）：

| | 原先住在 | 现在 | 留空 |
|---|---|---|---|
| **有效期**（窗口多宽） | `mission_tasks.params_json` 的 `score_max_age_hours`，旧键 `rescan_after_hours` | `military_attack_config.score_max_age_hours` | 2 小时 |
| **窗口门限**（窗口内够不够用） | `mission_tasks.params_json` 的 `top_n` | `military_attack_config.window_floor` | 100 个 |

⚠️ **一半全局一半按星系是不成立的**：「窗口多宽」按全局、「窗口内够不够用」按星系，
那种组合谁也解释不清，而它的症状（某个银河老在报「放宽窗口」）看起来像是数据问题。

**「军力上限」（`max_score`）没动，仍然是任务级的**：上限取决于这个任务用哪个预设
出击，而预设是按任务配的。（它当前仍然空转——实测 bot 最高战力约 70K。）

## 为什么它们本来就不该按星系配

任务页 2026-08-22 改版之后**一个任务对应一个出发点银河系**，于是这两格事实上成了
「按星系分别配」。而它们约束的**不是星系，是军力榜扫描的节奏**：榜是一趟扫完全宇宙
的，一轮扫多久、读数能有多新，与舰队从哪个银河系出发毫无关系。

一个数存成 N 份的代价是改要改 N 处，而**漏改一处的症状是那条链路悄悄用着另一个
有效期**，页面上一点异常都看不出来。

## ⚠️ 存量的按星系旧值：忽略 + 告警，不迁移

生产库里每个军力任务的 `params_json` 里都存着自己那一份。三条路：

- **照旧读** → 那就不是全局设置，改了攻击配置页不生效，需求本身没做到。
- **自动迁移**（把某个任务的值搬进全局）→ 搬哪一份都是**替用户拍一个数**。拍错的
  症状是所有星系一起换了个有效期，而页面上看不出这个数是从哪来的。**这个数该是多少
  只有用户知道。**
- **忽略并告警**（本次选的）→ 新列留 NULL（= 跟着代码默认走），每轮派遣往
  `system_log` 落一条 **WARNING**：

  > 军力选靶窗口已改为全局设置：任务「5系攻击」的参数里还存着 top_n=2、
  > rescan_after_hours=1，**已忽略**……这一轮实际用的是全局值：有效期 2.0 小时、
  > 窗口门限 2 个。要改就去攻击配置页改那一份；在任务页保存一次会把这几个旧键清掉，
  > 这条告警随之消失。

⚠️ **这次改动会让实机行为在某些任务上当场变掉**（一个从前配着 6 小时的任务，
升级后用的是全局那一份）。告警存在的全部意义就是别让那件事静默发生——不说的话，
症状是「某个银河突然打得少了 / 突然开始报放宽窗口」，而页面上、日志里一个字的解释
都没有。

判据是**「这个键在不在」，不是「它等不等于默认值」**：按取值判会把「用户当年就配的
2 小时」当成没配过，那条任务永远不告警，而它同样存着一个不生效的值。

告警**有尽头**：任务页保存一次会 `delete` 掉那三个键（`top_n` /
`score_max_age_hours` / `rescan_after_hours`）。永远响的告警等于没有告警。

⚠️ **旧键不由迁移脚本删。** 迁与不迁由用户决定（整段理由在迁移的模块头上）。

## 边界

- **有效期必须是正数**，上限 **168 小时（一周）**。
  - 填 0 的后果和填 0 的人想要的**正好相反**：0 = 「没有一条读数算新」→ 窗口内恒为
    0 个 → 每轮都放弃窗口 → 一律拿旧读数打，而页面上只显示那句正常的「已放宽窗口」。
  - 一周是上界因为**再往上挡不掉任何东西**：第 2 步的周期边界（周一 UTC+0 刷新）
    已经把上周期的读数整批滤掉了。一个填了却什么都不做的旋钮比没有它更坏。
  - **允许小数**（1.5 小时一直是合法取值，页面步长 0.5）。这一路上任何一处退回
    `int` 都会把它悄悄取整——库里那一列是 `Float`、pydantic 那个字段是 `float`、
    读侧走 `_float_knob` 而不是 `_knob`，三处各有用例钉着。
- **窗口门限至少 1**，**上界刻意不设**。
  - 0 会让窗口**永远不被放弃**：窗口内真的一个都没有的夜里（周一凌晨）这一轮会在
    空池子上选靶、一发不派，而该响的 WARNING 一个字都不写。
  - 不设上界是因为门限该多大取决于候选池此刻有多少个（3000+ 个 bot，而窗口内能有
    多少又取决于扫描节奏）。填得比池子还大只会让窗口每轮都被放弃，**而那件事会告警**。

## 落点

- 数据库：迁移 `c7f2a91d4e08`，`military_attack_config` 加两列
  （`score_max_age_hours` `Float`、`window_floor` `Integer`），**都可空、都不给
  `server_default`**（NULL = 跟着代码默认走，升完那一刻行为不变）。**一行业务数据不动。**
- 读侧唯一入口：`MissionScheduler._score_max_age()` / `._window_floor()`，
  非默认值走 `record_knob_override` 往 `system_log` 留一条「配置生效：用的是 X」。
- 校验：`validate_score_max_age_hours` / `validate_window_floor`（页面写库前用调度器
  同一把尺子量）。`validate_military_params` **不再**校验这两格——存量任务里那两个键
  已经不生效，照旧校验等于让一个不生效的值把保存整个拦下来，而报的错说的是一个用户
  再也看不到的框。
- 页面：`/settings` 新增「军力选靶窗口（有效期与门限）」一节；`missions.html` 撤掉
  那两个框与它们的回显，保存时清掉三个旧键。任务摘要不再报那个数（一个全局值摆在
  每一行任务上，读起来像是这一行配的）。
- 固化记录（`_frozen_summary`）不再念 `top_n`：固化只抄任务参数与档位，全局那份
  不在里面，念一个当时也已经不生效的数比什么都不念糟。
- 验证：`pytest tests`、`ruff check src tests`、`ruff format --check src tests`、
  `mypy src`（3 条既有错误不新增）。
- 回滚：revert 本次提交 + `alembic downgrade b8e1c4a72f05`（那条 downgrade 只带走
  这两列，有用例钉着）。存量 `params_json` 一个字没改，退回去之后照旧读得出来。
