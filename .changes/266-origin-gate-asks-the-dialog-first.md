**派遣起点回读「读不出」时先问一句屏上有没有弹窗；保护期弹窗不再当成起点漂了。**

用户口径（2026-08-27，逐字）：

> 「检查一下今天8点以后为什么4系的攻击没有发出」

## 症状

4 系一天起了 8 轮，**7 轮死在同一个目标 `4:268:5` 上**，每轮长得一模一样：

    08:43:18  出发星球：切到 4:277:15
    08:43:44    起点回读 '4:277:15'，确认当前星球是 4:277:15
    08:43:51    导航栏回读 ('4','277','15')，确认停在 4:277:15
    08:44:14    派遣面板起点回读 （读不出）（原文 ''）
    08:44:15    起点核对不过；这一发没派，这一轮到此为止

星球明明切对了 —— 上面两行刚各确认过一次。存下来的现场图（`system_log` id 109168，
`roi: [770,632,848,660]`、`origin_raw_text: ""`）上，那一刻屏幕上是**保护期弹窗**
（「没有可执行的任务。」）压在派遣面板上，起点那一格自然读空。

## ⚠️ 缺陷：整轮结束赶在认弹窗之前

`attack()` 的顺序是 `点攻击 → 核起点 → 翻预设条 → 确认终点 → _handle_dialog`。
弹窗在开面板那一下就冒出来了，而 `OriginDrifted` 是 `RoundExhausted` 的子类 ——
**抛出去就是整轮结束**，`_handle_dialog` 一步都没走到。于是：

1. `_note_protection_period` 没跑到 → `bot_targets.protection_seen_at_utc` 一直是
   `NULL`（生产上核过，那几个坐标全是 `NULL`）
2. 选靶查不到「撞过保护期」，目标没被排除；军力 10580、离得又近，排序上永远靠前
3. 下一轮又挑中它 → 又撞同一个弹窗 → 又整轮作废

**这是个自维持的循环，而且在长**：08-25 四次 → 08-26 六次 → 08-27 十四次。历史上
同样咬住过 `2:391:16`（6 次）、`5:261:8`（2 次）、`8:117:6`（2 次）。

## 改法

判「核对不过」之前，读不出的那一档先把屏交给 `_handle_dialog` 按弹窗类型认 ——
它已有的语义正好对上：保护期 → 记一笔、跳过这个目标、这一轮继续；资源耗尽 →
`RoundExhausted` 照旧停轮；认不出弹窗 → 落回原来那条拒绝逻辑。

**安全性不变：仍旧绝不在起点读不出时派遣。** 变的只是「读不出**且**屏上有认得的
弹窗」这一档 —— 从「整轮作废且什么都不记」变成「记下保护期、跳过这个目标、
这一轮继续」。

⚠️ **只在「读不出」那一档问弹窗。** 读出来是**别的坐标**时不问 —— 那是真漂了，
弹窗解释不了一行读得清清楚楚的坐标，而放行的代价正是 2026-08-18 那次事故：
一发从主星飞出去、账记在 9:250:8 上，多出发点的整套航线记账全是假的。

保护期那一档**不清** `_current_planet`：清掉是「记忆被证伪」的动作，而这里星球
切对了，只是被弹窗盖住。清掉的代价是这一轮余下十几个目标每个都白切一次星球。

- Configuration: 无新增配置项；保护期排除时长沿用攻击配置里那一格。
- Database: 无迁移。改动让原本就该写的 `bot_targets.protection_seen_at_utc` 真的写进去。
- Verification: `ruff format --check` / `ruff check` 干净；`mypy src` 3 条既有错误未
  新增；`pytest -q`（与 CI 同一条命令）全绿。新增 7 条单元用例；**六处变异各有对应
  用例变红**（完全不问弹窗 / 读到别的坐标也问 / 弹窗挡下却照常派 / 攻击那一支忘了
  退出派遣列表 / 侦察那一支忘了退出 / 保护期那一档也清星球记忆）。
- Safety: 只放宽「读不出且屏上是已认得的弹窗」一档；起点读出别的坐标、以及读不出
  而屏上什么都没有，两条路径逐字不变，各有用例钉着。
- Rollback: 把 `_require_origin_before_dispatch` 里那三行弹窗询问删掉、签名改回
  `-> None`、两个调用点去掉 `if not ...` 包装即可。
