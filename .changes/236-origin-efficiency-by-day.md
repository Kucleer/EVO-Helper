「数据概览」页新增**按天 × 按星球的效率**：回答「今天哪个出发星球效率最高」。

用户口径（2026-08-20）：「比如我想知道今天哪个星球的效率最高，用按天、按星球的
资源收益去除他的航线数。」

## 一、分子：只算稀有三样

槽位取 `domain.overview.RARE_SLOTS`，名字由 `domain.battle_resources.slot_label`
翻译——**查询里和模板里都不许再抄一份**（那张对照表的顺序与游戏「太空舱」页不一致，
抄第二份出去，对不上的症状是「数字全对、只是安在了别的资源名下」，页面上一点异样
都没有）。有一条用例直接读 SQL 模块与模板的**源码**钉这件事，因为它在渲染结果上
看不出来。

⚠️ **基础三样（金属 / 晶体 / 气体）绝不许进这个指标。** 实测 2026-08-20：它们由
**我方货舱容量**决定、与目标无关——同一预设 6 条战报的变异系数只有 **0.0001**
（719,900 / 720,000 / 720,100），而同期目标军力从 10,020 跨到 11,170 纹丝不动。
掺进来会让「预设大的星球」无脑领先，得到假结论。

## 二、归属：按**派出日**，UTC+0 切天

一发的收获记在它**派出**的那一天（`attack_dispatches.dispatched_at_utc`），
即使战报隔天才读回来。按读回日归属的话，「今天效率高」可能只是「今天补读了昨天的
战报」。资源顺着 `battle_reports.dispatch_id` 反查回派遣——**配不上派遣的战报
（`dispatch_id IS NULL`）一律不算**，它既说不出是哪颗星球派的、也说不出是哪天派的。

⚠️ **代价：当天的数永远不完整**（还有战报没回来）。所以「读回战报」与「回收率」
**并列在表里、不是小字**，而且回收率低于 **60%** 时两个效率数显式标成
「不可信」。

**60% 是怎么来的**：回收率就是分子的覆盖率，回收 60% ⇒ 效率至少低估 1 ÷ 0.6 =
**1.67 倍**；而实测相邻两颗星球的「每线」只差 13,053 / 8,007 = **1.63 倍**——
也就是说 1.67 倍的低估足以让相邻两行**换位**，阈值就压在这个「能翻排序」的边上。
再宽一点，页面会拿一个已经排错了的名次当结论；再严一点，正常的日子会被无谓地打上
不可信（当天最差的一颗是 69%）。两个参照：08-17 某颗星球 39 发只读回 13 发（33%）、
08-16 是 2 发读回 0 发（0%）——**那两天不是没赚，是战报没读回来**。

⚠️ **这个阈值还不是旋钮，理由写在常量上**：它的取值取决于用户愿意容忍多大的低估
（偏旋钮），但做成旋钮要在 `military_attack_config` 上加一列，而这个需求是**纯读的、
不该带迁移**。先留成常量、把推导写下来，让下一次改动是有意的。真要可配置，加列那
一步需要用户授权。

## 三、两个分母：每线、每线小时

⚠️ **只给「每线」会罚晚开工的星球。** 实测 2026-08-20：一颗星球当天只跑了
11.7 小时、另两颗跑了 21 小时，而它的「每线」是另两颗的 2.2~3.6 倍——那个差里有
一部分只是「另两颗多跑了 9 个小时」。所以表**按「每线小时」排序**，「每线」只是
并列显示的另一个视角。

**「在岗时长」＝当天首发 → min(现在, 当日 24 点)。** 库里没有「启用 / 停用」的历史
（`mission_task_origins.enabled` 只有当前值），所以这是一个代理量，两种情形会失真，
**只标注、不修正**：

1. **当天被停用过的星球被罚**——停用那几个小时照样进分母。
2. **首发之前的空转看不见**——配好了却干等到很晚才开工的星球，这个数偏小、效率偏高。

**为什么不用「首发 → 末发」**（我算基线时用的那个）：它**奖励早收工的星球**——
00:00 和 00:30 各派一发然后再没动过，在岗时长只有 0.5 小时，「每线小时」会高得离谱。
那和「罚晚开工」是同一个错、方向相反。**为什么不用调度器运行时长**：那个数对所有
星球都一样，拿它当分母等于把「每线小时」变成「每线」乘一个常数，排序一模一样，
那一列就白加了。

在岗时长短于 **6 分钟**时「每线小时」显示「—」而不是一个大数（防爆除法：趋近 0 时
它会飙到几十万，而那只反映「刚开工」）。6 分钟比实测最短往返 42 分钟短得多，
所以它挡掉的只有「刚派出第一发」这一种情形。

## 四、线数：真值 vs 下界（借 PR #235 的那一套，没另造一份）

⚠️ **`mission_runs.configured_lines` 记的是账号总数，不是每颗星球各自的数**——
所以「那一天这颗星球配着几条」这个数**库里根本没有**，只能分两档给：

- 那一天记下的**账号总数**和此刻配置的**启用总数**一致，且这颗星球此刻是启用的，
  才按此刻它的 `mission_task_origins.fleet_lines` 算，标成真值。
- 否则（那天没记总数 / 总数变过 / 这颗星球此刻停用或已被移除）退到**这颗星球当天的
  最大并发在飞数**这个下界。

两档都直接用 `domain.overview` 的现成件（`LineCount` / `LineSource` /
`max_concurrent_lines`），占用段的末端用 `occupancy_end`——**一份判据都没有重写**。
⚠️ **方向和利用率那边相反着读**：线数取下界 ⇒ 分母偏小 ⇒ **效率取上界**，
所以线数那格写「≥ N 条」、两个效率数写「≤ …」，悬停里说清方向。

⚠️ **一个查不出来的盲点**：账号总数没变、而星球之间的分配改了（2/4/3 → 3/3/3），
那个一致性检查看不出来，那一天会被当成真值。只标注、不修正——真要修得给
`mission_task_origins` 记历史。

⚠️ **一个已知偏差，只记在注释里、页面上不修正**：本以为「往返越远、回收率越低」，
2026-08-20 的数据**不支持**（往返 42 分的 89%、113 分的 72%、120 分的 83%——比 113 分
那颗更远的反而更高）。方向上应该存在，但当天不是主因。**不做任何距离归一化**：
没有证据支撑的修正比不修正更糟。

## 五、行集与日期

- **行集 = 当天真派出过的星球 ∪ 当前配着的星球（含停用的）。** 只看 `enabled`
  会漏掉当天被停用、甚至被删掉的那些，而它们当天真把活打出去了（实测 08-20 有一颗
  中途被自动停用）；只看派出过的会漏掉「配了却一发没派」，而那是这一页最该喊出来的
  一种浪费。停用的标「（已停用）」、已从配置里移除的标「（已移除）」——两者在页面上
  必须分得开。
- **只做按天，不做按周/月/总计**（用户倾向也是先只做按天）。理由：「在岗时长」这个
  代理量只在**一天之内**说得通，跨一周它会把机器关着的那些夜晚静默算进分母；要按周
  就得先把它换成「与挂机段求交」，而那正是 PR #235 刚落地的口径，应当等它稳定之后
  复用同一份，别现在造第二份。
- 日期选择器给最近 7 天，但**不早于 2026-08-18**（`RESOURCE_STATS_START_UTC`）：
  那 12 格的识别是 08-18 才修好的，更早的战报根本没有资源明细，摆出来会是一排
  「收获 0 / 效率 0」，而那些天真打出去了几十发。认不出来的日期静默回落到今天，
  **不 422**（同 `parse_granularity`）。

## 六、为什么自己一条路由

这一段和 PR #235 的「利用率分母 / 挂机时长」在同一页上**同时开发**。挤进
`overview_routes` 的 `?fragment=` 会让合并冲突落在**判据**上，所以：自己的 domain
模块、自己的 SQL、自己的路由（`GET /overview/origin-efficiency`）、自己的模板片段；
`overview.html` 那边只多一个容器、一段独立的轮询脚本，`overview_routes.py` 一个字
没动。有一条用例钉住「整页真的去取那条片段」——容器或那次 fetch 少一个，这一段在
页面上就整个不存在，而两个模块各自的用例照样是绿的。

- Configuration: 无新增旋钮。低回收率阈值（60%）与在岗时长下限（6 分钟）都是常量，
  前者带完整推导（见上，将来要做成旋钮需要加列 + 用户授权），后者是防爆除法、
  **不是偏好项**。
- Database: **无迁移、无新表新列**。纯读：新增的两个 repository 里一个
  `INSERT` / `UPDATE` 都没有。**开发一侧没有对任何库跑 `alembic upgrade`**，
  也没有连过生产库。
- Verification: `pytest -q`（3645 passed / 39 skipped，其中本 PR 新增 52 条；skip
  全是缺实拍素材那批）、
  `ruff check src tests`、`ruff format --check src tests`、`mypy src` 四道全绿。
  变异测试 **15 组全部转红**（含「分子加了基础三样」「槽位号抄第二份」「日切用本机
  时区」「归属改按读回日」「每线小时退化成每线」「回收率那一列被删」「低回收率不标」
  「线数/在岗时长除零」「停用的星球被漏掉」「排序反了」），详见 PR 说明。
- Safety: **纯只读页面**。不触发任何游戏动作、没有新的点击路径、不启动游戏、
  `AUTO_ENABLED` 与急停一个字没动。查询失败走和整页同一套限流留痕（直接 import
  `overview_routes._FailureLog`，不抄第二份），页面上给红条而不是把 0 当事实摆出来。
- Rollback: `git revert` 即可。没有 schema 变更要退；删掉三个新模块 + 一个模板片段 +
  `overview.html` 里那个容器和脚本，页面回到 PR #235 的样子。
