一趟信箱里跨屏认「这一行我见过」的身份（`MailRow.identity`）从**主题 + 时间**改成
**只认时间那一格**，同一封邮件不再因为主题读成两样而被重复开封。

## 为什么旧键从来没生效过

主题那一格读不稳：邮件面板半透明，背后那一页的字透上来落进同一块窄 ROI。
`var/logs` 的信箱实拍上量过（32 屏 192 行）：**主题一字不差的是 0 行**，
而时间读出 **180 行（93.8%）**。所以「主题 + 时间」这个复合键从来匹配不上任何一行，
它既没换来 docstring 里写的「少开一封」，也没避开「重开一封」——每个跨屏重叠的行
都照付重开的代价。生产库 2026-08-18 20:35–20:37 一趟里同一份战报开了两次
（`09:07:54` 与 `08:55:37` 各一对），8 封的预算里 2 封是重复的（≈46 秒），
紧接着就打了「这一趟已经开了 8 封，到上限」——**重开挤掉的正是还没读的战报**。

## ⚠️ 原 docstring 那条取舍保留了它对的那一半

它要防的是「拿读不出来的东西当身份」，所以**没有**写成 `raw_time_text or ""`：
那样一屏里读不出时间的行会共用同一个身份、第一行之外全被静默判成重复
（实拍上读不出时间的占 6.2%）。现在读不出时间时身份是 `None`，那一行一律算
「没见过」，付的是「重开一封 ≈ 8 秒」而不是「少开一封」——与 `may_be`、
`is_older_than` 往「开」的一侧倒是同一个方向。`kind` 同样不能兜底：它是主题的子串
判定，噪声吃掉那四个字就认不出（同一封邮件两次读数一次 `ATTACK` 一次 `UNKNOWN`）。

同一秒真的会有两封邮件（实拍 `13:07:42` 上 `远征舰队返回` 与 `远征报告`，192 行里
1 对）。同屏那一侧安全，靠的是「挑出没见过的」排在「记下见过的」**之前**——这条顺序
现在是判据的一部分，注释写明不许并成一步。跨屏那一对正好被屏幕下边缘切开时，
后一封这一趟会被跳过，下一趟能读到；这个代价的量级由新增的实拍用例守着
（没有任何一屏出现三行同秒）。

## 「这一屏拖不动了」必须一起换

`_scan_mail_rows` 里那条判据改挂 `mail_times_settled`。它今天几乎到不了——那一段在
`not fresh` 时才判，而主题不稳时 `fresh` 永远非空；去重修好之后它才第一次真正可达，
而比主题的那版在那里必然不成立，会白拖到 `MAIL_SCAN_PAGES` 上限。只修去重不修这条，
等于亲手激活一条已知坏掉的判据。「整屏读空不算到顶」原样保留。

- Configuration: 无新旋钮。判据是标定出来的，不做配置
- Database: **无迁移、无 schema 变更**。同一趟里数今天几发（`observe` / `DailyTally`）
  跟着不再把一封数成两发，写进 `daily_reconciliation` 的 `observed_reports` 因此更准
  （原先偏大，会提前收手少打；偏小那一侧才会超额，本次不往那边动）
- Verification: `pytest`（本机带实拍 3062 passed / 6 skipped；`var/logs` 不在时
  2959 passed / 109 skipped）、`ruff check src tests`、`ruff format --check src tests`、
  `mypy src`、`compileall`；六处变异逐条确认转红（见 PR 正文）
- Safety: 不碰游戏、不动鼠标、不起 runner——全程离线；生产库只读；一张游戏截图
  都没进仓库（实拍放 `var/logs`、缺图 skip）
- Rollback: revert 本次提交即可（没有迁移要退）。退回去就是退回重复开封，
  每趟约白花 8–46 秒开封预算
