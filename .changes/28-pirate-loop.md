海盗侦查-攻击循环：一个恒星系扫 1–4 位，侦察、判定、攻击，然后下一个。

```bash
python -m evo_helper.tools.pirate_loop --systems 2:137                    # 只扫，不派
python -m evo_helper.tools.pirate_loop --systems 2:137 --scout            # 加上侦察
python -m evo_helper.tools.pirate_loop --systems 2:137 --scout --attack   # 完整循环
```

实机跑通的部分（2026-08-09，2:137）：1–4 位全部认出「敌对海盗」，**四发侦察全部
派出**，每一发都过了简报闸门并正确退出「飞行中」列表。

## 设计要点

- **三档模式刻意分开**：默认一个动作都不做，`--scout` 只派探测器，`--attack` 才会
  把战斗舰队送出去。`LiveDriver(allow_actions=...)` 只在一处按模式打开。
- **预设只按标题匹配**（用户口径 2026-08-09）。`PresetPicker` 在预设条上 OCR 找到
  那个标题才点，找不到就整发放弃；**不读、不校验预设内容**——内容是用户自己在
  游戏里维护的，助手去核对既多余，也会把「用户改了预设」误判成故障。
- **预设条只往左拖。** 最右端是「+ 保存当前舰队」，点到它会覆盖用户的预设；
  往左拖永远离它更远。打开时的滚动位置不固定（实机上 AAA 在最左端，面板却从
  「探路 / BBB」那一段打开），所以先拖到夹住、再按名字找。
- **意图在点出发之前写，派遣在之后写。** 被闸门拦下的那些恰恰最该出现在日志里，
  而它们没有派遣行。

## 实机事故与由此加上的护栏

第一次跑 `--scout --attack` 时，派出侦察之后游戏停在「飞行中」列表上，而代码以为
还在恒星系视图，于是照着信箱路径连点三下——**第一下点在了某条探索任务的
「取消」上**，游戏弹出「确定要取消该任务吗？」。那一屏没有被继续盲点，人工否掉了，
用户的三条探索任务都还在跑。

由此加了三条护栏：

- **派出之后必须自己退出「飞行中」列表**（`_leave_dispatch_list`），并回读导航栏
  标签确认切回了恒星系视图。少这一步，下一个目标的导航就会在列表页上盲点。
- **去信箱的每一步都先认屏再点**：先确认在自己星球地表（读到星球名横条），
  再点信箱；确认读到「邮箱」标题，再点「报告」标签。认不出就抛异常停下。
- **开工先校几何**：`ensure_game_window()`。窗口被改过尺寸时所有坐标一起失效，
  而这件事悄无声息——本轮开工时窗口就是 1536×733。
