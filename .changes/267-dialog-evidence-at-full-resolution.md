**认不出的弹窗按原分辨率落库（连同 OCR 原文），并给起点闸门留下版本指纹。**

## ⚠️ 起因：证据不够用，修不下去

2026-08-27，4 系一天 17 轮全死在同一个目标 `4:268:5` 上，起点每次读成空。查下去
卡在证据上：

- 存下来的只有一张 480 宽的缩略图。1920 → 480 是 4×，那句弹窗被压成一条 22 像素的糊斑
- 只能去**量字迹宽度**（原分辨率 912..996，**88px**）反推字数（约 5–6 个字），
  再拿它排除词表里那三句（9 / 8 / 14 个字）
- 结论「不是已知那三句」够用了，**但到底是哪一句，永远读不出来**

于是修不下去：不知道措辞就写不进 `DIALOG_MESSAGES`，写不进词表 `snap_dialog` 就
永远认不出它，`_handle_dialog` 永远交 True，#266 那道支线落回老逻辑，循环照旧。

⚠️ **同一条教训 `crop_png_base64` 的注释里早写着**（导航栏值框缩成 34×8、数字剩
3.5px 高，「实测就是两团糊斑」）。那一次就是补原分辨率裁片解开的，这一次我在同一条
路上重新踩了一遍。

## 三处改动

**认不出的弹窗按原分辨率拍下来**，`dialog_raw_text` / `dialog_snapped` /
`dialog_png_base64` / `dialog_evidence_roi` 一起进 `payload_json`。

裁的那块（`DIALOG_EVIDENCE_ROI = (790, 425, 1130, 515)`）**故意比读字的框大一圈**：
只裁 `DIALOG_TEXT_ROI` 回答得了「这几个字长什么样」，回答不了「这句话有没有溢出框
外」—— 而那正是当时分不出的第二种可能，且有先例（`DIALOG_TEXT_ROI` 上一版把 14 个
字那句读成了 `'[派遣的舰队数量已达上'`）。

文字与裁片**来自同一帧**（`_frame_reader`）。2026-08-25 导航栏那条证据链各截各的，
同一条告警里日志记着 `['261','26','26','6','61']`、裁片重读却是
`['261','261','26','6','261']` —— 两份都对，只是不是同一刻的画面。

**`dialog_checked` 是版本指纹。** #266 那道支线落地时**一行新日志都没留**，于是它和
改动前在库里长得一字不差；用户问「生产跑的是哪个版本」时只能答「看不出」，而仓库
那条既定口径正是要防这个。现在 payload 里有这个键就是新版，`true` 还表示当时真走到
了「问了、认不出」那一档。

**认不出的原文也写进正文**，不只塞 payload：`payload_json` 存的是 text，按键取值得
`::jsonb` 转一道；正文 `LIKE` 一下就能按措辞分组。

- Configuration: 无新增配置项。
- Database: 无迁移，只多了几个 `payload_json` 的键。
- Verification: `ruff format --check` / `ruff check` 干净；`mypy src` 3 条既有错误未
  新增；`pytest -q`（与 CI 同一条命令）→ 4127 passed / 256 skipped。新增 7 条用例；
  **八处变异各有对应用例变红**（裁片用窄框 / 存缩略图而非原分辨率 / 文字和图各抓
  一帧 / 不记 OCR 原文 / 读到别的坐标也拍一张 / 指纹恒为 True / 原文不进正文 /
  取证失败把整轮弄死）。
- Safety: 纯诊断路径，取不到帧只交文字、不抛；主链路判定逐字不变。
- Rollback: 闸门里那个 `dialog` 字典与 `_dialog_evidence` 删掉，`_record_origin_mismatch`
  去掉 `dialog` 参数即可。
